# cc 説明文書

cc は C コンパイラである。C ソース 1 本を受け取り，ELF リロケータブル
オブジェクトを出力する。設計は [stage010-c89.md](../docs/stage010-c89.md)，
出力形式は [stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

Stage 8 の `stage008/cc.sc` の後継である。ソースを凍結しておかないと
チェーンを hex0 から再現できなくなるため，前段のファイルには手を入れず
新しいファイルとして置いてある。生成物の名前で世代を呼び分ける
(`cc8.bin` = Stage 8 の cc，`cc.bin` = 現行の cc)。

ソース [cc.sc](cc.sc) が正本である。バイナリはビルドで再現される生成物であり，
git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc8, ld -> cc10a0.bin (ブートストラップ) -> cc10a.o -> cc10a.bin
```

生成物は `cc10a.bin` である。Stage 10 は 3 部に分かれ，各部のコンパイラが
次の部をビルドするので，世代ごとに名前を持つ (`cc10a` = 第 1 部，
`cc10b` = 第 2 部)。`cc.bin` は最新世代の別名である。

SHA-256: ffc7ff2734380411064a96b9f2a73dc6d5bc0c9f7c793ee0470249aff86371a7

- 対象: RV32IM，リトルエンディアン，95132 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 使い方

```
{ cat prog.c; printf '\004'; } | sh tools/env.sh qemu tmp/build/cc.bin > prog.o
{ cat prog.o;  printf '\0';   } | sh tools/env.sh qemu tmp/build/ld.bin > prog.bin
```

プリプロセッサを通す場合は前段に `pp` を挟む
([stage009/pp.md](../stage009/pp.md))。

## Stage 8 の cc からの変更点

追加したのは構文だけで，IR の命令種別・コード生成規則・ABI・出力形式は
一切変えていない。これは **ブートストラップ 1 段目 `cc1.bin` と正本
`cc.bin` がバイト単位で一致する** ことで機械的に確かめられる
(異なるコンパイラが同じソースから同じバイナリを作っている)。

| 分類 | 追加した構文 |
|---|---|
| 文 | `for`，`do`-`while`，`switch` / `case` / `default`，`break`，`continue`，`goto` とラベル |
| 式 | `?:`，複合代入 (`+= -= *= /= %= &= \|= ^= <<= >>=`)，`++` / `--` (前置・後置)，カンマ演算子，`sizeof` (型・式)，キャスト |

これらはすべて既存の道具の組合せに落ちる。新しい制御構造はラベルと
`jmp` / `bz` / `bnz` へ，新しい演算子は既存の二項演算とロード・ストアへ。

## 実装上の要点

| 事項 | 扱い |
|---|---|
| `break` / `continue` | 飛び先を 2 本の積みで持つ。`switch` は `break` 側だけを積むので，`switch` の中の `continue` は自然に外側のループへ抜ける |
| `switch` | 本体を先に，振分けを後に出す。本体を読み終える前に `case` の一覧を知らなくて済む。値は隠しスロットに置く |
| `for` の歩進 | 構文上は本体の前，実行は本体の後。IR は解析順にしか積めないので，本体へ飛び越す `jmp` を 1 個入れて順序を入れ替える |
| `goto` | 関数ごとのラベル表。前方参照は未定義のまま登録し，関数の終わりで残っていればエラー 2 |
| 複合代入・`++` | 左辺値のアドレスを表す値番号を読みと書きで 2 度使う。左辺の評価は 1 度で済む |
| `?:` | `&&` / `\|\|` と同じく隠しスロット経由。この IR は値を「定義した命令番号」で指すので，合流点に 2 つの定義を届けられない |
| `sizeof` (式) | C は被演算子を評価しない。IR は配列と個数なので，解析前に個数を控え，型を得た後に巻き戻す |
| キャスト | すべての値が 32 bit セルなので型の付け替えだけ。コードは出ない |
| 「`x:`」と「`x = 1`」の見分け | 1 トークン先読みが要る。読取り位置とトークンを退避して読み直す (`lsave` / `lrest`) |

> 第 2 部以降の変更は [cc2.md](cc2.md) 以降を参照。以下は第 1 部時点の制限である。

## 制限 (第 2 部・第 3 部で解消する)

- 型は `int` / `char` / ポインタ / 構造体のみ。`unsigned` `short` `long`
  `enum` `union` `typedef` は無い
- 宣言は関数本体の先頭にまとめる (ブロック内宣言は不可)
- 関数プロトタイプ・`extern` / `static` は無い
- 初期化子・可変長引数・構造体の値渡しは無い
- `case` のラベルは整数定数と文字定数のみ (定数式は不可)
