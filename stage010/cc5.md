# cc5 説明文書

cc5 は C コンパイラである。第 2 部の 3 の [cc4.sc](cc4.sc) を出発点に，
**整数型の幅と符号を入れた** もの (第 2 部の 4)。設計は
[stage010-c89.md](../docs/stage010-c89.md)，出力形式は
[stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

ソース [cc5.sc](cc5.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド



SHA-256: 8301207039402b27851460e428f28aa24c4cf80af5a706fb9f9098fed82540a3

- 対象: RV32IM，リトルエンディアン，113388 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 第 2 部の 3 からの変更点

`unsigned` / `signed` / `short` / `long` を追加した。
**本段で初めてコード生成規則が変わる。**

| 型 | 幅 | 符号 |
|---|---|---|
| `char` | 1 | **なし** (C は処理系定義。sc の時代から `lbu` で読んできた) |
| `signed char` | 1 | あり |
| `short` / `unsigned short` | 2 | あり / なし |
| `int` / `long` | 4 | あり |
| `unsigned int` / `unsigned long` | 4 | なし |

## 実装上の要点

### 整数の格上げが効いて，符号の扱いが 1 箇所に集まる

`char` と `short` は算術の中で `int` へ格上げされる。`int` がその全ての値を
表せるので，`unsigned char` / `unsigned short` も **符号つき int** になる。
したがって **演算が符号なしになるのは `unsigned int` のときだけ** である。

ロードの時点で 32 bit へ拡張してあるので，格上げに命令は要らない。
型を付け替えるだけで済む。

### 命令の選択

| 対象 | 追加した命令 |
|---|---|
| ロード | `lb` (signed char) / `lh` (short) / `lhu` (unsigned short)。既存は `lbu` `lw` |
| ストア | `sh`。既存は `sb` `sw` |
| 除算・剰余 | `divu` `remu` |
| 右シフト | `sra` (符号つき。符号なしは従来の `srl`) |
| 大小比較 | `sltu` (符号つきは従来の `slt`) |

比較は `slt` を基本形とし，`>` `<=` は被演算子を入れ替え，`<=` `>=` は
結果を `xori 1` で反転する形をそのまま使う。符号なしは基本形を
`sltu` に差し替えるだけで済む。

### キャストの切詰め

幅の狭い型へのキャストは，左シフトの後に右シフトで戻す。符号つきなら
算術右シフト (符号拡張)，符号なしなら論理右シフト (0 拡張) である。

### 定数畳み込みの落とし穴

`>>` の意味が「論理シフト」から「符号つきなら算術シフト」へ変わったので，
**コンパイラ自身が定数を畳むときの `>>` も変わる**。論理右シフトの
畳み込みは，上位に伸びた符号ビットを明示的に落とす形へ書き改めた
(旧世代の意味で解釈しても同じ値になる書き方にしてある)。

符号なし除算・剰余と算術右シフトは畳み込まない。このコンパイラ自身が
符号つきでしか計算できず，負の値で答えが食い違うためである。

## 前世代とのコード生成の違い

コード生成規則を変えたので，ブートストラップ 1 段目と正本は一致しない。
正本が自分自身を再生成する固定点 (B2 == B3) は従来どおり成り立つ。

## 制限 (第 2 部の 5・第 3 部で解消する)

- `long long` は無い (`long` は `int` と同じ 4 バイト)
- 関数ポインタは無い
- `static` はリンケージを変えない
- ポインタの大小比較は符号つきで行う (同じ領域内なら順序は保たれる)
- 初期化子・可変長引数・構造体の値渡しは無い
