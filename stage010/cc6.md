# cc6 説明文書

cc6 は C コンパイラである。第 2 部の 4 の [cc5.sc](cc5.sc) を出発点に，
**関数ポインタと `static` のリンケージを入れた** もの (第 2 部の 5)。
設計は [stage010-c89.md](../docs/stage010-c89.md)，出力形式は
[stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

ソース [cc6.sc](cc6.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10e -> cc10f0 (ブートストラップ) -> cc10f
```

SHA-256: 8f3214b51ca257c1d97061ede0a798cc523b6754b3e70b49b3513333d15ca18f

- 対象: RV32IM，リトルエンディアン，120508 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 第 2 部の 4 からの変更点

| 追加 | 内容 |
|---|---|
| 関数ポインタ | `int (*f)(int);` 値としての関数名，間接呼出し，配列・仮引数・`typedef` |
| `static` のリンケージ | ELF のローカルシンボルとして出し，翻訳単位内で閉じる |

## 実装上の要点

### 関数型

型の表に **関数型** を足した。配列型と同じ考え方で，基底の 2048 番以降を
関数型の表の添字に割り当て，返却型を持たせる。仮引数の型までは持たない
(呼出しの検査は名前つきの関数と違って個数も見ない)。

式に現れるのは常に「関数へのポインタ」なので，型としては
`(1 << 16) | (2048 + k)` になる。次の 4 つがすべて同じ値になるのは，
**関数を参照はがししても関数のままで，式の中では再びポインタへ戻る**
と決めたためである。

```
p(x)   と   (*p)(x)
f      と   &f
```

### 呼出しが 2 通りになる

| 形 | 出力 |
|---|---|
| 記号を直接呼ぶ | `jal` + JAL 再配置 (従来) |
| 値を呼ぶ | `jalr` |

引数の積み方と返却値の受取りは同じである。IR には「値を呼ぶ」命令を
1 つ足した。

### `static` はリンカに手を入れずに済んだ

ld は既に次の作りになっている。

- 大域シンボルの収集を `sh_info` (最初の非ローカルの番号) から始める
- 再配置の解決を `st_shndx` で行い，1 (`.text`) / 2 (`.bss`) なら
  そのオブジェクト内で解く

したがって **cc が `static` の記号をローカル領域へ並べ替え，`sh_info` を
正しく書くだけ** で翻訳単位に閉じる。ELF は「ローカルが先，大域が後」で
並べる決まりなので，シンボル表を

```
[0] 空 | 文字列リテラル | static | 非 static
```

の順に組み立て，大域記号から ELF シンボル番号への対応表を先に作ってから
再配置を書く。

## 制限 (第 3 部で解消する)

- 局所の `static` 変数 (記憶域が静的になるもの) は構文エラーとする
- 関数ポインタの宣言子は `T (*名前)(仮引数)` の形に限る
  (`T (*f[3])(int)` のような入れ子の宣言子は不可。`typedef` で回避できる)
- 関数ポインタ経由の呼出しは引数の個数を検査しない
- 初期化子・可変長引数・構造体の値渡しは無い
