# cc2 説明文書

cc2 は C コンパイラである。Stage 10 第 1 部の [cc.sc](cc.sc) を出発点に，
**型と宣言** を広げたもの (第 2 部の 1)。設計は
[stage010-c89.md](../docs/stage010-c89.md)，出力形式は
[stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

ソース [cc2.sc](cc2.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10a -> cc10b
```

第 1 部のコンパイラ (cc10a) でビルドする。したがって **第 1 部で実装した
構文 (for / switch / ++ / 複合代入 / ?: / sizeof) をこのソースでは使ってよい。**
ブートストラップの各段が次の段を書きやすくする，というのがこの積み上げの
狙いである。

SHA-256: d98a4cd3356b372b82e5438b1a1cf926bbcef5893e64bdb977e466dd72ce430d

- 対象: RV32IM，リトルエンディアン，100284 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 第 1 部からの変更点

追加したのは宣言の構文と字句規則だけで，IR の命令種別・コード生成規則・
ABI・出力形式は一切変えていない。

| 追加 | 内容 |
|---|---|
| `typedef` | 型に別名を与える。名前 -> 型の対応表を 1 つ持つだけで済む |
| `enum` | 列挙定数。型としては int で，タグは型の区別を生まないので読み捨てる |
| `union` | 構造体表を共有し，メンバの位置を 0 に固定して大きさを最大値にする |
| `const` / `volatile` | 受理して読み飛ばす (`volatile` の意味論は持たない) |
| `void` | `void` と `void *` |
| 無名 `struct` / `union` | `typedef struct { ... } T;` が書ける。タグは内部で `$N` を振る |
| 識別子の大文字 | `enum` 定数や `typedef` 名は大文字が慣習であり，外部の C も使う |

## 実装上の要点

- **`struct` と `union` は同じ表を共有する。** 型としての違いはメンバの
  配置だけで，参照する側の扱いは同じだからである。`sunion` で配置を分ける
- **`enum` に型表は要らない。** 列挙定数は「名前 -> 値」の対応にすぎず，
  型は int である。タグは型を区別しないので読み捨てる
- **`typedef` 名かどうかで宣言か式かが決まる。** C の構文が文脈自由でない
  有名な箇所で，字句だけでは判断できない。`istype()` が表を引いて決める
- **識別子の大文字を解禁した。** 予約語はすべて小文字なので衝突しない

## 制限 (第 2 部の 2・第 3 部で解消する)

- 整数型は `int` / `char` のみ。`unsigned` `signed` `short` `long` は無い
- 多次元配列・関数ポインタ・関数プロトタイプ・`extern` / `static` は無い
- 宣言は関数本体の先頭にまとめる (ブロック内宣言は不可)
- 識別子は 15 バイト以下 (C89 は内部識別子 31 文字を要求する)
- `case` のラベルは整数定数と文字定数のみ (`enum` 定数は使えない)
- 構造体型のメンバ (入れ子の struct) は持てない
