# cc11 説明文書

cc11 は C コンパイラである。第 3 部の 4 の [cc10.sc](cc10.sc) を出発点に，
**文字エスケープを C89 の全種類に広げた** もの (Stage 10 の補遺)。
設計は [stage010-c89.md](../docs/stage010-c89.md) 19 章。

ソース [cc11.sc](cc11.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10j -> cc10k0 (ブートストラップ) -> cc10k (= cc.bin)
```

SHA-256: 7e3f88903d45ba515ca627f9d8f176c6804ef5b31fb40d3a88b0aa41e1fc7910

- 対象: RV32IM，リトルエンディアン，138824 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## なぜ補遺が要ったか

第 3 部の 4 で「C89 の言語仕様が揃った」としたが，**字句の側に穴が残って
いた**。エスケープが 6 種 (`\n` `\t` `\0` `\\` `\'` `\"`) しかなく，
C89 7.1.3 が定める `\a` `\b` `\f` `\r` `\v` `\?` と，8 進・16 進の
エスケープが無かった。

Stage 11 の libc を書き始めて `isspace` が `\f` `\r` `\v` を必要とし，
そこで気づいた。libc 側で 12 や 13 と数値で書けば通るが，それは
**処理系の穴を利用者に押しつける** ことになるので，処理系を直す。

## 第 3 部の 4 からの変更点

| 追加 | 綴り |
|---|---|
| 単純エスケープ | `\a` (7) `\b` (8) `\f` (12) `\r` (13) `\v` (11) `\?` (63) |
| 8 進 | `\101` 最大 3 桁。`\0` もここで扱う |
| 16 進 | `\x41` 桁数の制限は無く 1 バイトへ切り詰める |

消費の仕方も変えた。数値エスケープは桁数ぶん読み進めるので，
**`escv` 自身が読取り位置を進め，呼ぶ側は進めない**。文字リテラルと
文字列リテラルの両方が同じ関数を通るので，一箇所で済む。

コード生成規則は変えていないので，cc10j が作った 1 段目 (`cc10k0.bin`) と
それが自分自身を再コンパイルしたもの (`cc10k.bin`) はバイト単位で一致する。

## 制限

- 3 文字表記 (trigraph, `??=` 等) は無い。C89 にはあるが実用されず，
  `\?` を入れたのは綴りの完全性のためである
