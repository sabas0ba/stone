# cc10 説明文書

cc10 は C コンパイラである。第 3 部の 3 の [cc9.sc](cc9.sc) を出発点に，
**構造体を値で返せるようにした** もの (第 3 部の 4)。これで Stage 10 の
目的である C89 の言語仕様が揃い，[roadmap.md](../docs/roadmap.md) の
Phase A が完了する。設計は [stage010-c89.md](../docs/stage010-c89.md) 18 章。

ソース [cc10.sc](cc10.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10i -> cc10j0 (ブートストラップ) -> cc10j
```

SHA-256: 1657cbc453086c832ef0173511f6a8ea64455a2d41853bdf2c0151fbd646c629

- 対象: RV32IM，リトルエンディアン，136908 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 第 3 部の 3 からの変更点

| 追加 | 内容 |
|---|---|
| 構造体の返却 | `struct P mk(int x) { ... return p; }` |
| 返却値の利用 | `q = mk();` `f(mk())` `mk().y` `g = mk()` |

コード生成規則は変えていないので，cc10i が作った 1 段目 (`cc10j0.bin`) と
それが自分自身を再コンパイルしたもの (`cc10j.bin`) はバイト単位で一致する。

## 実装上の要点

### 返却もデータスタックで受け渡す

返却値の受渡しはこれまで 1 語だった。構造体は複数語なので，**引数と同じく
データスタックに積んで返す**。

```
呼ばれた側: 語 k-1 ... 語 0 の順に積み，最後に従来どおり 1 語の
            返却値 (中身は使わない) を積んで戻る
x9 から上へ: [使わない 1 語][語 0][語 1] ... [語 k-1]
呼んだ側:   呼出しの直後に語をフレームの一時領域へ引き取り，
            1 + k 語ぶん x9 を戻す
```

### 引取りは出力段で埋め込む

引数と違い，引取りは IR では書けない。**x9 が IR から触れない** ためである。
IR が知っているのは「フレーム上の位置」と「値番号」だけで，データスタックの
上を読む操作を組み立てる手段がない。

そこで呼出し命令に側情報 `iret` (引取り先のフレームオフセット) を持たせ，
出力段が呼出しの直後に複写を埋め込む。IR の命令種別は増えないので，
出力段・dce・レジスタ割付けの 4 箇所を触る必要はない。

### 返却値は左辺値ではない

`mk().x` は取れる (構造体の値はどれも実体のアドレスなので，メンバは
オフセットを足すだけで届く)。しかしその実体は呼んだ側の一時領域なので，
`mk().x = 5` を許すと捨てられる領域へ書くだけになる。`erv` を立てて
代入を型エラー (5) で撥ねる。

## 制限

- 構造体を返す関数ポインタは受けない。関数型が返却の形を持たないので，
  引取りの語数を出力段で決められない (型エラー 5)
- 構造体の初期化子は無い
- 大域の初期化子に定数式は書けない
