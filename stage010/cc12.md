# cc12 説明文書

cc12 は C コンパイラである。補遺の [cc11.sc](cc11.sc) を出発点に，
**配列に単項 `&` を適用できるようにした** もの (Stage 10 の補遺 2)。
設計は [stage010-c89.md](../docs/stage010-c89.md) 20 章。

ソース [cc12.sc](cc12.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10k -> cc10l0 (ブートストラップ) -> cc10l (= cc.bin)
```

SHA-256: f26f058da421bea13443c279bbdae8bc00d82deb529f6d0dfc9337af625fc49f

- 対象: RV32IM，リトルエンディアン，139124 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## なぜ補遺 2 が要ったか

式の中の配列は「先頭要素へのポインタ」へ退化し，退化した式は左辺値で
なくなるので，`&a` が一律にエラー 5 で撥ねられていた。C89 では `&a` は
合法で，値は先頭要素のアドレスと同じ，型が「配列へのポインタ」になる。

Stage 11 の stddef.h を書き始めて，offsetof
(`&(((t *)0)->m)`) が配列メンバに使えないことで気づいた。補遺 (文字
エスケープ) と同じく，**最初の実利用者が穴を踏んだ** 形である。libc や
テストの側で配列メンバを避ければ通るが，それは処理系の穴を利用者に
押しつけることになるので，処理系を直す。

## 補遺からの変更点

| 追加 | 内容 |
|---|---|
| 単項 `&` を配列に適用 | `&a` は先頭要素のアドレスと同じ値で，型は「配列へのポインタ」 |

- 退化の 5 箇所 (局所・大域・メンバの参照，添字の後，単項 `*` の後) で
  **退化前の配列型を `eaty` へ控える**
- 単項 `&` は，被演算子が退化した配列 (`earr`) なら値をそのまま返し，
  型を `eaty` の 1 段ポインタに付け替える
- `&a + 1` が配列 1 個ぶん進むこと，`sizeof(*&a)` が配列全体の大きさに
  なることは，既存のポインタ演算と配列退化がそのまま面倒を見る

コード生成規則は変えていないので，前段 (cc10k) が作った 1 段目と正本は
一致する (cc10l0.bin == cc10l.bin)。固定点 (B2 == B3) も維持する。
