# cc8 説明文書

cc8 は C コンパイラである。第 3 部の 1 の [cc7.sc](cc7.sc) を出発点に，
**可変長引数を入れた** もの (第 3 部の 2)。
設計は [stage010-c89.md](../docs/stage010-c89.md) 16 章，出力形式は
[stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

ソース [cc8.sc](cc8.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10g -> cc10h0 (ブートストラップ) -> cc10h
```

SHA-256: 2d3784eea93391d8291c18a9d7bfa981e984a23be2c5a592de63f57803501e14

- 対象: RV32IM，リトルエンディアン，133100 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 第 3 部の 1 からの変更点

| 追加 | 内容 |
|---|---|
| `...` | 仮引数の並びの末尾に置く。名前つきが 1 個以上要る |
| 隠しローカル `__va_ptr` | 可変長関数の中でだけコンパイラが用意する `char *` |
| 呼出しの積み順 | 可変部を逆順に先に積み，名前つきを後から順に積む |
| 呼出し後の後始末 | 返却値と一緒に，余分に積んだぶんも捨てる |
| [include/stdarg.h](../include/stdarg.h) | `va_list` / `va_start` / `va_arg` / `va_end` |

`cc10h0.bin` と `cc10h.bin` は一致しない。実引数の評価をすべて済ませて
から `ARG` を出す形に変えたため，IR の並びが変わり，レジスタ割付けの
結果も変わるからである (コード生成規則が変わる変更)。正本は 1 段目が
自分自身を再コンパイルしたもので，以降は固定点になる (B2 == B3)。

## 実装上の要点

### レジスタ退避領域が要らない

普通の ABI は先頭数個の引数をレジスタで渡すので，`va_arg` のために
それらをフレームへ書き戻す領域 (register save area) が要る。この処理系は
もともと全部データスタック渡しなので，その仕掛けが丸ごと不要になる。

必要なのは **可変部と名前つきの並び順** だけで，それは呼ぶ側で決まる。

```
積む順:      arg[n-1] ... arg[k]   arg[0] arg[1] ... arg[k-1]
x9 から上へ: arg[k-1] ... arg[0]   arg[k] arg[k+1] ... arg[n-1]
                名前つき (逆順)      可変部 (昇順)
```

呼ばれた側のプロローグ (名前つきを後ろから取り出す) は 1 命令も変わらず，
取り出し終えた時点の `x9` がそのまま可変部の先頭を指す。

### `va_start` は隠しローカルからの代入

プロローグの末尾で `x9` を `__va_ptr` へ書く。利用者から見れば普通の
ローカル変数なので，`va_start(ap, last)` は `((ap) = __va_ptr)` で足りる。
**式の構文をひとつも増やさずに済む。**

`__va_ptr` の登録は `{` を読み進める前に行う。記号表の鍵 `tname` を
書き換えるため，先に `next()` すると本体の先頭トークンの名前が消え，
`istype()` が `typedef` 名を見失う (`va_list ap;` が宣言に見えなくなる)。

### 後始末は呼んだ側の責任

呼ばれた側は名前つきしか取り出さないので，可変部はスタックに残る。
個数を知っているのは呼ぶ側だけなので，返却値を取り出す
`addi x9,x9,4` の即値を `4 + 4 * (n - k)` にして一緒に捨てる。
命令は 1 つも増えない。

## 制限 (第 3 部の残りで解消する)

- 可変長関数の呼出しには，呼出しより前に宣言が要る。宣言が無いと
  呼ぶ側が名前つきの個数を知れず，積む順序も捨てる語数も決められない。
  個数不明のまま呼んだ後で可変長と判れば型エラー (5)
- 関数ポインタ経由の呼出しは可変長にできない (ポインタの型が名前つきの
  個数を持たない)
- 実引数は 32 個まで
- 構造体の値渡し・返却は無い
