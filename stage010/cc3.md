# cc3 説明文書

cc3 は C コンパイラである。第 2 部の 1 の [cc2.sc](cc2.sc) を出発点に，
**宣言を広げた** もの (第 2 部の 2)。設計は
[stage010-c89.md](../docs/stage010-c89.md)，出力形式は
[stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

ソース [cc3.sc](cc3.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10b -> cc10c0 (ブートストラップ) -> cc10c
```

SHA-256: 507d89ae3e7636c93cad517f8789930a2d8c0039b4be25eecab4bbb51917724c

- 対象: RV32IM，リトルエンディアン，102416 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 第 2 部の 1 からの変更点

| 追加 | 内容 |
|---|---|
| 関数プロトタイプ | `int f(int, char *);` 定義せずに宣言だけする。仮引数名は省略できる |
| `(void)` | 引数なしの明示 |
| `extern` | 他の翻訳単位にある変数・関数を参照する。変数は `.bss` を取らず未定義シンボルになる |
| `static` | 受理する (下の制限を参照) |
| ブロック内宣言 | 複文の先頭に宣言を置ける。名前は複文を抜けると見えなくなる |

**これでヘッダが「宣言を共有する場所」になった。** Stage 9 の時点では
ヘッダに書けるのはマクロと型定義だけで，関数や変数の宣言は書けなかった
([stage009-pp.md](../docs/stage009-pp.md) 7 章の申し送り)。

## 実装上の要点

- **ブロック内宣言とフレームの割付け。** 隠しスロット (`&&` / `||` / `?:` /
  `switch` が使う) は局所変数領域の直後から取っていたが，本体の解析中に
  局所変数が増えると領域を奪い合う。そこで **隠しスロットも局所変数と
  同じ割付けポインタから取る** ことにした。どちらも「フレーム上の 1 語」で
  あり，区別する理由はもともと無い。
  複文を抜けると割付けポインタを戻すので兄弟の複文は同じ領域を使い回すが，
  フレームの大きさは最大値 (`cmax`) で決まる
- **プロトタイプと定義の見分け。** 仮引数を読み終えた時点で `;` なら
  プロトタイプ，`{` なら定義である。プロトタイプは引数の個数と返却型だけを
  控え，記号は未定義のままにする
- **`(void)` は 1 トークン先を覗いて見分ける。** `(void)` は引数なし，
  `(void *p)` は引数 1 個である
- **`extern` の変数は `.bss` を取らない。** 未定義シンボルとして出し，
  リンカが他の翻訳単位の定義へ解決する。先に `extern` で宣言してから
  同じ翻訳単位で定義するのも正しい

## 前世代とのコード生成の違い

フレームの割付け方を変えたので，**関数によってはフレームの大きさが数語
異なる**。IR の命令種別・ABI・出力形式は変えていない。したがって
ブートストラップ 1 段目 (cc10b が作ったもの) と正本は一致しないが，
正本が自分自身を再生成する固定点 (B2 == B3) は成り立つ。

## 制限 (第 2 部の 3・第 3 部で解消する)

- **`static` はリンケージを変えない。** 記号は大域のまま出るので，
  2 つの翻訳単位が同じ名前の `static` 関数を持つとリンカが多重定義と
  みなす。局所の `static` 変数 (記憶域が静的になるもの) は構文エラーとする
- 整数型は `int` / `char` のみ。`unsigned` `signed` `short` `long` は無い
- 多次元配列・関数ポインタは無い
- 識別子は 15 バイト以下 (C89 は内部識別子 31 文字を要求する)
- 初期化子・可変長引数・構造体の値渡しは無い
