# cc9 説明文書

cc9 は C コンパイラである。第 3 部の 2 の [cc8.sc](cc8.sc) を出発点に，
**構造体を値として扱えるようにした** もの (第 3 部の 3)。
設計は [stage010-c89.md](../docs/stage010-c89.md) 17 章，出力形式は
[stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

ソース [cc9.sc](cc9.sc) が正本である。バイナリはビルドで再現される生成物で
あり，git 管理しない。

## ビルド

```
sh tools/build.sh stage010
# ... -> cc10h -> cc10i0 (ブートストラップ) -> cc10i (= cc.bin)
```

SHA-256: b8fed83c7fcf5da18af4cdcec614d1be3ca9b9085192256d1a96de983938c43a

- 対象: RV32IM，リトルエンディアン，135580 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 第 3 部の 2 からの変更点

| 追加・修正 | 内容 |
|---|---|
| 局所の構造体変数 | `struct S s;` これまでは型エラー (5) だった |
| 入れ子のメンバ | `struct A { struct B b; };` 同上 |
| 構造体の代入 | `a = b;` **これまでは先頭 4 バイトしか複写しない誤りだった** |
| 構造体の値渡し | `f(s);` **これまでは先頭 4 バイトしか積まない誤りだった** |

代入と値渡しは，第 3 部の 2 までコンパイルは通るのに実体の先頭 1 語しか
運ばれていなかった。エラーにならず値だけが壊れる形なので，ここで直す。

コード生成規則は変えていないので，cc10h が作った 1 段目 (`cc10i0.bin`) と
それが自分自身を再コンパイルしたもの (`cc10i.bin`) はバイト単位で一致する。

## 実装上の要点

### 構造体の値は「アドレス」で持ち回る

式の値は 1 語 (レジスタ 1 本) に載るという前提で IR を組んでいる。
構造体はそこに載らないので，**構造体型の式の値はその実体のアドレス** とし，
`rv()` で読み出さないことにした。配列の退化と同じ考え方だが，型は構造体の
ままにしておく (メンバ参照がオフセットを足せるように)。

```c
int rv(int v) {
  if (elv) {
    if (isstru(ety)) { elv = 0; return v; }   // 構造体はアドレスのまま
    v = ldval(v, ety);
    elv = 0;
  }
  return v;
}
```

この規則ひとつで，代入も値渡しも「アドレスから語単位で複写する」形に揃う。
複写 (`scopy`) は IR の段で語ごとの load / store に展開するので，
**出力段・dce・レジスタ割付けには手を入れずに済む**。代わりに大きな構造体
では IR が長くなるので上限を設けた (1024 バイトを超えたら領域超過 6)。

### 実引数は語数で数える

構造体の実引数は `ceil(大きさ/4)` 語を占め，語 0 から順に積む。呼ばれた側は
後ろから取り出すので，**フレーム上の並びが元の記憶域の並びと一致する**。
つまり仮引数の構造体はふつうの局所の構造体変数と同じ形になり，メンバ参照は
何も変えずに動く。呼ばれた側のプロローグも 1 命令も変わらない。

このため引数の個数 `cna` は「語数」を数える。呼ぶ側も語数で数えるので，
個数の検査はそのまま働く。

## 制限 (第 3 部の 4 で解消する)

- **構造体の返却は無い。** 返却値の受渡しは 1 語なので，複数語を返すには
  呼出し側の後始末を変える必要がある。ここで撥ねておかないと，先頭メンバ
  以外が壊れる形で静かに通ってしまうので，返却型が構造体の関数は
  型エラー (5) とする
- 可変長引数の可変部に構造体は置けない (語数と実引数の個数がずれると
  可変部を並べ替えられない)。名前つきの側には置ける
- 構造体の初期化子は無い
- 自分自身をメンバに持つ構造体は型エラー (5)
