# Stage 4: sol 設計文書

## 1. 目的と位置づけ

### 1.1 目的

asm 言語はレジスタ割当・呼出し規約・分岐の組立てをすべて書き手が管理する。
Stage 5 (C サブセット相当のコンパイラ) の規模の記述には，制御構造・サブルーチン・
変数を言語機能として備えた，より高い抽象度が必要である。

sol の目的は，レジスタ管理と命令選択を廃止することである。sol はスタック指向の
小言語であり，構造化制御 (if/else, ループ)・関数・大域変数を備える。
アセンブリの手書きは sol コンパイラ自身のソース (asm 言語で記述) をもって最後とする。

名称 sol は stack-oriented language の略である。

### 1.2 用途

- Stage 5 (C サブセットコンパイラ) の処理系ソースを sol 言語で記述し，sol でビルドする。

```
sh tools/env.sh qemu tmp/build/sol.bin < stage005/xxx.sol > tmp/xxx.bin
```

sol はコンパイラであり，出力は asm と同じフラットバイナリ (ロードアドレス
0x8000_0000) である。生成物は QEMU 上で単体実行できる。

### 1.3 非目標

- ローカル変数・引数の名前付けは扱わない (データスタックと大域変数で代用する)。
- 型は持たない。すべて 32 bit セルである。
- 最適化は行わない。各語を固定の命令列に展開する。
- 文字列は NUL 終端の生バイト列のみ。エスケープシーケンスは持たない。

## 2. 入力言語仕様 (sol 言語)

### 2.1 前提の要約 (前段から継承するもの)

実行モデルは hex0/hex1/asm と同じフィルタである
(正式な定義は [stage001-hex0.md](stage001-hex0.md) 3 章)。
sol コンパイラはフラットバイナリとして 0x8000_0000 へロードされて実行され，
UART (stdin) からソーステキストを読み，UART (stdout) へ生成バイナリを書き出す。
終了は test finisher への書込みで行い，正常 0x5555 (終了コード 0)，
異常 (code << 16) | 0x3333 (終了コード code) である。入力の終端は `.` である。

### 2.2 字句

```
input   := token* '.'
token   := number | charlit | strlit | word
number  := ['-'] dec | ['-'] '0x' hex     ; 32 bit。hex は小文字
charlit := ''' 任意の 1 バイト '''        ; 値を push (例: 'a')
strlit  := '"' SP (('"' 以外の任意バイト)*) '"'
word    := 空白でも '#' でもないバイトの列 (1..15 バイト)
comment := '#' (LF 以外)*
ws      := SP | TAB | CR | LF
```

- トークンは自由形式で，ws で区切る。行の概念はコメントの終端のみ。
- `word` の字種は制限しない。ただし数値に解釈できる形 (先頭が数字，または
  `-` + 数字) は数値が優先される。`.` はトークンの先頭に置けない (入力終端)。
- `strlit` は `"` + 区切りの SP 1 個 + 内容 + `"`。内容は NUL 終端されて
  コード中に埋め込まれ，先頭アドレスが push される。長さは 255 以下。
- コメント・文字列・文字リテラルの内部を除き，`.` は入力終端である。

### 2.3 実行モデル (生成コード)

- データスタック: x9。0x87f0_0000 から下向き。全セル 32 bit。
- リターンスタック: x2。0x8780_0000 から下向き (関数の戻り先のみ)。
- 大域変数領域: 0x8010_0000 から上向きに割り付ける (バイナリには含まれない)。
- 真偽値: 0 = 偽，非 0 = 真。比較演算は 1/0 を push する。
- 生成バイナリの先頭には固定のランタイム (レジスタ初期化，`main` 呼出し，
  exit/getc/putc ルーチン) が置かれ，`main` から実行が始まる。`main` が
  返ると終了コード 0 で終了する。関数 `main` の定義は必須である (エラー 3)。

### 2.4 定義 (トップレベルのみ)

| 構文 | 意味 |
|---|---|
| `const name number` | 定数。参照時に値を push |
| `var name` | 大域変数 (1 セル)。参照時にアドレスを push |
| `buf name number` | 大域バッファ (number バイト，4 バイト整列)。参照時にアドレスを push |
| `fn name ... end` | 関数定義。`end` は関数からの復帰を含む |

- 名前空間は 1 つ (プリミティブ語 > 定義名の優先順)。プリミティブ語と同名の
  定義および再定義はエラー 4。
- 関数は定義前に呼び出せる (前方参照可)。`var`/`buf`/`const` の前方参照は
  エラー 6 (パス間でサイズ判断が変わるため)。
- 関数の入れ子定義はエラー 5。定義の外に実行語・リテラルを置くとエラー 5。

### 2.5 プリミティブ語 (関数本体内)

| 分類 | 語 | スタック効果 |
|---|---|---|
| スタック | dup drop swap over rot | 通常の Forth と同じ |
| 算術 | + - * / % | ( a b -- a op b )。/ % は符号付き (div/rem) |
| ビット | & \| ^ << >> | ( a b -- a op b )。>> は論理右シフト |
| 比較 | = <> < > <= >= u< u>= | ( a b -- 1/0 )。u 前置は符号なし |
| 論理 | not | ( n -- n==0 ) |
| メモリ | @ ! c@ c! | @ ( addr -- n ), ! ( n addr -- ), c は 1 バイト |
| 制御 | if else then / begin until / begin while repeat | 後述 |
| 関数 | ret | 関数から復帰 (end は暗黙の ret を含む) |
| I/O | getc putc | ( -- c ) / ( c -- )。UART 1 バイト |
| 終了 | exit | ( code -- )。test finisher へ書き込み終了 |

制御構造 (すべて関数本体内のみ。対応の不整合はエラー 5):

- `cond if A then` : cond が真なら A。
- `cond if A else B then` : cond が真なら A，偽なら B。
- `begin A cond until` : cond が真になるまで A を繰り返す。
- `begin cond while A repeat` : cond が真の間 A を繰り返す。

### 2.6 エラー

| 終了コード | 条件 |
|---|---|
| 0 | 正常終了 |
| 1 | 構文の誤り (数値の桁欠落，名前の 15 バイト超過，文字/文字列リテラルの形式違反，const/buf の値が数値でない) |
| 2 | 未定義の語 |
| 3 | `main` 未定義 |
| 4 | 重複定義 (プリミティブ語との衝突を含む) |
| 5 | 構造の誤り (制御構造の不整合，関数外の実行語，関数の入れ子，`end`/`ret` の位置違反，入力終端時に関数が未閉包) |
| 6 | var/buf/const の前方参照 |
| 7 | 生成コードの参照距離が範囲外 (実用上は発生しない) |

## 3. 実装方針

### 3.1 2 パス構成 + fixup 表

pass 0 (読込み) は入力全体をバッファへ格納する。コメント・文字列・文字リテラルの
内部の `.` は終端としない。

pass 1 (アドレス計算) と pass 2 (出力) は同一の走査を共有する。全トークンの
生成サイズはオペランド値に依存しないため，パス間でアドレスはずれない
(リテラル push は常に 4 語，関数呼出しは常に 1 語，等)。

前方分岐 (if/else/while) の解決には fixup 表を用いる。分岐系トークンには
出現順に連番 k を振る (両パスで同一)。pass 1 は対応する then/repeat 等の
到達時に fixup[k] へ目標アドレスを記録し，pass 2 は分岐の出力時に fixup[k] を
読む。制御構造の対応は制御スタック (kind, value) で検査する。

未知の語は pass 1 では前方参照の関数呼出しとみなして 1 語で数え，
pass 2 で未解決ならエラー 2 とする。var/buf/const は参照時 4 語のため
前方参照するとサイズが狂う。これは定義位置 (入力オフセット) を記号表に記録し，
参照位置と比較して検出する (エラー 6)。

### 3.2 メモリマップ (sol コンパイラ実行時)

| 領域 | 用途 |
|---|---|
| 0x8000_0000 | sol 本体 (末尾にプリミティブ表・テンプレートを含む) |
| 0x800e_0000 | 文字列リテラル組立てバッファ (256 バイト) |
| 0x800f_0000 | scratch: トークン (長さ 1 + 名前 15) |
| 0x8010_0000 | 記号表: 32 バイト/エントリ (名前 16 + 値 4 + 種別 4 + 定義位置 4 + 予約 4) |
| 0x801c_0000 | 制御スタック (8 バイト/段，上向き) |
| 0x801e_0000 | fixup 表 (4 バイト/エントリ) |
| 0x8020_0000 | 入力バッファ |

生成プログラム実行時のマップは 2.3 節 (データスタック・リターンスタック・大域領域)。

### 3.3 コード生成

各語は固定テンプレートの命令列に展開する (テンプレートはプリミティブ表から
参照されるデータ)。リテラル・変数・定数の push は lui+addi+push の 4 語固定。
関数呼出しは `jal x1`，復帰はリターンスタック経由の 3 語。分岐は
`lw x10 0(x9); addi x9 x9 4; beq x10 x0 target` の 3 語 (until/while/if 共通)。
B/J 即値の合成は asm と同じビット散在手順を用いる。

ランタイム前置部 (33 語固定) は先頭に出力され，`main` への jal (pass 2 で解決)，
exit (0x8000_001c)・getc (0x8000_004c)・putc (0x8000_0068) の各ルーチンを含む。

### 3.4 プリミティブ表

1 エントリ 28 バイト: 名前 (長さ 1 + 15) + ハンドラアドレス 4 + 引数 4 + フラグ 4。
引数はテンプレートアドレス (テンプレート語) またはランタイムルーチンの絶対
アドレス (getc/putc/exit)。フラグ 1 は関数外でも許される語 (const/var/buf/fn)。
探索は記号表と同じ 4 語比較の線形探索。表アドレスは asm の `la` で得る。

### 3.5 レジスタ割当 (sol コンパイラ)

| レジスタ | 役割 |
|---|---|
| x1 / x28 / x29 | link (上位 / 中位 / 下位ルーチン) |
| x2 | 制御スタックポインタ (上向き) |
| x3 / x4 | fixup 連番 / 関数内フラグ |
| x5 / x6 | UART base / test finisher base |
| x7 / x8 | 現在の文字 / emit_byte の出力バイト |
| x9 | 生成プログラムの大域領域アロケータ |
| x12 | pass0 状態 / 数値の負号フラグ |
| x13 / x14 / x15 | 入力ポインタ / 出力アドレス / パス番号 |
| x16 / x17 | 記号表 次エントリ / lookup 結果 |
| x18 / x19 / x20 | scratch / 記号表 base / 入力バッファ base |
| x21 / x22 | 命令語アキュムレータ / 分岐目標 |
| x24-x27 | ハンドラ一時値 (x27 = リテラル値) |
| x10, x11, x23, x30, x31 | 一時値 |

## 5. 検証計画 (tests/stage004)

1. ビルド再現: `asm(sol.s)` の SHA-256 が sol.md 記載値と一致すること
2. 実行: 制御構造・関数 (再帰含む)・変数・バッファ・文字列・I/O を使う
   プログラム群 (hello / fib / ctrl) をコンパイルして QEMU 上で実行し,
   出力と終了コードを確認すること
3. フィルタ: getc/putc によるフィルタプログラム (echo) が機能すること
   (Stage 5 の動作形態の先行確認)
4. エラー系: 未定義語 → 2，main 未定義 → 3，重複定義 → 4，制御不整合 → 5，
   前方参照 → 6
5. verify 層: コンパイル出力の逆アセンブルとテンプレート・ランタイムの照合

## 6. Stage 5 への接続

Stage 5 (C サブセットコンパイラ) の処理系ソースは sol 言語で記述する。
文字列処理・記号表などコンパイラに必要な部品はすべて sol の語彙 (メモリ操作・
制御構造・関数) で構成できる。sol への機能追加は行わない。
