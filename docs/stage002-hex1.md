# Stage 2: hex1 設計文書

## 1. 目的と位置づけ

### 1.1 目的

hex0 言語には分岐先の表現がなく，分岐・ジャンプのオフセットは人手で計算するほかない。
オフセットは命令の挿入・削除のたびに再計算となり，プログラム規模の拡大に耐えない
(Stage 1 の hex0.bin 64 命令が手計算の実用上の上限に近い)。

hex1 の目的は，ラベルの定義・参照によって分岐オフセットの手計算を廃止することである。
これにより Stage 3 (アセンブラ) 規模のプログラムをソース上で保守できるようになる。
オフセットの手計算は hex1 自身のソース (hex0 言語で記述) をもって最後とする。

### 1.2 用途

- Stage 3 (アセンブラ) のソースを hex1 言語で記述し，hex1 でビルドする。
- hex1 言語は hex0 言語の上位互換とし，既存の hex0 言語ソースはそのまま処理できる。

```
sh tools/env.sh qemu stage002/hex1.bin < stage003/asm.hex1 > tmp/asm.bin
```

### 1.3 非目標

- ニーモニックは扱わない (Stage 3 の役割)。命令語は引き続き hex ペアで記述する。
- lui/addi 対 (hi20/lo12) のアドレス参照合成は導入しない。データ領域のアドレスは
  固定アドレスの定数として人手で記述する (メモリマップを設計で固定すれば足りるため)。
- リンカ的な複数入力・再配置は扱わない。入力 1 本，ロードアドレス 0x8000_0000 固定。

## 2. 入力言語仕様 (hex1 言語)

### 2.1 前提の要約 (Stage 1 から継承するもの)

本節は判断に必要な前提の要約である。正式な定義は [stage001-hex0.md](stage001-hex0.md) を参照。

実行モデル: hex1 は hex0 と同じくフィルタである。フラットバイナリを
QEMU virt の 0x8000_0000 へロードして実行し，UART (stdin) からソーステキストを読み，
UART (stdout) へバイナリを書き出す。終了は test finisher への書込みで行い，
正常 0x5555 (終了コード 0)，異常 (code << 16) | 0x3333 (終了コード code) である。

基底言語 (hex0 言語) の文法:

```
input    := element* end
element  := byte | comment | ws
byte     := hexdig hexdig     ; 2 桁で 1 バイト即時出力。桁間に他の文字を挟めない
hexdig   := '0'..'9' | 'a'..'f'   ; 小文字のみ
comment  := '#' (LF 以外の任意バイト)*
ws       := SP | TAB | CR | LF
end      := '.'               ; 正常終了。以降は読まない
```

エラーは，許可されない文字 = 終了コード 1，16 進数字 1 桁の状態での終端 = 2。
hex1 はこの文法・エラーの上位互換であり，以下の追加を除きすべて同一に扱う。

### 2.2 文法追加

```
label    := ':' name              ; 定義: 現在の出力アドレスに name を束縛する
bref     := '!' name tmpl         ; B-type 参照: tmpl に imm[12:1] を合成して 4 バイト出力
jref     := '$' name tmpl         ; J-type 参照: tmpl に imm[20:1] を合成して 4 バイト出力
wref     := '&' name              ; ラベルの絶対アドレスを LE 4 バイトで出力
tmpl     := byte byte byte byte   ; imm フィールドを 0 とした命令語 (LE)。
                                  ; byte 間には ws / comment を置ける
name     := namechar{1..15}
namechar := 'a'..'z' | '0'..'9' | '_'
```

- `name` の直後は ws またはコメント開始でなければならない。
- 参照のオフセットは (ラベルアドレス - 参照命令のアドレス) で計算する。
- `label`/`bref`/`jref`/`wref` が桁間 (上位桁のみ読んだ状態) に現れた場合は
  hex0 と同様にエラー 1 とする。

### 2.3 エラー (hex0 から拡張)

| 終了コード | 条件 |
|---|---|
| 0 | 正常終了 |
| 1 | 許可されない文字 (hex0 と同一。name の文字種違反・長さ超過を含む) |
| 2 | 16 進数字が 1 桁の状態で終端 |
| 3 | 未定義ラベルへの参照 |
| 4 | ラベルの重複定義 |
| 5 | オフセットが参照型の表現範囲外 (B: ±4KiB, J: ±1MiB)，または奇数 |

## 3. 実装方針

### 3.1 2 パス構成

UART 入力は巻き戻せないため，入力全体を RAM へ蓄えてから 2 回走査する。

- pass 0 (読込み): `.` まで入力バッファへ格納する。
- pass 1 (アドレス計算): バッファを走査し，出力アドレスを数えながら
  ラベル定義をシンボル表へ登録する。参照は 4 バイトとして数えるのみ。
- pass 2 (出力): 再走査し，バイトを出力する。参照はシンボル表を引いて合成する。

pass 1 と pass 2 は「出力の有無」だけが異なる同一の走査であり，実装を共有する。
(単一パス + 前方参照のバックパッチ方式は，出力バッファへのビット散在パッチが
必要になり状態管理が複雑なため採らない。)

### 3.2 メモリマップ

| 領域 | 用途 |
|---|---|
| 0x8000_0000 | hex1 本体 |
| 0x8010_0000 | シンボル表: 20 バイト/エントリ (name 15 + 長さ 1 + アドレス 4)，線形探索 |
| 0x8020_0000 | 入力バッファ (RAM 末尾 0x87FF_FFFF まで約 126 MiB) |

QEMU virt の既定 RAM 128 MiB を前提とする。容量検査は行わない
(超過し得る規模の入力は Stage 3 以降の課題とする)。

### 3.3 参照の合成

B-type: rel を imm[12|10:5] → bit31-25, imm[4:1|11] → bit11-7 に配置し tmpl と OR する。
J-type: rel を imm[20|10:1|11|19:12] → bit31-12 に配置し tmpl と OR する。
範囲・偶数性の検査後に合成する。tmpl の imm フィールドが 0 であることは検査しない
(ソース記述の責任とする)。

### 3.4 規模見積り

hex0 の 3〜4 倍 (200〜300 命令) を見込む。ソースは hex0 言語で記述するため
分岐オフセットは手計算となる。手計算の負担を抑えるため，機能単位の小ブロックに
分割し，ブロック間はサイズ余裕を持たせた配置とすることを検討する
(未使用領域は 00 で埋め，アドレスを切りのよい値に揃える)。

## 4. 成果物と管理形態

| ファイル | 内容 |
|---|---|
| stage002/hex1.hex | hex1 のソース (hex0 言語)。注釈付き listing を兼ねる |
| stage002/hex1.md | 説明文書: 仕様参照，ビルド手順，期待 SHA-256，プログラム構造表 |

hex1.bin は hex0 によるビルドで再現可能な生成物であり，git 管理しない
(人手エンコードの生バイナリを直接管理するのは hex0.bin までである)。
ビルドはビット再現であり，期待 SHA-256 を hex1.md に記録して検証する。

ビルド標準化のため，本 Stage でビルドスクリプトを導入する
(make はホスト環境に導入されておらず，既存のテスト・環境操作と同じく
POSIX sh スクリプトで統一する):

```
sh tools/build.sh stage002    # hex0 で hex1.hex から tmp/build/hex1.bin を生成
```

## 5. 検証計画 (tests/stage002)

1. ビルド再現: `hex0(hex1.hex)` の SHA-256 が hex1.md 記載値と一致すること
2. 上位互換: `hex1(hex0.hex) == hex0.bin`，`hex1(hex1.hex) == hex0(hex1.hex)`
   (hex0 言語ソースを hex0 と同一に処理すること)
3. ラベル機能: `!` `$` `&` と前方・後方参照を含むテストケースについて，
   オフセット手計算版 (hex0 言語) と出力が一致すること
4. エラー系: 未定義ラベル → 3，重複定義 → 4，奇数オフセット → 5
5. verify 層: 生成した hex1.bin の逆アセンブルと hex1.hex の注釈の照合
   (`verify/checklisting.sh` が機械照合する。テストから毎回呼ぶ)

### 5.3 コード 5 は 3 バイトで出せる

コード 5 (範囲外) について長らく「数千命令規模の入力を要するため
テスト対象外」と書いてきたが，これは **B-type の飛距離 (±4KiB) だけを
見た誤り** だった。同じコード 5 は**奇数オフセット**でも出る。分岐命令は
飛び先の最下位ビットを表せないので，参照先が 2 の倍数でなければ
その場で弾かれる。

```
:a 00 !a 63 00 00 00 .
```

`:a` の直後に 1 バイト置いたので `a` は奇数番地を指し，`!a` の合成が
コード 5 になる。距離を稼ぐ必要はない。テストはこの形を使う。
