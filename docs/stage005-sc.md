# Stage 5: sc 設計文書 (言語仕様書を兼ねる)

## 1. 目的と位置づけ

### 1.1 目的

sol はスタック指向であり，式・ローカル変数・引数の表現を書き手のスタック管理に
委ねている。Stage 6 (セルフホスト) で必要になる「自分自身を記述できる言語」には，
式・関数引数・ローカル変数・ポインタ・構造体を備えた C サブセット相当の
抽象度が必要である。

sc の目的は，この C サブセットを定義し，そのコンパイラを sol 言語で実装する
ことである。名称 sc は small C の略である。本文書は sc 言語の仕様書を兼ねる
([plan.md](plan.md) 4 章 Stage 5 の完了条件は本仕様書に対するテストスイートの通過である)。

### 1.2 用途

- Stage 6 (セルフホスト) で sc コンパイラ自身を sc 言語で再記述する。

```
sh tools/env.sh qemu tmp/build/sc.bin < prog.sc > tmp/prog.bin
```

出力は前段と同じフラットバイナリ (ロードアドレス 0x8000_0000) であり，
QEMU 上で単体実行できる。

### 1.3 非目標

- プリプロセッサ・型修飾子・浮動小数点・多次元配列・初期化子・可変長引数は
  扱わない。
- 構造体の値渡し・値代入は扱わない (ポインタ・メンバ経由で操作する)。
- 最適化は行わない。

## 2. sc 言語仕様

### 2.1 字句

- 入力の終端は EOT (0x04) である (C ソースには `.` が頻出するため，
  hex0〜sol の `.` 終端は使わない)。テストハーネスはソース末尾に EOT を付加する。
- コメントは `//` から行末まで。空白は SP/TAB/CR/LF。
- 識別子: `[a-z_][a-z0-9_]*`，1..15 バイト。英大文字は使わない。
- 整数リテラル: 10 進，または `0x` 16 進 (小文字)。32 bit。負数は単項 `-` で表す。
- 文字リテラル: `'c'`。エスケープは `\n` `\t` `\0` `\\` `\'` `\"` のみ。
- 文字列リテラル: `"..."`。エスケープは同上。長さ 255 以下。NUL 終端されて
  コードに埋め込まれ，値は先頭アドレス (`char *`) である。
- 予約語: `int` `char` `struct` `if` `else` `while` `return`

### 2.2 型

```
type      := 'int' | 'char' | 'struct' ident
fulltype  := type '*'*
```

- すべての値は 32 bit セルである。`char` の値もセルとして扱うが，
  `char` 型の記憶域 (スカラ変数・配列要素・メンバ・ポインタ参照先) への
  アクセスは 1 バイト (lbu/sb) で行う。
- ポインタは任意の深さを取れる。配列は 1 次元のみで，式中では先頭要素への
  ポインタに退化する (代入不可)。
- 構造体はメンバとして `int` / `char` / ポインタ / `int`・`char` の 1 次元配列を
  持てる (構造体型のメンバは持てない。構造体へのポインタメンバは可)。
  メンバのオフセットは宣言順で，char 配列以外は 4 バイト境界に整列し，
  構造体サイズは 4 の倍数へ切り上げる。
- 構造体の変数は大域のみ (ローカル・引数・返却値は不可)。ポインタは自由。

### 2.3 プログラム構造

```
program    := (structdecl | globaldecl | funcdef)* EOT
structdecl := 'struct' ident '{' (fulltype ident ('[' number ']')? ';')* '}' ';'
globaldecl := fulltype ident ('[' number ']')? ';'
funcdef    := fulltype ident '(' params? ')' '{' localdecl* stmt* '}'
params     := fulltype ident (',' fulltype ident)*
localdecl  := fulltype ident ('[' number ']')? ';'
```

- 大域変数は 0x8010_0000 から宣言順に割り付けられる (バイナリには含まれず，
  初期値は不定である。QEMU 起動直後は 0)。
- ローカル変数はフレーム上に確保される。宣言は関数本体の先頭にまとめる
  (文の後の宣言はエラー 1)。配列を含むフレームは 2040 バイト以下 (エラー 6)。
- 引数はセル値のみ (配列・構造体は不可。ポインタは可)。
- 関数は前方参照できる (未定義のまま入力が終わればエラー 2)。
  変数・構造体は使用前に宣言されていなければならない (エラー 2)。
- `main` の定義は必須である (エラー 3)。`main` の返却値がプログラムの
  終了コードになる。

### 2.4 文

```
stmt := '{' stmt* '}'
      | 'if' '(' expr ')' stmt ('else' stmt)?
      | 'while' '(' expr ')' stmt
      | 'return' expr? ';'
      | expr ';'
      | ';'
```

- 条件は 0 = 偽，非 0 = 真。
- `return` を通らず関数末尾に到達した場合は 0 を返す。

### 2.5 式

優先順位 (低い順)。二項演算子はすべて左結合，代入のみ右結合:

```
1: =
2: ||          (短絡。結果は 1/0)
3: &&          (短絡。結果は 1/0)
4: |
5: ^
6: &
7: == !=       (結果は 1/0)
8: < > <= >=   (符号付き比較。結果は 1/0)
9: << >>       (>> は論理右シフト)
10: + -
11: * / %      (/ % は符号付き)
単項: - ! * (参照はがし) & (アドレス取得)
後置: [expr] (添字) (args) (関数呼出し) .ident ->ident
一次: 整数/文字/文字列リテラル, 識別子, '(' expr ')'
```

- ポインタ演算: `p + n` / `p - n` は指し先サイズでスケールされる。
  `p - q` (同型ポインタ) はバイト差を指し先サイズで割った要素数を返す。
  `a[i]` は `*(a + i)` と同じである。
- 代入の左辺は左辺値 (変数・`*p`・`a[i]`・メンバ) でなければならない (エラー 5)。
  代入式の値は代入された値である。
- 関数呼出しの実引数は左から右に評価される。引数の個数は宣言と一致しなければ
  ならない (エラー 5)。ただしこの検査が働くのは，**呼出しの時点で個数が
  判っている** (呼出しより前に定義済みの) 関数だけである。前方参照の
  呼出しは個数が未知 (-1) の間は検査を省き，定義後も過去の呼出し位置を
  遡って再検査しない。このため前方参照の呼出しの個数不一致はエラーに
  ならず，データスタックが不均衡な誤ったコードが黙って生成される
  (既知の制限。実装は `ecallseq`。同系譜の scc / occ も同じ)。

### 2.6 組込み関数

| 関数 | 意味 |
|---|---|
| `getc()` | UART から 1 バイト読み，その値を返す |
| `putc(c)` | UART へ 1 バイト書く。0 を返す |
| `exit(c)` | 終了コード c で終了する。戻らない |

### 2.7 実行モデル (生成コード)

- データスタック x9 (0x87f0_0000 から下向き): 式の評価と実引数・返却値の受渡し。
- フレームスタック x2 (0x8780_0000 から下向き)，フレームポインタ x8:
  フレームは [戻り先 ra][旧 x8][引数][ローカル] の順で，呼出し毎に確保される。
- 生成バイナリ先頭には固定のランタイム (32 語: レジスタ初期化，`main` 呼出し，
  exit/getc/putc) が置かれる。`main` の返却値が test finisher へ書かれる
  (0 → 0x5555，非 0 → (code << 16) | 0x3333)。

### 2.8 コンパイラのエラー

| 終了コード | 条件 |
|---|---|
| 0 | 正常終了 |
| 1 | 構文エラー (字句の誤り・長さ超過・宣言位置の誤りを含む) |
| 2 | 未定義の識別子 (入力終端時に未解決の前方参照関数を含む) |
| 3 | `main` 未定義 |
| 4 | 重複定義 |
| 5 | 型エラー (非左辺値への代入・非ポインタの参照はがし・メンバ誤り・引数個数不一致など) |
| 6 | 容量超過 (フレーム 2040 バイト超・文字列 255 超・表あふれなど) |

### 2.9 前段からの変化と記述例

前段 (sol) からの主な変化:

- スタック操作 (dup/swap 等) と後置記法が消え，中置演算子の式・優先順位・
  括弧が使えるようになった。レジスタもスタックも書き手からは見えない。
- 関数が名前付きの引数とローカル変数を持ち，値を `return` で返すようになった
  (sol は大域変数とデータスタックのみ)。
- ポインタ・配列・構造体という型の概念が入った。ポインタ演算は指し先の
  サイズでスケールされる。
- 入力終端が `.` から EOT (0x04) に変わった (2.1 節)。

想定している記述の例 (連結リストの走査。宣言・構造体・ポインタ・
制御構造・関数の組合せ):

```
// 単方向リストの合計を返す
struct node {
  int val;
  struct node *next;
};
struct node n1;
struct node n2;

int total(struct node *p) {
  int s;
  s = 0;
  while (p) {
    s = s + p->val;
    p = p->next;
  }
  return s;
}

int main() {
  n1.val = 40;
  n2.val = 8;
  n1.next = &n2;
  n2.next = 0;
  putc('0' + total(&n1) / 10);
  putc('0' + total(&n1) % 10);
  putc('\n');
  return 0;
}
```

仕様の各機能を網羅する実例はテストスイート (5 章) を参照:

- [tests/stage005/arith.sc](../tests/stage005/arith.sc): 演算子の優先順位・短絡評価
- [tests/stage005/fib.sc](../tests/stage005/fib.sc): 再帰・前方参照・10 進出力
- [tests/stage005/ptr.sc](../tests/stage005/ptr.sc): ポインタ・配列・アドレス取得・文字列
- [tests/stage005/struct.sc](../tests/stage005/struct.sc): 構造体・メンバアクセス・連結リスト
- [tests/stage005/upper.sc](../tests/stage005/upper.sc): getc/putc によるフィルタ

## 3. 実装方針 (sc コンパイラ = sol プログラム)

### 3.1 単一パス + 出力バッファ

前段 (hex1/asm/sol) は UART へ直接出力するため 2 パス構成を採ったが，
sc は sol 言語で実装され，メモリ操作が自由である。そこで生成コードを
メモリ上の出力バッファへ書き，前方分岐・前方呼出しはバックパッチで解決し，
最後にバッファ全体を UART へ書き出す単一パス構成とする。

- if/while/&&/|| の前方分岐: 分岐命令の位置を記録し，到達時に書き戻す。
- 前方参照の関数呼出し: 記号表エントリに未解決呼出し位置の連結リストを持つ
  (プレースホルダ語の中に前の位置を格納する)。定義時に一括で書き戻す。

### 3.2 再帰下降構文解析

優先順位の各段を関数にした再帰下降とする。式の評価結果は「値がスタックに
積まれた状態」либо「アドレスが積まれた状態 (左辺値，ロード遅延)」であり,
大域フラグ (elv) と型 (ety) で区別する。代入・`&` は左辺値を要求し,
その他の演算子は必要時にロード命令を発行して右辺値化する。

### 3.3 メモリマップ (sc コンパイラ実行時。sol の大域領域 0x8010_0000 から確保)

| 領域 | 用途 |
|---|---|
| srcbuf (1 MiB) | 入力ソース (pass0 で EOT まで読込み) |
| outbuf (1 MiB) | 生成バイナリ (バックパッチ対象) |
| gsym (40 B × 2048) | 大域記号表 (変数・関数): 名前 16 + 種別 4 + 型 4 + 値 4 + 定義済 4 + 配列 4 + 引数数 4 + 予約 4 |
| lsym (32 B × 256) | ローカル記号表 (引数・ローカル): 名前 16 + 型 4 + オフセット 4 + 配列 4 + 予約 4 |
| stab (24 B × 256) | 構造体表: 名前 16 + サイズ 4 + 予約 4 |
| mtab (28 B × 2048) | メンバ表: 構造体番号 4 + 名前 16 + 型 4 + オフセット 4 |
| sbuf (256 B) | 文字列リテラル組立て |
| tname (16 B) | 現在の識別子トークン |

型の表現: ty = (ポインタ深さ << 16) | 基底。基底は 0 = char, 1 = int,
2+k = 構造体 k。配列は記号表の配列フラグで表す。

### 3.4 生成コードの規約

式の値はデータスタック経由 (sol と同じテンプレート群)。関数プロローグは
フレーム確保と実引数のフレームへの移送，エピローグはフレーム解放と
`jalr x0 0(x1)`。ローカル/引数のアドレスは `addi x10 x8 off; push`，
大域は `lui+addi; push`。ロード/ストアは型により lw/lbu / sw/sb を選ぶ。


## 5. 検証計画 (tests/stage005)

仕様書 (2 章) に対するテストスイートとして，機能別の sc プログラム群を
コンパイル・実行し，出力と終了コードを確認する。

1. ビルド再現: `sol(sc.sol)` の SHA-256 が sc.md 記載値と一致すること
2. 式・演算子: 優先順位・短絡評価・比較・シフトを含む式の評価 (arith.sc)
3. 関数: 引数・返却値・再帰・前方参照 (fib.sc)
4. ポインタ・配列: `&` `*` 添字・ポインタ演算・char 配列 (ptr.sc)
5. 構造体: メンバアクセス `.` `->`・構造体ポインタ (struct.sc)
6. 制御・大域変数・文字列・I/O: フィルタプログラム (upper.sc)
7. エラー系: 構文 → 1，未定義 → 2，main 未定義 → 3，重複 → 4，
   型 → 5 (非左辺値への代入)
8. verify 層: コンパイル出力の逆アセンブルとランタイム・テンプレートの照合

## 6. Stage 6 への接続

Stage 6 (セルフホスト) では sc コンパイラを sc 言語で再記述する。
本仕様の範囲 (関数・ポインタ・構造体・配列・文字列) は c4 系の
セルフホストコンパイラの実績に照らして自己記述に十分である。
sc への機能追加が必要になった場合は本仕様書を改訂し，テストを追加する。
