# Stage 7: occ (現代化) 設計文書

## 1. 目的と位置づけ

### 1.1 目的

scc までのコード生成は構文直結のテンプレート展開であり，式の値をすべて
メモリ上のデータスタック経由で受け渡す。1 語のリテラルにも 4 命令を要し，
生成コードの質が実行時間・サイズの双方を制約している。

occ (optimizing sc compiler) の目的は，コンパイラの内部構造を現代的な形 —
中間表現 (IR) を介した多段構成 — に再設計することである
([plan.md](plan.md) 4 章 Stage 7)。構文解析は IR を構築し，最適化パスが
IR を書き換え，レジスタ割付を経てコードを出力する。sc 言語仕様
([stage005-sc.md](stage005-sc.md) 2 章) は変更しない。

### 1.2 完了条件

- 各最適化パスの単体テストが通ること (5 章)
- 固定点検証の維持: B2 = B1(occ.sc), B3 = B2(occ.sc) について B2 == B3
  (B1 は scc で bootstrap した occ)。コード生成が変わるため B1 == B2 は
  成立しない (B1 は旧コード生成による occ，B2 以降が occ 自身によるコード生成)

### 1.3 非目標

- sc 言語仕様の変更・拡張。
- 制御フローを跨ぐ変数の SSA 化 (mem2reg)・φ 関数。変数アクセスは
  load/store のまま残す (2.1 節)。
- 命令スケジューリング・ループ最適化等の高度なパス。

## 2. 中間表現 (IR)

### 2.1 形式

関数単位の 3 番地コード列。各命令は高々 1 個の値を定義し，値は定義した
命令の番号で参照される。式の一時値は構文上一度しか定義されないため，
この IR は φ 関数を持たない SSA である。ローカル・大域変数は
メモリ (LOAD/STORE) として残し，制御フローを跨ぐ値の受渡しはすべて
メモリを経由する (&& / || の結果も隠しスロットを使う)。

| 命令 | 意味 |
|---|---|
| CONST v | 定数 v を定義 |
| LADDR off / GADDR a / GSTR p | ローカルアドレス / 大域絶対アドレス / 文字列プールアドレス |
| LOADW a / LOADB a | 語 / バイトのロード |
| STOREW a v / STOREB a v | 語 / バイトのストア |
| BIN op a b | 二項演算 (add sub mul div rem and or xor sll srl slt sgt sle sge seq sne) |
| NEG a / NOT a | 単項演算 |
| ARG v / CALL f n | 実引数 (データスタックへ push) / 呼出し (結果を定義) |
| RET v | 返却 |
| LABEL l / JMP l / BZ v l / BNZ v l | ラベル / 無条件・条件分岐 |

### 2.2 生成コードの規約 (ABI は scc と同一)

関数間 ABI (実引数・返却値をデータスタック x9 で受渡し，フレームスタック
x2 + fp x8，ランタイム前置部 32 語) は scc と同一に保つ。関数内部のみが
変わる: 式の一時値はレジスタに割り付けられ，データスタックは呼出しの
引数・返却値の受渡しにだけ使う。

- 割付対象レジスタ: x13..x27 (15 本)。すべて callee-saved とし，
  使用したものだけをプロローグで退避しエピローグで復元する
  (呼出しを跨いで生きる値の caller 側退避を不要にするため)。
- x10, x11 はロード/ストア/スピルの scratch。x5, x6 はランタイム専用。
- スピル: 割付けで空きがない場合は最終使用が最も遠い値をフレームの
  スピル領域へ退避する。スピル領域はローカルの後ろに確保する。

## 3. 最適化パス

各パスは IR 配列上の書換えである。適用順: fold → dce → 割付け。

| パス | 内容 |
|---|---|
| fold (定数畳み込み) | 両オペランドが CONST の BIN と，CONST の NEG/NOT を CONST に置換する。除算・剰余は除数 0 のとき畳み込まない。BZ/BNZ の条件が CONST の場合は JMP または削除に置換する |
| dce (不要コード削除) | 使用されない純粋な値 (CONST/アドレス/BIN/NEG/NOT/LOAD) の定義を削除する。LOAD は副作用なしとみなす (I/O は getc/putc を使うこと。生ポインタの読み捨ては削除され得る) |

コード出力段の改良 (パスではなく出力規則):

- -2048..2047 の定数は addi 1 語で実体化する (従来は常に lui+addi の 2 語)。
- 条件分岐 (BZ/BNZ) は「逆条件の B-type で 1 語跳び越え + jal」の 2 語で
  出力する。B-type 即値の範囲は ±4KiB しかなく，従来実装 (sc/scc) は
  範囲検査なしに直接 beq を発行するため，4KiB を超える if/while 本体を
  silent に誤コンパイルする (本 Stage の開発中に発見した潜在制限)。
  occ は jal (±1MiB) を経由することでこの制限を除去する。

なお bootstrap の 1 段目 (B1 = scc(occ.sc)) は旧実装のコード生成で occ.sc を
コンパイルするため，occ.sc 自身は各 if/while 本体が旧コード生成でも
±4KiB に収まるよう，大きなループ本体を関数に分割して記述している
(fold の命令単位処理 foldins など)。

## 5. 検証計画 (tests/stage007)

1. ビルド再現: B2 (occ.bin) の SHA-256 が occ.md 記載値と一致すること
2. 固定点: B3 = B2(occ.sc) が B2 とビット一致すること (完了条件)
3. 同値性: Stage 5 仕様スイート (arith/fib/ptr/struct/upper) を B2 で
   コンパイル・実行し，仕様どおりの出力・終了コードになること
4. パス単体テスト (コンパイル結果のビット一致で判定):
   - fold: `return 2 + 3 * 4;` == `return 14;`，`return -(2 + 3);` == `return -5;`
   - dce: `1 + 2;` (捨てられる式) を含むプログラム == それを除いたプログラム
   - 割付け・出力改良: 同一プログラムについて B2 の出力が scc の出力より
     小さいこと (データスタック経由のテンプレート展開の除去)
5. エラー系: scc と同じエラーコード (1..6) を返すこと
6. verify 層: B2 の出力の逆アセンブルと割付け規約 (2.2 節) の照合
