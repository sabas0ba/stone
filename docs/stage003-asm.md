# Stage 3: asm 設計文書

## 1. 目的と位置づけ

### 1.1 目的

hex1 言語は分岐オフセットの手計算を廃止したが，命令語そのものは依然として
hex ペアの手エンコードである。レジスタ番号や即値を 1 bit 単位でフィールドへ
詰める作業は機械的で誤りやすく，Stage 4 (低級構造化言語) 規模の記述には耐えない。

asm の目的は，命令エンコードの手作業を廃止することである。RV32IM の全命令を
ニーモニックとオペランドで記述できるようにし，手エンコードは asm 自身のソース
(hex1 言語で記述) をもって最後とする。

### 1.2 用途

- Stage 4 (低級構造化言語) の処理系ソースを asm 言語で記述し，asm でビルドする。
- テスト・検証プログラムの記述にも用いる。

```
sh tools/env.sh qemu tmp/build/asm.bin < stage004/xxx.s > tmp/xxx.bin
```

### 1.3 非目標

- リンカ機能 (複数入力・再配置・セクション) は扱わない。入力 1 本，
  ロードアドレス 0x8000_0000 固定のフラットバイナリ出力である。
- 式評価 (ラベル演算 `label+4` 等) は扱わない。即値は数値リテラルのみ。
- `%hi`/`%lo` 相当のアドレス分解は疑似命令 `la` に限定して提供する。
- 文字列リテラル (`.ascii` 相当) は扱わない。必要になった段階 (Stage 4) で
  上位言語側が担う。

## 2. 入力言語仕様 (asm 言語)

### 2.1 前提の要約 (前段から継承するもの)

実行モデルは hex0/hex1 と同じフィルタである
(正式な定義は [stage001-hex0.md](stage001-hex0.md) 3 章)。
フラットバイナリを QEMU virt の 0x8000_0000 へロードして実行し，
UART (stdin) からソーステキストを読み，UART (stdout) へバイナリを書き出す。
終了は test finisher への書込みで行い，正常 0x5555 (終了コード 0)，
異常 (code << 16) | 0x3333 (終了コード code) である。
入力の終端は hex0/hex1 と同じく `.` である (UART に EOF はないため)。

### 2.2 字句

```
input    := element* end
element  := labeldef | statement | comment | ws
end      := '.'                   ; 単独の '.'。以降は読まない
comment  := '#' (LF 以外の任意バイト)*
ws       := SP | TAB | CR | LF | ','
name     := namehead namechar{0..14}
namehead := 'a'..'z' | '_'
namechar := 'a'..'z' | '0'..'9' | '_'
reg      := 'x' dec               ; x0..x31 のみ。ABI 名は持たない
imm      := ['-'] dec | ['-'] '0x' hex
dec      := ('0'..'9')+
hex      := ('0'..'9' | 'a'..'f')+   ; 小文字のみ (hex0/hex1 と同じ)
```

- `,` は空白と同一に扱う。オペランド区切りの `,` は書いても書かなくてもよい。
- 命令・ディレクティブ・ラベルはすべて自由形式で，行の概念を持たない
  (コメントの終端にのみ LF を用いる)。
- `name` はラベル名の名前空間とニーモニックの名前空間で共通の字句である。
  ラベル定義は `name ':'` (直後に `:`，間に空白を挟まない) で表す。
  `:` が続かない `name` はニーモニックとして解釈する。

### 2.3 文

```
labeldef  := name ':'             ; 現在の出力アドレスに name を束縛する
statement := mnemonic operand*    ; オペランドの数と形式はニーモニックで決まる
```

命令の形式とオペランド:

| 形式 | 文法 | 命令 |
|---|---|---|
| R | rd rs1 rs2 | add sub sll slt sltu xor srl sra or and mul mulh mulhsu mulhu div divu rem remu |
| I | rd rs1 imm12 | addi slti sltiu xori ori andi |
| SH | rd rs1 shamt | slli srli srai |
| LD | rd imm12 '(' rs1 ')' | lb lh lw lbu lhu jalr |
| S | rs2 imm12 '(' rs1 ')' | sb sh sw |
| B | rs1 rs2 label | beq bne blt bge bltu bgeu |
| U | rd imm20 | lui auipc |
| J | rd label | jal |
| FX | (なし) | fence ecall ebreak |

- imm12: -2048..2047 (符号付き 12 bit)。範囲外はエラー 6。
- shamt: 0..31。範囲外はエラー 6。
- imm20: 0..0xfffff (lui/auipc の上位即値を生の値で書く)。範囲外はエラー 6。
- label: 分岐・ジャンプ先はラベルのみ (数値オフセットは書けない)。
  オフセットはアセンブラが計算する。範囲 (B: ±4KiB, J: ±1MiB) 外または
  奇数はエラー 5 (hex1 と同一)。
- `fence` は fence iorw,iorw (0x0ff0000f) 固定とする。pred/succ の指定は持たない。

### 2.4 疑似命令

| 疑似命令 | 展開 | サイズ |
|---|---|---|
| nop | addi x0, x0, 0 | 4 |
| mv rd rs | addi rd, rs, 0 | 4 |
| li rd imm32 | lui rd, hi20; addi rd, rd, lo12 | 8 (固定) |
| la rd label | lui rd, hi20; addi rd, rd, lo12 (ラベル絶対アドレス) | 8 (固定) |
| j label | jal x0, label | 4 |
| call label | jal x1, label | 4 |
| jr rs | jalr x0, 0(rs) | 4 |
| ret | jalr x0, 0(x1) | 4 |
| beqz rs label | beq rs, x0, label | 4 |
| bnez rs label | bne rs, x0, label | 4 |

- li/la は即値の大小によらず常に 2 命令 (8 バイト) に展開する。
  パス間でサイズ判断を変えないための固定化である。imm32 は全 32 bit を受け付け，
  hi20 = (imm + 0x800) の上位 20 bit，lo12 = imm の下位 12 bit (符号付き) に分解する。

### 2.5 ディレクティブ

ディレクティブはニーモニックと同じ名前空間の語である (`.` 前置は用いない。
`.` は終端記号であり，終端判定を 1 文字で行えるようにするため)。

| 語 | 意味 |
|---|---|
| word (imm32 \| label) | 32 bit 値を LE 4 バイト出力。label は絶対アドレス |
| byte imm | 1 バイト出力。imm は -128..255 (範囲外はエラー 6)，下位 8 bit を出力 |

- 整列 (アライメント) の強制・自動化は行わない。`byte` の後に命令を置く場合の
  整列は書き手の責任とする (hex0/hex1 と同じ精神)。
- `word` のオペランドは，先頭が数字または `-` なら即値，`a-z_` ならラベルと解釈する。

### 2.6 エラー

| 終了コード | 条件 |
|---|---|
| 0 | 正常終了 |
| 1 | 不正な文字・構文 (名前の長さ超過・数値の桁欠落を含む) |
| 2 | 未知のニーモニック |
| 3 | 未定義ラベルへの参照 |
| 4 | ラベルの重複定義 |
| 5 | 分岐・ジャンプのオフセットが範囲外 (B: ±4KiB, J: ±1MiB)，または奇数 |
| 6 | 即値が形式の範囲外 (imm12/shamt/imm20/byte) |
| 7 | 不正なレジスタ (x0..x31 以外) |

3, 4, 5 は hex1 と同一の意味である。エラー検出時は即時に異常終了する。

## 3. 実装方針

### 3.1 2 パス構成 (hex1 と同一の骨格)

- pass 0 (読込み): `.` まで入力バッファへ格納する (コメント内の `.` は終端としない)。
- pass 1 (アドレス計算): 走査してラベル定義をシンボル表へ登録する。
  命令はオペランドまで完全に構文解析し，サイズ分だけ出力アドレスを進める
  (出力は抑止)。ラベル参照の解決は行わない。
- pass 2 (出力): 再走査し，エンコードして出力する。ラベル参照を解決する。

pass 1 と pass 2 は同一の走査ルーチンを共有し，「出力の有無」と
「ラベル解決の有無」だけをパス番号で分岐する。全命令のサイズは
オペランド値に依存しない (li/la の 8 バイト固定化) ため，パス間で
アドレスがずれることはない。

### 3.2 メモリマップ (hex1 と同一)

| 領域 | 用途 |
|---|---|
| 0x8000_0000 | asm 本体 (末尾にニーモニック表を含む) |
| 0x800f_0000 | scratch: 名前組立てバッファ (長さ 1 + 名前 15) |
| 0x8010_0000 | シンボル表: 20 バイト/エントリ (長さ 1 + 名前 15 + アドレス 4)，線形探索 |
| 0x8020_0000 | 入力バッファ (RAM 末尾まで約 126 MiB) |

### 3.3 ニーモニック表

命令の諸元は asm 本体末尾のデータ表に置く。1 エントリ 24 バイト:

| オフセット | 内容 |
|---|---|
| 0 | 名前長 (1..15)。0 は表の終端 |
| 1..15 | 名前 (0 詰め) |
| 16..19 | base word: opcode / funct3 / funct7 を配置済みで他フィールドが 0 の命令語 (LE)。FX はこれをそのまま出力する |
| 20..23 | ハンドラの絶対アドレス (形式ごとの解析・エンコードルーチン) |

探索はシンボル表と同じ 4 語比較の線形探索。ハンドラアドレスは hex1 の `&` で
記述するため，表の再配置に人手の追随は不要である。表の先頭アドレスは
`auipc` + 直後に置いた `&mtable` データ語の `lw` で実行時に取得する
(hex1 言語には任意距離のアドレス取得構文がないため)。

### 3.4 エンコード

- レジスタ番号は rd → bit11:7, rs1 → bit19:15, rs2 → bit24:20 へシフトして OR する。
- B/J 形式の即値ビット散在は hex1 の h_bang/h_dollar と同じ手順を用いる。
- I/S/U の即値は範囲検査 (2.3 節) の後に配置する。
- li/la の hi20/lo12 分解は hi = (imm + 0x800) & 0xfffff000 を lui へ,
  lo = imm[11:0] を addi へ配置する (addi 側の符号拡張を hi 側の +0x800 で補償)。

### 3.5 asm 自身のソース記述 (hex1 言語) と転記コメント

asm のソース stage003/asm.hex1 は hex1 言語で記述する。分岐・ジャンプは
すべて hex1 のラベル参照 (`!` `$`) で書くため，hex0 で書いた hex1 のような
ブロック整列・パディングは不要である。

全コード行・データ行には `#:` で始まる転記コメントを付け，その内容を
asm 言語の文として書く (ラベル定義行は `name:` を転記する)。転記コメントを
機械抽出したものは asm 言語で書いた asm 自身のソースとなり，自己アセンブルの
固定点検証に用いる (5 章)。これにより手エンコードの全行が機械的に照合される。

### 3.6 レジスタ割当

| レジスタ | 役割 |
|---|---|
| x1 | link (ハンドラからの下位ルーチン呼出し) |
| x5 / x6 | UART base / test finisher base |
| x7 | 現在の文字 |
| x8 | emit_byte の出力バイト |
| x12 | pass0 コメント内フラグ / parse_imm 負号フラグ |
| x13 | 入力バッファ読取りポインタ |
| x14 | 出力アドレス (絶対) |
| x15 | パス番号 (1/2) |
| x16 / x17 | シンボル表 次エントリ / lookup 結果 (0=未発見) |
| x18 / x19 / x20 | scratch base / シンボル表 base / 入力バッファ base |
| x21 | 命令語の組立てアキュムレータ |
| x22 | 相対オフセット |
| x24 / x25 / x26 / x27 | rd / rs1 / rs2 / 即値 |
| x30 | ニーモニック表 base |
| x28 / x29 | link (中位 / 下位ルーチン) |
| x9-x11, x23, x31 | 一時値 |

## 4. 成果物と管理形態

| ファイル | 内容 |
|---|---|
| stage003/asm.hex1 | asm のソース (hex1 言語)。全行に asm 言語の転記コメント (`#:`) を持つ |
| stage003/asm.md | 説明文書: 仕様参照，ビルド手順，期待 SHA-256，プログラム構造表 |

asm.bin は hex1 によるビルドで再現可能な生成物であり，git 管理しない。
ビルドはビット再現であり，期待 SHA-256 を asm.md に記録して検証する。

```
sh tools/build.sh stage003   # hex0 -> hex1 -> asm の順で tmp/build/asm.bin を生成
```

## 5. 検証計画 (tests/stage003)

1. ビルド再現: `hex1(asm.hex1)` の SHA-256 が asm.md 記載値と一致すること
2. 全命令エンコード: RV32IM 全 48 命令 (+ 全疑似命令・ディレクティブ) を含む
   ソースを asm で処理し，手エンコードした期待バイナリ (hex0 言語で記述し
   hex0 でビルド) とビット一致すること
3. 自己アセンブル固定点: asm.hex1 の転記コメント (`#:`) を抽出した asm 言語
   ソースを asm で処理した出力が，asm.bin 自身とビット一致すること
   (手エンコードと asm のエンコードの相互検証)
4. 実行: ラベル・疑似命令を用いたプログラムを asm でビルドし，QEMU 上で
   実行して出力と終了コードを確認すること
5. エラー系: 未知ニーモニック → 2，未定義ラベル → 3，重複定義 → 4，
   即値範囲外 → 6，不正レジスタ → 7
6. verify 層: 全命令エンコードテストの出力を逆アセンブルし，ソースの記述と
   照合すること

## 6. Stage 4 への接続

Stage 4 (低級構造化言語) の処理系ソースは asm 言語で記述する。
文字列リテラル・式評価等の利便機能は asm へ追加せず，必要なら Stage 4 側で担う。
