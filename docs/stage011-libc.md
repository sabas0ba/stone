# Stage 11: フリースタンディング libc 設計文書

## 1. 目的と位置づけ

### 1.1 目的

Stage 10 で C89 の**言語**が揃った。しかし C のプログラムは言語だけでは
書けない。`memcpy` も `strlen` も `malloc` も無い状態では，これまでの
コンパイラ自身がそうだったように，すべてを手書きの走査で済ませることに
なる。

Stage 11 の目的は **標準ライブラリの中核を自作の C で用意する** ことである。
[roadmap.md](roadmap.md) Phase B の 1 段目であり，これが済めば「他人の書いた
C」が要求するものの半分が揃う。

### 1.2 フリースタンディングとは

C89 は処理系を 2 種類に分ける。

| | 要求されるヘッダ |
|---|---|
| ホスト形式 (hosted) | 標準ヘッダすべて。`main` が呼ばれ `stdio` が使える |
| **フリースタンディング** | `float.h` `limits.h` `stdarg.h` `stddef.h` のみ |

現時点の実行環境はベアメタルで，ファイルも標準入出力もない。したがって
まずフリースタンディングを名乗り，そのうえで **OS を要さない範囲の関数**
(`string.h` / `ctype.h` / `stdlib.h` の一部) を足す。`stdio.h` は
syscall を獲得する Stage 12 の課題である。

### 1.3 分割

| 部 | 内容 |
|---|---|
| 第 1 部 | 土台と純粋な関数: `stddef.h` `limits.h` `string.h` `ctype.h` (3 章) |
| 第 2 部 | 記憶域: `malloc` / `free` / `calloc` / `realloc` |
| 第 3 部 | 整列と探索・数値変換: `qsort` `bsearch` `atoi` `strtol` `abs` `div` |

第 1 部を先に置くのは，**どれも状態を持たない** からである。ヒープの設計
(第 2 部) や比較関数を介した呼出し (第 3 部) と違い，入力から出力が一意に
決まるので，検証が値の照合だけで済む。libc の置き場・ビルドの通し方・
テストの型をここで決めてしまい，後続はその上に足す。

### 1.4 非目標

- `stdio.h` (ファイル・標準入出力)。syscall が要るので Stage 12
- 浮動小数点を扱うもの (`math.h`, `strtod`, `%f`)。RV32I**M** に FPU が無く，
  ソフトウェア浮動小数点そのものが独立した課題である
- ロケール (`setlocale`)・シグナル (`signal.h`)・`setjmp`
- ワイド文字 (`wchar.h`)

## 2. 構成

### 2.1 置き場

```
include/        ヘッダ (利用者から見える面)
  stddef.h      size_t, NULL, offsetof
  limits.h      CHAR_BIT, INT_MAX, ...
  stdarg.h      (Stage 10 第 3 部の 2 で追加済み)
  string.h
  ctype.h
lib/            実装 (自作の C)
  string.c
  ctype.c
```

ヘッダと実装を分けるのは，**利用者が見るものと処理系が持つものを分ける**
ためである。`include/` は前処理で取り込まれ，`lib/` はコンパイルされて
オブジェクトになる。

### 2.2 リンクの通し方

ld は既に複数のオブジェクトを受け取れる (Stage 8)。したがって libc は
**オブジェクトを並べるだけ** で使える。アーカイブ (`.a`) の形式と `ar` は
Stage 13 の課題で，ここでは要らない。

```
pp(stddef.h string.h string.c) | cc > string.o
pp(... prog.c)                 | cc > prog.o
ld prog.o string.o             > prog.bin
```

必要なオブジェクトだけを並べる形なので，使わない関数は最初からリンクされ
ない。アーカイブの「必要なメンバだけ取り出す」働きを，人が並べることで
代用している。

### 2.3 純度ポリシー

これまでどおり，ホストの `as` / `ld` / libc は使わない。`lib/` は自作の
C で書き，自作の cc でコンパイルし，自作の ld でリンクする。

## 3. 第 1 部の設計: 土台と純粋な関数

### 3.1 `stddef.h`

```c
typedef unsigned size_t;
typedef int ptrdiff_t;
#define NULL 0
#define offsetof(t, m) ((size_t)&(((t *)0)->m))
```

`size_t` を `unsigned` にするのは，この処理系のポインタが 32 ビットで
`unsigned` も 32 ビットだからである。`offsetof` は「0 番地に置いた構造体の
メンバのアドレス」という慣用的な方法で書ける。これが動くのは Stage 10 第 3 部の
3 でメンバ参照がアドレス計算に落ちるようになったためである。

なお，この定義はメンバ m が配列のとき `&` を配列に適用する。着手時の
処理系はこれを一律にエラーとしていたため，Stage 10 に補遺 2
([stage010-c89.md](stage010-c89.md) 20 章 / cc10l) を追加してから進めた。

`NULL` を `((void *)0)` ではなく `0` にしているのは，`void *` との比較や
代入で余計な型検査に引っかからないようにするためである。

### 3.2 `string.h` の実装方針

| 関数 | 方針 |
|---|---|
| `memcpy` | 前から 1 バイトずつ。領域が重なる場合の動作は未定義 (C89 どおり) |
| `memmove` | 重なりを見て前から / 後ろからを選ぶ |
| `memset` | 前から 1 バイトずつ |
| `memcmp` | `unsigned char` として比較する |
| `strlen` | NUL まで走る |
| `strcpy` / `strncpy` | `strncpy` は n に満たない分を NUL で埋める (C89 どおり) |
| `strcmp` / `strncmp` | `unsigned char` として比較する |
| `strchr` / `strrchr` | 終端の NUL も探索対象に含む (C89 どおり) |
| `strcat` / `strncat` | 末尾を探してから複写する |
| `strstr` | 素朴な二重走査 |
| `strspn` / `strcspn` / `strpbrk` | 文字集合を 256 バイトの表に展開する |

**比較を `unsigned char` で行う** のは C89 の要求である。この処理系の
素の `char` は符号なしなので実害は出ないが，仕様どおりに書いておく。
`char` の符号は処理系定義で，移す先が変われば結果が変わる。

速度のための語単位の複写は入れない。整列していない領域の扱いが増え，
得られるものに対して複雑すぎる。必要になった時点で `memcpy` だけ差し替える。

### 3.3 `ctype.h` の実装方針

C89 の `is*` は **`int` を取り，`unsigned char` の値か `EOF` でなければ
未定義** である。表を引く実装が普通だが，ここでは範囲比較で書く。

- 表 (256 バイト) を持つと，使わなくても `.bss` か `.text` を消費する
- 範囲比較なら分岐数個で済み，どの関数も独立にリンクできる

`EOF` (-1) を渡しても誤動作しないよう，範囲比較では必ず下限も検査する。

ロケールは持たないので，`isalpha` は ASCII の英字だけを真とする。

### 3.4 なぜ `restrict` も `const` も付けないか

C89 に `restrict` は無い (C99)。`const` は Stage 10 第 2 部の 1 で
**構文としては受けるが意味論は持たない**。宣言に付けても検査されないので，
付けると「検査されている」という誤解を生む。付けない。

## 5. 検証計画 (tests/stage011)

テストの素材は Stage 10 と同じく用途で分ける (`src/` と `expected/`)。

1. **ビルド再現**: `string.o` / `ctype.o` の SHA-256 が各 `.md` 記載値と一致
2. **値の照合**: 各関数を境界込みで呼び，結果を出力して照合する。
   とくに次を落とさない。
   - `memmove` の重なり (前へ・後ろへ・完全一致)
   - `strncpy` の詰め物 (n に満たないとき NUL で埋まること)
   - `strchr(s, 0)` が終端を指すこと
   - `memcmp` / `strcmp` が `unsigned char` として比較すること
     (0x80 以上を含む文字列で符号付き比較と結果が変わる)
   - `is*` に `EOF` (-1) を渡しても偽を返すこと
3. **リンクの単位**: 使わない翻訳単位を並べなくてもリンクが通ること
   (`string.o` だけで済むプログラムに `ctype.o` を渡さない)
4. **自己適用**: libc を使って書いた小さなプログラムが動くこと

`0` 除算のような未定義動作の検査は行わない。

## 6. Stage 12 への接続

第 3 部まで終えると，OS を要さない範囲の標準ライブラリが揃う。
残るのは `stdio.h` と，その下の syscall である。Stage 12 で
[roadmap.md](roadmap.md) 2.2 の案 X (Linux ユーザランド) を決め，
`open` / `read` / `write` / `close` / `brk` を獲得する。

そのとき **`malloc` の下回りが差し替わる** (第 2 部で固定の領域を使って
おき，Stage 12 で `brk` へ繋ぎ替える)。この境界を第 2 部の設計で意識しておく。
