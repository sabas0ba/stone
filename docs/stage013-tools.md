# Stage 13: ビルド道具立て 設計文書

## 1. 目的と位置づけ

### 1.1 目的

Stage 12 で「ファイルを開き，読み書きし，引数を受け取り，終了コードを
返す」コマンドが OS の上で書けるようになった
([stage012-os.md](stage012-os.md) 9 章)。しかしコマンドを **起動する**
手段はまだ無い。起動できるのは sfs 内の固定名 `boot` に書いた 1 本だけで，
複数のコマンドを続けて走らせるにはホスト側で QEMU を起動し直すしかない。

Stage 13 の目的は **ゲスト内で開発が完結する道具立てを揃える** ことである。

- プログラムからのプログラム起動 (spawn)。シェルとビルド駆動の前提
- シェル相当。コマンド行の解釈と入出力のつなぎ替え (リダイレクト)
- テキストエディタ。ゲスト内でソースを直す手段
- cc / ld / pp の OS 側への移住。ホスト側の sh スクリプトなしで
  チェーン全体を再ビルドできるようにする

[roadmap.md](roadmap.md) Phase B の最終段である。

### 1.2 非目標

- マルチタスク・並行実行。プロセスは引き続き一度に 1 つで，起動は
  「子の終わりを待つ」逐次実行に限る (パイプは作らない。中間結果は
  ファイルで受け渡す)
- アドレス変換。子の実行中，親の像は退避領域へ複写して守る (3.2)
- 環境変数・カレントディレクトリ。名前空間はフラットのまま
  ([stage012-os.md](stage012-os.md) 4.2)
- 対話編集 (スクリーンエディタ)。エディタは ed 風の行エディタから始める
- ベアメタル環境と既存 Stage の生成物・テストは一切変えない (凍結。
  [artifacts.md](artifacts.md))

## 3. 第 1 部: spawn とシェル

### 3.1 syscall の増設は前置部を変えずに済ませる (sys_ecall)

Stage 12 の 'E' 前置部は syscall ごとに専用スタブ (sys_read / sys_write /
sys_openat / sys_close / sys_brk) を機械語で持つ
([stage012-os.md](stage012-os.md) 6.3)。この形のまま syscall を足すと，
**足すたびにリンカの新世代が要る**。それは避けたい。

そこでリンカの新世代 ld13 の 'E' 前置部に **汎用スタブを 1 本だけ** 足す。

```
int sys_ecall(int n, int a, int b, int c);   /* a7=n, a0..a2=a,b,c で ecall */
```

以降の syscall の増設は libc の環境部 (C で書ける層) が sys_ecall を包む
だけで済み，前置部 (機械語) は二度と変えなくてよい。既存の専用スタブは
互換のためそのまま残す。

### 3.2 spawn: 逐次実行のプロセス起動

#### 意味

```
int spawn(char *path, char **argv, char *in, char *out);
```

path の ELF 実行形式を起動し，**その終わりを待って** 子の終了コード
(0..255) を返す。失敗は -1 (errno)。fork / exec のような分離はしない。
プロセスは一度に 1 つという Stage 12 の実行モデル (逐次実行) を保ったまま，
「起動して待つ」だけを提供する。

- argv は NULL 終端のポインタ列。NULL なら {path, NULL} 相当
- in / out は標準入出力のつなぎ替え (3.3)。NULL なら親と同じ先を継ぐ
- 子は fd 3 以降をすべて閉じた状態で始まる。親の開いていたファイルと
  fd 表は子の終了後に復元される

#### カーネルの実装 (退避と復帰)

アドレス変換が無いので，子も親と同じ固定位置 (0x8600_0000) へ配置される。
親の像は spawn の間 **退避領域へ複写して守る**。

```
0x8100_0000 .. 0x8370_0000   退避領域 (カーネルとトラップフレームの間)
```

退避するのは (1) トラップフレーム (33 語)，(2) fd 表とつなぎ替えの状態，
(3) ubrk と sp，(4) ユーザ像 [0x8600_0000, ubrk)，(5) フレームスタック
[sp, 0x8700_0000) である。子が exit したら逆順に書き戻し，親の a0 へ
子の終了コードを入れて再開する。入れ子は 8 段まで，退避領域が尽きたら
-ENOMEM。起動するファイルが無ければ何も壊さず -ENOENT を返す
(ELF でなければ -ENOEXEC。この検査は親の像を上書きする前に行う)。

argv の文字列は親の像の中にあるので，**親を退避する前にカーネル側の
buffer へ写す** (子の像を配置した時点で親の memory は読めなくなるため)。

#### syscall 番号は独自の範囲に置く

syscall ABI は RV32 Linux 互換だが ([stage012-os.md](stage012-os.md) 2.1)，
Linux に「起動して待つ」1 本の syscall は無い (clone + execve + wait4 の
合成になる)。Linux の番号に別の意味を与えると互換が壊れるので，
**Linux が使わない番号 500 を SPAWN に割り当てる**。

- Linux の番号 (0..463 付近) は今後も Linux の意味でだけ使う。独自の
  拡張は 500 番台に置き，両者を混ぜない
- 可搬性は libc の層で保つ: `spawn` の API は，実 Linux の上では
  clone / execve / wait4 で実装できる。ユーザプログラムは spawn を
  呼ぶ限り無改変で両方の環境に通じる

### 3.3 標準入出力のつなぎ替え (リダイレクト)

dup2 と fd の継承をカーネルに持ち込む代わりに，**spawn の引数で子の
fd 0 / fd 1 の結び先 (ファイル名) を指定する** 形にする。

- カーネルはプロセスごとに「fd 0 / fd 1 の結び先」を持つ。既定は UART。
  in が与えられれば fd 0 をその sfs ファイルへ (無ければ -ENOENT)，
  out が与えられれば fd 1 をその sfs ファイルへ (無ければ作成，あれば
  切詰め) 結んで子を始める。NULL なら親の結び先と位置を引き継ぐ
- fd 2 は常に UART。診断はリダイレクトに巻き込まれない
- cc / ld / pp は「標準入力を読み標準出力へ書くフィルタ」なので，
  この仕組みだけで第 3 部の移住に足りる

### 3.4 fd 0 の read はブロックする (kernel12 からの変更)

kernel12 の read は UART に用意が無ければその場で 0 (EOF) を返した。
シェルがスクリプトを標準入力から読む形 (QEMU への パイプ) では，これは
「まだ届いていない」と「終わった」を区別できず，成立しない。

kernel13 では fd 0 の read を **最初の 1 バイトが届くまで待ち，届いて
いる分だけ返す** 形に変える。入力の終わりは従来からの約束どおり
**EOT (0x04)** で表す ([dev-notes.md](dev-notes.md) 4 章)。シェルは
EOT を読んだら終了する。fd 0 がファイルへ結ばれている場合は従来どおり
末尾で 0 (EOF) を返す。

ベアメタルの鎖が「getc はブロックし，終端は約束 (EOT / `.`) で表す」で
来たのと同じ形であり，挙動の先例に合わせる変更である。kernel12 とその
テストは凍結されたまま変わらない。

### 3.5 boot 行は引数まで解釈する

sfs 内の固定名 `boot` の 1 行を空白で区切り，argc / argv として起動する
プログラムへ渡す (kernel12 は名前 1 語だけだった)。シェルを介さず
1 本のコマンドを引数付きで走らせる検査がこれで書ける。

### 3.6 シェル (sh)

自作 C (C89 + libc) で書く行指向の最小シェル。

- 1 行読み (fgets)，空白 (SP / TAB) で語に分割。空行は読み飛ばす
- `< name` / `> name` を取り出して spawn の in / out に渡す
- 最初の語をコマンド名 (= sfs 内のファイル名) として spawn する
- 組込みは 2 つ: `exit [n]` (シェルを終える。n 省略時 0)，
  `echo ...` (語を空白 1 つで繋いで出す。分割の検査に使う)
- プロンプト `$ ` を stdout へ出す。子の終了コードが 0 以外なら
  `? N` を 1 行で出す (検査がそのまま照合できる)
- spawn の失敗は `sh: <名前>: errno <E>` を出して次の行へ進む
- fgets が EOF (EOT または結び先ファイルの末尾) を返したら終了コード 0

パイプ・変数・引用符・グロブは作らない。必要になった部で足す。

### 3.7 libc は第 13 世代へ複製する

シェルの入力になる libc は世代ごとに凍結する ([artifacts.md](artifacts.md))。
`stage012/libc` を `stage013/libc` へ全文複製し，環境部 (posix/sys.c) に
spawn の包みを足す。純粋部は触らない。
