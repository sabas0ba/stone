# ld 説明文書

ld は cc が出力した ELF リロケータブルオブジェクトを結合し，ロードアドレス
0x8000_0000 のフラットバイナリを作るリンカである。設計は
[stage008-elf-ld.md](../docs/stage008-elf-ld.md) を参照。

ソース [ld.sc](ld.sc) が正本である。バイナリはビルドで再現される生成物であり，
git 管理しない。

## ビルド

```
sh tools/build.sh stage008
# ... -> occ -> ld0 (ブートストラップ) -> ld.o -> ld.bin
```

SHA-256: 79ac94c7e937458fc75f3d00e859b6b94c566273b4615040403269e73a615d83

- 対象: RV32IM，リトルエンディアン，13964 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 使い方

実行環境は UART のみでファイルを開けないため，オブジェクトを連結して
標準入力から与える。列の終わりは 0x7f 以外の 1 バイトで示す
(ELF の先頭バイトが 0x7f なので，それ以外なら「次は無い」と判る)。

```
{ cat a.o b.o; printf '\0'; } | sh tools/env.sh qemu tmp/build/ld.bin > prog.bin
```

## 出力の配置

| 位置 | 内容 |
|---|---|
| 0 | ランタイム前置部 32 語 (crt0 相当。ld が持つ) |
| 128〜 | 各オブジェクトの `.text` を入力順に連結 |
| 以降 | `.bss` (NOBITS なので出力されない。アドレスのみ割り当てる) |

前置部は `main` を呼び，`getc` (offset 68) / `putc` (96) / `exit` (124) の
実体を提供する。これらは cc からは普通の外部関数に見える。

## プログラム構造

| 関数 | 内容 |
|---|---|
| `rd1` / `rd2` / `rd4` / `shf` | 入力バッファからの読取りとセクションヘッダの参照 |
| `readobjs` | オブジェクト列の読込み (ELF ヘッダから全体長を求めて切り出す) |
| `gfind` / `gadd` / `gfindlit` / `gaddlit` | 大域シンボル表 |
| `layout` | 各オブジェクトの `.text` と `.bss` の最終位置の決定 |
| `collect` | 定義済み大域シンボルの収集 (多重定義の検出) |
| `mksymad` | オブジェクトごとのシンボル番号 → 最終オフセットの対応表 |
| `prologue` / `patchmain` | ランタイム前置部の出力と `main` 呼出しの解決 |
| `copytext` / `applyrel` / `relocate` | `.text` の複写と再配置の適用 |

アドレスは内部ではすべて像の先頭からのオフセットで扱い，0x8000_0000 は
再配置の値を作る瞬間にだけ足す。sc に符号なし整数がなく，0x8000_0000 を
含む値の大小比較が負数として扱われてしまうためである。

## 制限

- 大域シンボル表 (`gnm`) は 16 バイト固定スロットで，名前は登録時に
  **15 バイトへ黙って切り詰められる** (ld13 まで同じ)。定義側だけが
  切り詰められ，参照側の全文比較と一致しなくなるため，16 バイト以上の
  外部名は **翻訳単位を跨ぐ参照だけが未定義シンボル (終了コード 2) になる**
  (同一オブジェクト内の参照は節内オフセットで解決されるため通る)。cc は
  Stage 10 で識別子を 31 バイトへ広げたので，コンパイルは通るのにリンクで
  未定義という原因の遠い失敗になる。C89 が保証する外部識別子 6 文字は
  満たす。Stage 14 の [ld14](../stage014/ld14.md) がスロットを 32 バイトへ
  広げて解消した
