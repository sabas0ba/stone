# cc15af --- C コンパイラ 第 15 世代 その 32

`cc15ae` との差は `funcdef()` の 1 か所 (註を除く)。ソースは `stage015/cc15af.sc`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.10。

## 直したもの: 空の括弧の関数宣言

C89 6.5.4.3 ——

> 関数宣言子の識別子並びが空で，それが関数定義の一部でないときは，
> 仮引数の個数も型も与えない。

`int f();` はプロトタイプではなく，どの個数の実引数でも呼べる。先に
プロトタイプがあれば，後から来た `int f();` と合わせた合成型 (6.1.2.6)
はプロトタイプのままである。

`cc15ae` までは `int f();` を**仮引数 0 個のプロトタイプ**として控えて
いた。実引数のある呼出しは個数の不一致 (5) で拒まれる。

| 書き方 | `cc15ae` | `cc15af` |
|---|---|---|
| `int f(int, int);` `int f();` `f(1, 2)` (再宣言) | **5 で拒む** | 通る |
| `int g();` `g(1, 2, 3)` (宣言だけ。定義は後ろの K&R 形式) | **5 で拒む** | 通る |
| `int h();` `int h() { ... }` `h()` (空の括弧の定義) | 通る | 通る |
| `int k(void);` `k(1)` | 5 で拒む | 5 で拒む (正しい) |

GCC 4.7.4 の `libiberty/regex.c` は再宣言の形である。`<stdlib.h>` の後で

```c
char *malloc ();
char *realloc ();
```

と宣言し直し，`realloc` を 2 引数で呼ぶ。`byte_regex_compile` の中の
最初の `realloc` の呼出しで止まっていた。

## 直し方

`funcdef()` で `()` の直後が `;` なら (定義ではない宣言なら)，**仮引数の
情報 (個数・64 bit / 浮動小数点の位置・可変長か) に触らずに戻る。**

- 先にプロトタイプがあれば，それがそのまま残る (合成型)
- 初めて見る名前なら個数は未知 (-1) のままで，宣言の判らない呼出しと
  同じに扱われる (実引数はそのまま積み，積んだ語数で呼ぶ)

**定義** (`int h() { ... }`) はこれまでどおり仮引数 0 個である。`(void)`
の明示も変えていない。

返却型は宣言のものに置き換わる (`void *malloc(size_t)` の後の
`char *malloc ();` なら `char *`)。どちらもポインタ 1 語なので値の
受け渡しは変わらない。

## どうやって見つけたか

`libiberty/regex` は `pp18` の押し戻しの器で止まっていた (8.10)。`pp19`
で前処理を通すと，その先で `cc15ae` が 5 で拒んだ。

5 を返す箇所は `cc15ae.sc` に 61 あるので，終了コードだけでは場所が
判らない。**調査用に各 `exit(5)` を別々の値へ置き換えた版**を組み
(`tmp/` の中だけ。リポジトリには入れない)，同じ `.i` を通して 3054 行
(非可変長の呼出しの個数の検査) と特定した。

## ビルドチェーンは変わらない

既存のソースは空の括弧で関数を宣言していない。`sh` / `ed` / `mk` を
訳した `.o` は `cc10l` のものと 1 バイトも変わらない。

## 測り方

`tests/stage015/probe/emptydecl.c` を足した。**通るだけでは足りない** ——
宣言が判らない呼出しは実引数をそのまま積むので，積み方を誤れば値が変わる。
3 つの形とも値を出してホストと突き合わせる。

| | `cc15ae` | `cc15af` |
|---|---|---|
| `tools/diff17.sh emptydecl` | **我々だけが拒む (rc=5)** | 値が一致 (`7 123 5`) |

`STONE_DIFF_CC=tmp/build/cc15ae.bin` で直す前を再現できる。
