# cc15m 説明文書

cc15m は C コンパイラの Stage 15 第 6 部の世代である。
[cc15l.sc](cc15l.sc) (容量だけの世代) を出発点に，**tcc の翻訳単位が
使う C の機能で我々の cc に無かったもの**をまとめて入れた。穴は
tcc.c (ONE_SOURCE・前処理後 828 KB) を通しながら 1 つずつ実測した
([stage015-tcc.md](../docs/stage015-tcc.md) 12 章)。

ソース [cc15m.sc](cc15m.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15l(cc15m.sc) -> cc15m0     (1 段目)
# cc15m0(cc15m.sc) -> cc15m     (正本。以降は固定点)
```

SHA-256: c22ff624affa2d5d49b991f2a2bd020db952d63f9c6bce56620fa88c7fd6c301

- 対象: RV32IM，リトルエンディアン
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 入れたもの

**黙って誤る (bad) を 2 つ直した。** どちらも既存のソースでは偶然
表に出ていなかった。

| 穴 | 内容 |
|---|---|
| **ラベルつき文** | `if (c) lab: s;` の `s` が if の外の文になり，条件に関わらず走っていた。C89 6.6.1 では「ラベル + 文」で 1 つの文である。tcc の `parse_define` がこの形を使い，'##' の誤りが常に報告されていた |
| **8 進リテラル** | `0666` を 10 進 666 と読んでいた (`open` の許可) |

言語の追加は次のとおり。

| 群 | 穴 |
|---|---|
| 宣言 | 関数型の typedef (`typedef void *F(void *);`)・無名メンバ (`union { struct { int a, b; }; ... };`)・メンバ宣言子の並び (`int a, b;`)・仮定義の重複と後続の本定義 (C89 6.7.2)・トップレベルの空宣言・`inline` の読み捨て・`__attribute__((...))` の読み捨て |
| 定数式 | `sizeof`・キャスト・`offsetof` の展開 (`(size_t)&(((T *)0)->m)`)・列挙定数の初期化子 |
| 式 | 64 bit の複合代入・浮動小数点の複合代入・ビットフィールドの複合代入・`?:` の枝が 2 語・ポインタ ± 64 bit・シフトの桁数が 64 bit の式・`__FUNCTION__` |
| 文・宣言 | ブロックの遮蔽 (内側で同名を宣言できる)・局所の構造体初期化子・狭い局所への 64 bit 初期化子 |
| 字句 | 空白に `\v` `\f`・64 bit を超える浮動小数点リテラルの整数部 |
| 器 | 文字列リテラル 4 Ki → 32 Ki (tcc の予約語表は連結して約 10 KB) |

## 設計の要点

- **ブロックの遮蔽**は「重複検査を現在のブロックの中だけにする」ことで
  足りる。名前の巻き戻し (`lcnt` の退避) は既にあったので，加えたのは
  ブロック先頭を指す `lblk` と，内側優先の探索 (`lfind` を降順に) だけ
- **無名メンバ**は内側のメンバ表を外側へ複写する (`msplice`)。入れ子の
  無名は内側の `strudef` が先に展開を済ませているので 1 段で足りる
- **大きな浮動小数点リテラル**は，64 bit に収まらない桁を読み捨てて
  桁数だけ数え，10 進指数へ足す。仮数の頭 60 bit 強が残るので double の
  丸めには十分である (tcc は 2^96 を基数変換の重みに使う)
- **定数式の `offsetof`** は `&((T *)0)->m` の形だけを畳む。一般の
  アドレス定数は引き続き扱わない

## 検証

- 固定点: cc15m(cc15m.sc) == cc15m0(cc15m.sc) (B2 == B3)
- 回帰: sh / ed / mk と rt64.c / rtfp.c の `.o` が変わらない
- 台帳: [gap15m](../tests/stage015/probe/gap15m.c) が 33 検査すべて通る
- **tcc**: T1 (この cc が作った tcc) が我々の OS 上で C を翻訳し，
  出力 `.o` がホストの gcc で作った riscv32-tcc の出力と**バイト一致**
  する ([stage015-tcc.md](../docs/stage015-tcc.md) 12.9)
