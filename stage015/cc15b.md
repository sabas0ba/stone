# cc15b 説明文書

cc15b は C コンパイラの Stage 15 第 2 部の世代である。
[cc15a.sc](cc15a.sc) (64 bit の土台) を出発点に，**64 bit の演算**を
入れた。設計は [stage015-tcc.md](../docs/stage015-tcc.md) 6 章。

ソース [cc15b.sc](cc15b.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15a(cc15b.sc) -> cc15b0     (1 段目)
# cc15b0(cc15b.sc) -> cc15b     (正本。以降は固定点)
```

SHA-256: e135720a18b885ba80d252b1409340af925ac042af21170b319be801b7e54927

- 対象: RV32IM，リトルエンディアン，174748 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## この世代で通るようになったもの

[stage015-tcc.md](../docs/stage015-tcc.md) 6.2 の内訳のうち
項目 6 (加減・ビット演算・比較)・7 (シフト)・10 (型変換)。

| 演算 | 組み方 |
|---|---|
| `+` / `-` | 下位語を足し (引き)，桁上げ (借り) を符号なし比較 `sltu` で作って上位語へ運ぶ |
| `&` `\|` `^` | 語ごとに独立なので上下をそのまま行う |
| `==` `!=` | 上下を `xor` して `or` を取り，0 かどうかを見る |
| `<` `>` `<=` `>=` | 上位語で決まればそれ，等しければ下位語を符号なしで比べる |
| `<<` `>>` | 桁数が 32 未満か以上かで結果が変わる。**分岐を作らず**，印から 0 / 全 1 のマスクを作って両方を計算し選ぶ |
| 単項 `-` `~` | `0 - x` と `x ^ -1` を 2 語で行う |
| キャスト | 狭い型 -> 64 bit は符号 (0) で伸ばし，64 bit -> 狭い型は下位語を残す |

**命令種別 (IR の c_*) は 1 つも足していない。** すべて既存の 32 bit の
演算の組合せである。`sltu` (`b_ult`) が桁上げの検出に使えたのが効いた。

## この世代がまだ拒むもの (終了コード 5)

- **64 bit の引数と返却** (6.2 の項目 11)
- 乗算・除算・剰余 (項目 8・9)
- 64 bit とポインタの加減算

拒み方は cc15a と同じ仕組みである。左辺値を値へ変える関数を
`rvany` (64 bit 可) と `rv` (32 bit 専用) に分けてあり，**教えていない
経路は自動的に拒む**。この世代では二項演算子と単項演算子とキャストを
`rvany` へ移した。

## 実装の要点

### シフトの場合分けを分岐なしで行う

桁数が 32 以上かどうかで結果の形が変わるが，**分岐を作るとラベルと
合流が要り，IR が増える**。代わりに「32 以上なら 1」の印を作り，
`neg` で 0 / 全 1 のマスクへ変えて，両方の結果を `and` / `or` で選ぶ。

もう 1 つ注意が要るのは `32 - n` である。`n` が 0 のとき 32 になり，
RV32 のシフト命令は桁数の下位 5 bit しか見ないので 0 桁シフトになって
しまう。そこで `n != 0` の印でその項を消している。

### 踏んだ穴: 文字リテラルが 64 bit に見える

64 bit かどうかの印 (`tvalll`) は数値リテラルの字句解析が立てるが，
**文字リテラルの経路で消していなかった**。そのため `1LL` の直後に
`putc(':')` と書くと，`':'` が 64 bit 定数と見なされ，64 bit の引数と
して拒まれた。症状は「無関係な行が終了コード 5」である。

大域変数に印を持たせるときは**立てる場所と消す場所を一組で考える**
こと。cc15a で `ehi` を `eprim` の入口で消したのと同じ話である。
`lsave` / `lrest` (1 トークンの先読み) でも一緒に退避するようにした。
