# cc15aa --- C コンパイラ 第 15 世代 その 27

`cc15z` との差は 3 か所で，どれも**範囲つき case** (`case lo ... hi:`。
GNU C) のためである。ソースは `stage015/cc15aa.sc`。設計は
[docs/stage018-ext.md](../docs/stage018-ext.md) 11。

**世代の名前が英字を使い切った。** `cc15a` 〜 `cc15z` の次は `cc15aa`
とする。置き場は `stage015/` のままである —— 第 15 世代の系列であって，
Stage 17 が `cc15q` 〜 `cc15v` を，Stage 18 が `cc15w` 以降をここへ
足してきたのと同じ扱いである。

## 1. どう直したか

`case` の値の表 (`swval`) と対に，**上端の表** (`swhi`) を持つ。
普通の `case` では両方に同じ値が入るので，振分けの側は

```
swhi[i] == swval[i]     … 等値で比べる (従来どおり)
それ以外                … lo <= v && v <= hi で比べる
```

と分かれる。`case lo ... hi:` の 3 点は 1 つのトークンとして来る ——
可変長引数の `...` と同じものである。

## 2. 空の範囲

`case 20 ... 19:` は空の範囲で，C は「合致しない」と定める。
`lo <= v && v <= hi` はこの形のまま偽になるので，特別扱いは要らない。

## 3. 比べ方は符号つき

`case` の値は整数定数式で，switch の対象が符号なしのこともある。
我々は符号つきで比べる —— 2^31 を超える値を範囲で書くと合わなくなるが，
**範囲つき case は文字や小さい列挙のために使う形**なので，そこは
実物が要求してから直す。

## 4. 鎖は変わらない

`sh` / `ed` / `mk` の `.o` は `cc10l` のものと一致し，`cc15aa0` と
`cc15aa` もバイト一致する。
