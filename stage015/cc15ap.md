# cc15ap --- C コンパイラ 第 15 世代 その 42

`cc15ao` との差は，整数の左辺に浮動小数点の右辺を複合代入する形 (`i += d`) と，ELF の組立てバッファの大きさである (註を除く)。ソースは `stage015/cc15ap.sc`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.15。

GCC の cc1 が要る MPFR を測って見つけた。測った 1281 単位のうち，`cc15ao` が拒んだのは MPFR の `eint.c` だけである。

## 直したもの 1: 整数の左辺と浮動小数点の右辺の複合代入

`E1 op= E2` は `E1 = E1 op (E2)` と同じで，E1 は 1 回だけ評価する (C89 6.3.16.2)。E1 が整数で E2 が浮動小数点なら，通常の算術変換により演算は double で行い，結果を 0 方向へ切り捨てて E1 の型へ戻す。MPFR の eint.c が `prec += -d;` (prec は long，d は double) と書く。

`cc15ao` までは右辺が浮動小数点だと 5 で拒んでいた。左辺が浮動小数点の複合代入 (`d += i`) は `cc15i` 以降受けている。

| 左辺 | 経路 |
|---|---|
| 32 bit 以下の整数 | 左辺を double へ持ち上げ，`__dadd` などで演算し，`__d2i` / `__d2u` で戻して幅で切る |
| 64 bit の整数 | 同じく持ち上げて演算し，`__d2ll` / `__d2ull` で戻して 2 語書く |
| ビットフィールド | 従来どおり拒む |
| ポインタ | 誤りなので拒む (C89 6.3.16.2 はポインタの左辺に整数の右辺しか許さない) |

対象の演算子は + - * / である。% とシフトとビット演算は浮動小数点を取らないので，右辺が浮動小数点ならもともと誤りである。

**整数へ先に切り捨ててはならない。** `i += 0.5` を 2 回行っても i は変わらず (1.5 は 1 になる)，`i *= 1.5` は 7 を 10 にする (`i * 1` ではない)。probe はこの差を値で見る。

## 直したもの 2: ELF の組立てバッファ —— 黙って壊れた .o を出していた

`.o` 全体を組み立てるバッファ (`eb`) は 8 MiB で，上限の検査が無かった。GCC の `insn-attrtab` を遠距離呼出しで訳すと `.o` は 8.5 MB になる。溢れた分がバッファの直後の書込み位置 (`ep`) を壊し，**節表の位置 (e_shoff) と実際の位置が 21 バイトずれた `.o` を，終了コード 0 で出していた**。

`gcc17.sh objects` の検査 (節表の位置 + 個数 × 大きさ = ファイルの長さ) が拒んだので表に出た。近距離呼出しでは同じ単位が 8 MiB に収まっていた。

32 MiB に広げ，超えれば 6 で止める。`.text` の上限 16 MiB と表の上限 (記号・`.strtab` 2 MiB・再配置 262144 件) の和は 32 MiB に収まる。静的な領域は約 85 MiB になり，QEMU の既定の 128 MiB に収まる。`cc15al` が `ob` (出力 16 MiB) に入れたのと同じ種類の検査である。

## ビルドチェーンは変わらない

`sh` / `ed` / `mk` を訳した `.o` は `cc10l` のものと 1 バイトも変わらない。整数の左辺に浮動小数点の右辺を複合代入する形は，既存のソースに無い (`cc15ao` が拒んでいた)。

## 測り方

`tests/stage015/probe/fpopasn.c` は int / unsigned / short / unsigned char / long long / unsigned long long の左辺に double と float を複合代入する。0 方向への切捨て，式の値 (書いた後の左辺)，左辺の添字と右辺がそれぞれ 1 回だけ評価されることを見る。

| | `cc15ao` | `cc15ap` |
|---|---|---|
| `tools/diff17.sh fpopasn` | **我々だけが拒む** (5) | 値が一致 |
| MPFR の `eint.c` | gap (5) | ok |
| GCC の `insn-attrtab` (遠距離呼出し) | 節表がずれた `.o` (終了コード 0) | readelf が読める `.o` |
