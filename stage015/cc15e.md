# cc15e 説明文書

cc15e は C コンパイラの Stage 15 第 2 部の最後の世代である。
[cc15d.sc](cc15d.sc) を出発点に，**64 bit の除算・剰余**を通した。
設計は [stage015-tcc.md](../docs/stage015-tcc.md) 6.2 の項目 9。

ソース [cc15e.sc](cc15e.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15d(cc15e.sc) -> cc15e0     (1 段目)
# cc15e0(cc15e.sc) -> cc15e     (正本。以降は固定点)
```

SHA-256: 413ec35cd6b744909ac783f1cc40632e1c0a53289bf21464f317dfdf492946ad

- 対象: RV32IM，リトルエンディアン，180108 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 除算は展開せず呼び出す

RV32 に 64 bit の除算命令は無く，シフトと引き算で組む必要がある。
展開すると呼出し 1 つあたりの命令が多くなるので，**実行時支援の関数を
呼ぶ**形にした。実体は [rt64.c](rt64.c) にあり，cc がその名前を知っている。

| 演算 | 呼ぶ関数 |
|---|---|
| 符号なしの `/` | `__udiv64` |
| 符号なしの `%` | `__umod64` |
| 符号つきの `/` | `__div64` |
| 符号つきの `%` | `__mod64` |

引数の渡し方 (下位語・上位語の順に 2 つぶん) と返却の受け取り方は，
cc15c・cc15d で入れた 64 bit の実引数・返却の規約をそのまま使う。
**新しい規約を作っていない。**

名前を libgcc 風の `__divdi3` にしないのは，引数の渡し方が本処理系の
規約 (データスタック経由) であり，同じ名前で別物を指すと紛らわしい
ためである。

## 実行時支援は使うときに初めて登録する

`getc` / `putc` / `exit` は起動時にまとめて登録しているが，同じことを
すると**使わない翻訳単位にも未定義シンボルとして記号表に出てしまう**。
`ld` はそれを解決できず終了コード 2 で落ちる (前置部が定義を持つ
getc などと違い，実行時支援の定義は `rt64.o` にしかない)。

そこで**除算を初めて出すときに登録する**形にした。使わない翻訳単位の
オブジェクトは 1 バイトも変わらない。既存のソースが cc10l と同じ .o に
なる回帰も，これで保たれる。

## 踏んだ穴

- **記号表の鍵は `tname` である。** 名前で関数を引く・登録するときに
  tname を書き換えるので，退避して戻さないと**解析中の識別子の名前が
  失われる**。cc15a の `ehi`，cc15b の `tvalll` と同じ「大域の状態を
  跨いで壊す」型である
- **`rt64.c` はブロックコメントを含むので pp を通す**
  ([dev-notes.md](../docs/dev-notes.md) の既知の落とし穴)。直接 cc へ
  渡して構文エラー (1) になった

## これで第 2 部が終わる

[stage015-tcc.md](../docs/stage015-tcc.md) 6.2 の内訳 12 項目が
一通り埋まった。残る制限:

- 可変長引数の**可変部**に置く 64 bit (逆順に積むので語数がずれると
  並べ替えられない。構造体と同じ制約)
- 64 bit とポインタの加減算
