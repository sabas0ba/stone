# cc15a 説明文書

cc15a は C コンパイラの Stage 15 第 2 部の世代である。
[../stage014/cc14g.sc](../stage014/cc14g.sc) を出発点に，
**64 bit 整数 (`long long`) の土台**を入れた。設計は
[stage015-tcc.md](../docs/stage015-tcc.md) 6 章。

ソース [cc15a.sc](cc15a.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc14g(cc15a.sc) -> cc15a0     (1 段目)
# cc15a0(cc15a.sc) -> cc15a     (正本。以降は固定点)
```

SHA-256: 22d5b856ea094ec6c6af87741cc7532ddd33ac1e8faaa793adde7eb5476d9a18

- 対象: RV32IM，リトルエンディアン，160660 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## この世代で通るもの

`long long` / `unsigned long long` の**値を持ち，代入し，読み出す**まで。

- 型として受ける (それまでは終了コード 2 で拒んでいた)
- 記憶域を 8 バイトで取る (局所・大域・構造体メンバ)
- 64 bit のリテラル (`81985529216486895LL`，`0x123456789abcdefLL`)
- 64 bit どうしの代入と，32 bit からの代入 (符号ありは符号を伸ばし，
  符号なしは 0 を置く)

## この世代が拒むもの (終了コード 5)

**64 bit の演算は，まだ 1 つも実装していない。** 加算・比較・シフト・
乗除算・引数・返却のいずれも拒む。

これは意図した設計である ([stage015-tcc.md](../docs/stage015-tcc.md) 6.1)。
64 bit の値を黙って下位語だけで計算すると，**値が静かに壊れる**。
台帳でいう「通るが誤り」であり，いちばん悪い状態である。実装するまでは
拒むほうが正しい。

拒み方は構造で担保してある。左辺値を値へ変える関数を 2 つに分けた。

| 関数 | 役割 |
|---|---|
| `rvany` | 64 bit を許す。**64 bit を扱えると判っている経路だけ**が呼ぶ (代入の右辺・初期化子) |
| `rv` | 32 bit 専用。64 bit が来たら拒む |

既存の経路はすべて `rv` を呼んでいるので，**教えていない経路は自動的に
拒む**。実装した演算が増えるたびに，その経路を `rvany` へ移していく。

## 実装の要点

- **64 bit は「上位語・下位語の 2 値」として前段で分解する**
  (設計の案 2)。IR・コード生成・レジスタ割付けには手を入れていない
- 式の付随情報に `ehi` (上位語の値番号。0 = 32 bit の式) を 1 本足した。
  `ety` / `elv` / `earr` などと同じ受け渡し方である
- 左辺値のときは `ehi` を使わない。上位語は**アドレス + 4** にある
- cc 自身の `int` は 32 bit なので，リテラルの上位語は `tvalhi` に別途
  持つ。10 進の桁上げは `mulhi10` (16 bit ずつに割った符号なし乗算) で
  求める

### 踏んだ穴 2 つ

1. **`ehi` は大域なので，前の式の値が残る。** 消し忘れると，次の式が
   64 bit に見えて `rv` に拒まれる (症状は無関係な行の型エラー)。
   式は必ず一次式から始まるので `eprim` の入口で消している
2. **構造体メンバの大きさが 4 に丸められていた。** スカラは 1 語に
   収まるという前提の丸めで，64 bit だと**上位語が隣のメンバを壊す**。
   `long long` を丸めから外した
