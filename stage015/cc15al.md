# cc15al --- C コンパイラ 第 15 世代 その 38

`cc15ak` との差は GCC 4.7.4 の gcc/ に残っていた書き方と容量である (註を除く)。ソースは `stage015/cc15al.sc`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.14。

`cc15ak` の時点で gcc/ の 347 単位のうち 318 単位が通り，残りは書き方 (gap) 22 単位・容量 (cap) 5 単位・宣言の不足 (decl) 2 単位だった。`cc15ah` 以降は 1 世代ごとに測り直していたが，残りを 1 世代でまとめて受ける。decl の 2 単位はコンパイラではなく構成の側 (`tools/gcc17.sh`) で直す。

## 直したもの: 書き方

| 書き方 | 止まっていた単位 |
|---|---|
| 静的初期化子のアドレス定数 `&g.m`, `&a[3]`, `&a[1].q[2]` | c-decl, c-common, c-cppbuiltin, c-format, c-pch, coverage, gtype-desc, tree |
| 関数型の仮引数 `int f (int g (int))` | sel-sched, sel-sched-ir, sel-sched-dump |
| 64 bit の定数式 `1LL << 40` | i386, options |
| 関数の中の enum | c-pragma, tree-vect-stmts |
| 関数型の typedef による宣言 `binop_t add2;` | caller-save |
| 初期化子つきの extern `extern int x = 1;` | c-opts |
| 括弧で囲んだ文字列 `("fatal error: ")` (静的初期化子) | diagnostic |
| 配列へのポインタ `int (*p)[4]` | reload1 |
| 大きさを省いた局所配列 `int a[] = { ... };` | toplev |
| 局所の構造体の入れ子初期化 | tree-ssa-ccp |
| ビットフィールドの複合代入 (右辺が 64 bit) | tree-stdarg |

- **アドレス定数** (C89 6.4) は，`&名前` に続く `.メンバ` と `[定数]` のオフセットを畳み込み，再配置の addend に載せる。ビットフィールドのアドレスは取れないので 5 で拒む。
- **関数型の仮引数** は C89 6.7.1 に従い関数へのポインタに読み替える。
- **64 bit の定数式** は片方が 64 bit のとき `cbin64()` が `long long` で畳み込む。符号の有無を追っていないので，`>>`・大小比較・`/`・`%` は両方が負でないときだけ畳み込み，他は 5 で拒む。`/` と `%` は評価器自身が 64 bit の除算を使えないので 32 bit に収まる値に限る。静的初期化子のキャストはこれまで読み飛ばしていたので，`(long long)1 << 50` を 32 bit で畳み込んでいた。整数型へのキャストは評価器へ回す。
- **関数の中の enum** は列挙定数の表をブロックの出入りで戻す (`ecblk` / `ecfn`)。探索は内側 (後から登録した方) から引く。
- **初期化子つきの extern** は C89 6.7.2 で定義になる。
- **局所の初期化子** は 0 で埋めてから `laggr()` が配列と構造体を入れ子で置く。大きさを省いた局所配列は `lasize()` が要素を数えてから型を決める。
- **ビットフィールドの複合代入** は右辺が 64 bit のとき下位語で計算する。結果は幅で切るので上位語は効かない。`/` と `%` は上位語が効くので 5 で拒む。

## 直したもの: 素の int のビットフィールドの符号

C89 6.5.2.1 では，素の `int` のビットフィールドが符号つきかは処理系定義である。`cc15ak` までは一律に符号なしで読み，`int hi : 16` に入れた -5 を 65531 と読んでいた。GCC は符号つきとするので合わせる (`bfget()`)。

| 型 | `cc15ak` | `cc15al` |
|---|---|---|
| `int` / `signed char` / `short` | 符号なし | 符号つき |
| `unsigned` 各種・素の `char` | 符号なし | 符号なし |
| `enum` | 符号なし | 符号なし (GCC と同じく負の列挙定数が無い前提) |

enum の型は int と同じ番号なので，`ptype()` が enum を読んだかを `penum` で伝える。読出し・`++` / `--`・複合代入の 3 経路が同じ `bfget()` を使う。符号つきの `>>=` は算術シフトにする。

## 直したもの: 容量

| | `cc15ak` | `cc15al` | 止まっていた単位 |
|---|---|---|---|
| ソース | 4 MiB | 16 MiB | insn-attrtab (`.i` が 4.66 MB) |
| 引数 | 32 個 | 256 個 | insn-emit |
| goto ラベル | 64 個 | 4096 個 | insn-recog |
| 局所記号 | 8192 個 | 65536 個 | insn-output |
| 大域初期化子の文字列 | 4096 個 | 32768 個 | insn-output |
| 関数本体の文字列の後埋め | 2048 個 | 16384 個 | |
| 文字列リテラルの器 | 64 KiB | 1 MiB | |
| 構造体の複写 | 1024 バイト | 1 MiB | opts |

構造体の複写は 1024 バイトまで語ごとの命令を並べていた。これを越える大きさは IR のループ (隠しスロットに数を置く) で語を写し，末尾の半語と 1 バイトを続けて写す。

## ビルドチェーンは変わらない

既存のソースは上の書き方を使わず，素の int のビットフィールドに負の値を入れない。`sh` / `ed` / `mk` を訳した `.o` は `cc10l` のものと 1 バイトも変わらない。
