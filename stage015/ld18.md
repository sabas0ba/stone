# ld18 --- リンカ (cc1 を組む世代)

GCC 4.7.4 の cc1 を組むためのリンカ。ソースは `stage015/ld18.sc`，駆動は `tools/ld18.sh`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.15。

## ld17 で組めない理由

cc1 は gcc/ の 347 単位に libiberty・libcpp・libdecnumber・zlib などを足したもので，cc15am が訳した `.o` は合わせて 200 MB を超える。ld17 は tcc (1 オブジェクト) を組む大きさで作ってある。

| | ld17 | ld18 |
|---|---|---|
| 入力 | 標準入力 (UART)・8 MiB | RAM 上の 384 MiB |
| 出力 | 標準出力 (UART)・8 MiB | RAM 上の 384 MiB 弱 |
| オブジェクト | 64 個 | 8192 個 |
| 大域記号 | 8192 個・線形探索・名前 63 字で切る | 262144 個・ハッシュ・名前の長さに上限なし |
| ライブラリ | なし (渡したものはすべて組む) | 未定義の名前を定義する部品だけを取り込む |
| main の呼出し | jal (前後 1 MiB) | 前置部の末尾の踏み台から lui + jalr |
| データスタック | 256 KiB 固定 | 入力の頭で指定 (`ld18.sh -s`) |
| 出力形式 | 'F' / 'K' / 'E' | 'E' だけ |

ld17 は変えない。ビルドチェーンの OS 用プログラムは従来どおり ld17 で組む。

## 入出力は RAM を介する

200 MB を超える入出力を UART で 1 バイトずつ通すと時間がかかる。また出力は，ホスト側が詰まると QEMU が途中を捨てる (`tools/run-qemu.sh` で対処した)。ld18 は QEMU の RAM をホストのファイルで裏づけ (`STONE_QEMU_RAMFILE`)，決まった番地で受け渡す。

| 番地 | 中身 |
|---|---|
| 0x9000_0000 | 入力。`'LDI1'`・全体の長さ・形式 (`'E'`)・データスタックの大きさ，続けて記録の列 |
| 0xa800_0000 | 出力の頭。`'LD18'`・イメージの長さ |
| 0xa800_1000 | 出力イメージ |

記録は「長さ (4 バイト)・印 (4 バイト)・オブジェクト」で，オブジェクトは 4 の倍数へ詰める。印の bit 0 が 1 のものはライブラリの部品である。標準出力 (UART) には診断と経過の 1 行だけを書く。

`tools/ld18.sh` が入力を詰めて 1 GiB の疎な RAM ファイル (`tmp/ld18/ram`) へ書き，ld18 を走らせ，出力の頭を見てイメージを取り出す。

```
sh tools/ld18.sh [-s データスタック] -o 出力 <オブジェクト...> -L <ライブラリの部品...> -N <オブジェクト...>
```

## ライブラリの部品

`-L` の後ろのオブジェクトは，組むと決まったものが参照する名前を定義するときだけ組む (書庫と同じ意味)。部品を取り込むとその参照がまた部品を呼ぶので，取り込むものが無くなるまで繰り返す。

**参照に数えるのは再配置が使う名前だけである。** cc は宣言しただけの関数も記号表に未定義の記号として出す。これを参照に数えると，使わない関数のために部品を引き込み，その部品の参照でさらに引き込む。

## main の呼出し

'E' の前置部は ld17 と同じ語の並びで，main を呼ぶ語 (`ehsz + 32`) だけが違う。ld17 はそこに main への `jal` を埋める。ld18 は前置部の末尾に踏み台を置き，そこへ `jal` する。

```
lui  x31, %hi(main)
jalr x0, %lo(main)(x31)
```

踏み台は ra を変えないので，main は前置部の続き (exit) へ戻る。x31 は cc15am の遠距離呼出しと同じく，生成コードが値を置かないレジスタである。

## 置く順

オブジェクトは入力の順に置く。前置部の syscall スタブ (`getc` / `sys_read` …) は `jal` で呼ばれるので，それを呼ぶ libc の部品は前置部から 1 MiB 以内に要る。libc と実行時ルーチンを先に並べる。遠距離呼出しで訳した単位 (cc15am の `#pragma stone far_call`) はどこに置いてもよい。

届かない `jal` は最初の 1 つで止めず，64 件まで名前を並べてから 4 で止まる。遠距離呼出しで訳していない単位が 1 回で判る。

## 終了コード

| 値 | 意味 |
|---|---|
| 1 | cc の `.o` でない入力・未知の再配置 |
| 2 | 未定義の名前 (全部並べる) |
| 3 | 多重定義 |
| 4 | jal が届かない |
| 5 | main が無い |
| 6 | 容量 |
| 7 | 入力の頭が違う |

## 測り方

libc25 の 11 部品と実行時ルーチン (rt64 / rtfp) をライブラリとして渡し，遠距離呼出しで訳した小さなプログラムを組んで kernel27 の上で走らせた。引数・malloc・printf・ファイルの書出し・終了コードが期待どおりになり，組んだのは 12 部品のうち 7 つだった。
