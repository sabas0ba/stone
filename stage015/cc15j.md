# cc15j 説明文書

cc15j は C コンパイラの Stage 15 第 3 部の最後の世代である。
[cc15i.sc](cc15i.sc) を出発点に，**浮動小数点の仮引数と実引数**を
入れた。これで第 3 部 (浮動小数点) の cc 側が一通り揃った。

ソース [cc15j.sc](cc15j.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15i(cc15j.sc) -> cc15j0     (1 段目)
# cc15j0(cc15j.sc) -> cc15j     (正本。以降は固定点)
```

SHA-256: 77d0c579604e6198611bc11b31199dbdaba0268e444a33d00ff4938b72e3c66d

- 対象: RV32IM，リトルエンディアン
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 形

記号表の仮引数ビット表を 2 本足した (`gdbm` = double の語位置，
`gflm` = float の語位置。64 bit 整数の `gllm` と同じ形)。呼出しの際に
宣言と突き合わせ，C の変換を行う。

| 実引数 → 仮引数 | 変換 |
|---|---|
| int / long long / float → double | 持ち上げ (`__i2d` など) |
| int / double → float | double を経由して丸める |
| double / float → int, long long | 切捨て (`__d2i` / `__d2ll`) |

宣言が判らないとき (前方参照・関数ポインタ) と可変長引数の可変部は
従来どおり触らない。プロトタイプと定義の食い違いは拒む。

## 直した穴: double を返す呼出しの返却

**cc15h / cc15i に「通るが誤り」が潜在していた。** 出力段の 2 語返却の
判定が `isll` のままで，double を返す実行時支援の呼出し (型変換
`__i2d` など) が**構造体の返却**として扱われていた。構造体の複写は
`tsize` (= 8) を語数として数えるので，データスタックの位置が呼出しの
たびに 24 バイトずれる。

- cc15h / cc15i の台帳の形 (main の浅いフレームでの変換) では**偶然
  露呈しなかった**。仮引数の浮動小数点を入れた検査 (fparg) が関数の
  中の変換で最初に踏み，返却値のコピーが MMIO 領域まで暴走した
- 直しは判定を `is2w` にすること 1 箇所である

台帳の考え方 (「通るが誤り」がいちばん悪い) に照らすと，cc15h / cc15i
は誤りを持ったまま凍結されたことになる。**世代は凍結し，直しは次の
世代で行う**という鎖の作法どおり，ここで直した。当該世代の台帳の
項目そのものは正しい (あの形では誤りが出ない) が，補遺として
それぞれの .md からもこの節を参照する。
