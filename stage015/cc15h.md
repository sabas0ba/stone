# cc15h 説明文書

cc15h は C コンパイラの Stage 15 第 3 部の 3 番目の世代である。
[cc15g.sc](cc15g.sc) を出発点に，**型 `float` / `double`** を入れた。
リテラル・記憶域・代入・型変換・返却まで。四則と比較はまだ無い
(次の世代 cc15i)。設計は
[stage015-tcc.md](../docs/stage015-tcc.md) 10 章。

ソース [cc15h.sc](cc15h.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15g(cc15h.sc) -> cc15h0     (1 段目)
# cc15h0(cc15h.sc) -> cc15h     (正本。以降は固定点)
```

SHA-256: 012a9ed34ae19510eee3816f878bd816cd9de9088f16df5114340bf1d819dc70

- 対象: RV32IM，リトルエンディアン
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 形

- `double` は 64 bit の bit の並いとして `long long` と同じ経路 (2 語，
  `ehi`) で運ぶ。`float` は 32 bit の並びとして int と同じ経路で運ぶ。
  記憶域・引数・返却の語数は新しい述語 `is2w` (2 語の型か) で揃え，
  **演算の分岐には使わない** (整数は `isll`，浮動小数点は `isfp`)
- 型変換は実行時支援 ([rtfp.c](rtfp.c)) の呼出しに落とす (`cvtto`)。
  int / unsigned / long long ↔ double，float ↔ double，浮動小数点 ->
  整数の切捨て。**IR に命令種別を足していない**
- 単項マイナスだけは呼出しにしない。IEEE 754 の否定は符号 bit の反転
  そのものなので，xor 1 命令で足りる

## リテラルは コンパイル時に変換する

`1.5` や `1e300` は**コンパイラ自身が** binary64 の bit の並びへ変換
する。実行時支援と同じソフト浮動小数点 (正規化・乗算・除算・binary32
への丸め) をコンパイラに埋め込んだ。10 の冪は正しく丸めた表 (`p10tab`,
309 件) で持ち，仮数に掛けるか割るかの 1 回だけ丸めが入る。

- 変換の誤差は最大 1.5 ulp 程度。**ホストの strtod (0.5 ulp) と末尾
  bit が違いうる**。tcc とホストの出力を突き合わせる段 (第 6 部) で
  効いてくるかもしれない。既知の妥協として記録する
- 埋め込んだ関数で 64 bit の `/` `%` を使ってはならない (cc の実行形式
  は rt64.o をリンクしない)。除算は引き算とシフトで組んである

## まだ無いもの (拒む)

| 何 | 出方 |
|---|---|
| 四則と比較 | 終了コード 5 (台帳 fparith)。**黙って整数演算で bit を壊さない**ことが要点 |
| 条件 (`if (d)`) | 5。-0.0 が偽にならないといけないので or では書けない |
| 仮引数の浮動小数点 | 5。実引数の変換規則が要る (記号表が型を持たない) |
| 複合代入・++/-- | 5 |
| f 接尾辞つきを double の初期化子へ | 5 |

## 見つけた罠

- **トークン番号の衝突。** `k_float = 92` としたら `k_register` が既に
  92 だった。`double` が記憶域クラスに見えて読み捨てられ，ただの
  構文エラーになる。番号は 94/95 へ
- **再配置の表が足りない** (cc15g の説明文書)

## 検証

- 固定点: cc15h(cc15h.sc) == cc15h0(cc15h.sc) (B2 == B3)
- 回帰: sh / ed / mk と rt64.c / rtfp.c が同じ `.o` になる (浮動小数点を
  使わないソースの生成コードは 1 バイトも変わらない)
- 台帳: fpstore (リテラル・記憶域・変換の 14 項目が期待の bit の並びと
  一致)。fparith は gap 5

## 補遺 (cc15j での訂正)

本世代には「double を返す実行時支援の呼出しの返却が，構造体の返却として
扱われてデータスタックの位置をずらす」誤りが潜在していた。本世代の
台帳の形では露呈しないが，関数の中で型変換を行うと壊れる。
[cc15j.md](cc15j.md) の「直した穴」を見よ。
