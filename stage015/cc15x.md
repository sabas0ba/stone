# cc15x --- C コンパイラ 第 15 世代 その 24

`cc15w` との差は単項式の `( 型 )` の枝の 1 か所 (註を除く)。ソースは
`stage015/cc15x.sc`。経緯は
[docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.3 の 9。

## 直したもの: cast の型名の中の関数ポインタ

C89 6.5.5 ——

> 型名とは、識別子を宣言しない宣言指定子の並びと、それに続く省略可能な
> 抽象宣言子である。

`cc15w` で通した仮引数並びの抽象宣言子と**同じ宣言子**だが、**通る道が
別**である。

| 場所 | 読むところ | `cc15w` | `cc15x` |
|---|---|---|---|
| 仮引数並び | `pparam` | 通る | 通る |
| cast の型名 | 単項式の `( 型 )` | **1 で拒む** | 通る |

`cc15w` は前者だけを直し、後者を見ていなかった。**`cc15q` が初期化子の
側だけを直して式の側 (`sizeof` と単項 `&`) を見落とし、`cc15r` で揃えた
のと同じ形の見落としである** ([cc15r.md](cc15r.md))。1 か所で起きるものは
他でも起きる。

## 表に出た形

GCC 4.7.4 の `libcpp/symtab.c` 65 行 ——

```c
  _obstack_begin (&table->stack, 0, 0,
		  (void *(*) (long)) xmalloc,
		  (void (*) (void *)) free);
```

`obstack` は確保子を `void *(*)(long)` として持つが、実際に渡すのは
`xmalloc` (`void *(size_t)`) なので、上流は cast で型を合わせる。
`libcpp/symtab` / `libcpp/init` / `libiberty/obstack` の **3 単位**が
ここで止まっていた。

**この壁は `cc15w` で 4 を通すまで見えていなかった。** その前は同じ
3 単位が仮引数並びの側 (`obstack.h` 193 行) で止まっていた。
**1 つ通すと次が見える。**

## 直し方

`pstars(ptype())` の直後に、仮引数並びと同じ宣言子を読む。

```c
      if (isfnp()) {
        t = fnpdec1(t, 1);
        if (fpnam[0] != 0) exit(1);
      }
```

**名前が書いてあれば拒む。** 型名は識別子を宣言しないので、
`(void *(*f) (long)) x` は型名ではない。`fnpdec1` は名前を受け付ける
ので、受けた後に空であることを見る。

型は `65536 | ftype(b)` —— 関数へのポインタになる。ポインタなので
`narrow()` は素通しになり、**出るコードは今までのポインタ間の cast と
変わらない**。

## 限界

`cc15w` と同じ範囲である。`( * ) ( 仮引数 )` だけを受け、
`(int (*)) x` や `(int (*)[4]) x` は拒むままにした。

`sizeof (void *(*)(long))` も読めない。**これは別の枝** (`esizeof`) で、
GCC 4.7.4 の libiberty / libcpp の閉包に現れないので足していない。
会っていない形を想像で足すと、根拠の無い実装が残る。

## 鎖は変わらない

既存のソースは関数ポインタ型への cast を使っていない。`sh` / `ed` /
`mk` を訳した `.o` は `cc10l` のものと 1 バイトも変わらず、`cc15x0` と
`cc15x` もバイト一致する (`tests/stage015/test.sh` が両方を見る)。

## 測り方

- 台帳 `tests/stage015/ledger.txt` に `fnpcast` を `ok y\n` で足した。
  **読めるだけでは足りない**ので、cast した関数ポインタを**実際に呼んで
  値を見る** —— `symtab.c` 65 行と同じ形 (引数の位置で cast し、受けた側が
  中で呼ぶ) を通し、**確保子を替えれば答も変わる**ことまで見る。cast が
  呼び先を決めていなければここで食い違う。変数へ入れてから呼ぶ道と、
  cast を直に呼ぶ道も通す
- `tools/diff17.sh` がホストの `gcc` と突き合わせる。ホストも
  `-std=c89 -pedantic-errors` で通し、同じ `y` を出す
