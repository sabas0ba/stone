# cc15x --- C コンパイラ 第 15 世代 その 24

`cc15w` との差は 4 か所で，どれも同じ 1 つの機能 ——
**指示つき初期化子** (C99 6.7.8) である。ソースは `stage015/cc15x.sc`。
設計は [docs/stage018-ext.md](../docs/stage018-ext.md) 3.5。

```c
struct S s = { .b = 2, .a = 1 };
int a[5]   = { [4] = 5, [1] = 2 };
```

## 1. どこを直したか

初期化子を読む道は 4 本ある。**4 本とも直さないと，同じ書き方が
場所によって通ったり通らなかったりする。**

| | 場所 | 何を受けるか |
|---|---|---|
| `ginit` | 大域の配列 (最外) | `[k] = v` |
| `ginit1` | 大域の入れ子 (構造体・配列) | `.name = v` / `[k] = v` |
| `linit` の構造体 | 局所の構造体 | `.name = v` |
| `linit` の配列 | 局所の配列 | `[k] = v` |

**大域と局所で仕組みが違う。** 大域は `.text` へバイトを順に書くので
「書く位置を移す」ことになり，局所は先に全体を 0 で埋めてから代入を
出すので「代入先を選ぶ」だけで済む。

## 2. 触れなかった場所は 0 である

指示子は書く位置を跳ばす。**跳んだ手前が埋まらないまま残ると
「動くが違う」になる**ので，跳ぶたびに埋める。

- 前へ跳ぶ (`hw` より先) … 隙間を 0 で埋めてから移る
- 後ろへ戻る … **0 で埋めてはいけない。** そこには既に値がある
- 読み終えたら，書いた最後尾 (`hw`) から宣言した幅まで 0 で埋める

**2 つ目を最初は数え落とした。** 戻るときも詰める道を通していたので，
`{ .b = 2, .a = 1, .c = 3 }` の `b` が 0 に戻り，和が 6 でなく 4 に
なった。プローブ (`tests/stage015/probe/desig.c`) が値の食い違いとして
出した。

## 3. 受けないもの

**連ねた指示子** (`.a.b = v` / `[k].f = v` / `[i][j] = v`) は
`exit(5)` で拒む。黙って別の場所を埋めるより拒むほうがよい。実装は
「指示子の並びを辿って位置と型を出す」形になるので，要ることが
判ってから足す。

配列の要素数を指示子から決める形 (`int a[] = { [3] = 1 }`) は，
大域では `hw` がそのまま総量になるので通る。局所は元から要素数を
省略できない。

## 4. 鎖は変わらない

既存のソースはこの形を使っていない。指示子が無ければ通る道も出る
バイト列も従来どおりで，`sh` / `ed` / `mk` の `.o` は `cc10l` のものと
一致する。`cc15x0` と `cc15x` もバイト一致する。

```
sh tools/build.sh stage015

# cc15x0(cc15x.sc) -> cc15x     (正本。以降は固定点)
```
