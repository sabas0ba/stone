# cc15ad --- C コンパイラ 第 15 世代 その 30

`cc15ac` との差は 5 か所 (註を除く)。ソースは `stage015/cc15ad.sc`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.3。

**GCC 4.7.4 を測って残っていた C89 適合の不足を、これですべて解消した。**
`gap` の 5 単位がちょうどこの 5 つで、1 つずつ 1 単位の翻訳を妨げていた。

## 直したもの

| | 形 | `cc15ac` | `cc15ad` | 妨げていた単位 |
|---|---|---|---|---|
| 1 | 複文の中の `struct Qdmy;` | **1 で拒む** | 通る | `concat` |
| 2 | ビットフィールドへの `++` / `--` | **5 で拒む** | 通る | `fibheap` |
| 3 | `int (f) (int x)` | **1 で拒む** | 通る | `hashtab` |
| 5 | block scope の `typedef` | **1 で拒む** | 通る | `sort` |
| 6 | block scope の `extern` | **1 で拒む** | 通る | `xmalloc` |

(4 と 7 は `cc15w` / `cc15ac` で通した。番号は 8.3 の表のものである)

### 1. 複文の中のタグだけの宣言

```c
{ struct Qdmy; ... }
```

`ansidecl.h` の `VA_OPEN` が
`{ va_list ap; va_start(ap, v); { struct Qdmy` と展開する。可変長引数を
使う単位すべてがこの形を通る。

**大域では `dcont()` が同じ形を既に受けていた。** 宣言子が無い宣言は
型を登録するだけで変数を作らない、という 1 行である。複文の側
(`plocal()`) だけが持っていなかった。

### 2. ビットフィールドへの `++` / `--`

**これは値の問題である。** 語ごと動かすと隣のフィールドを壊すので、
読み・修正・書きが要る。

**代入 (`assign()` の `bw` の分岐) は既にそれを持っていた。** `incdec()`
だけが持たず、`if (ebfw) exit(5);` で拒んでいた。同じ処理を `incdec()` へ
入れた。

幅からはみ出た桁は捨てる —— 3 bit の 7 に 1 を足せば 0 である。

| | `v.a` (3 bit) | 隣 (`b` / `c` / `d`) |
|---|---|---|
| `a = 7; a++` | **0** | 動かない |
| `a = 0; a--` | **7** | 動かない |
| `d = 0; d--` (8 bit) | **255** | 動かない |

### 3. 括弧で囲んだ名前の宣言子

```c
int (f) (int x) { ... }        /* int f (int x) と同じ */
int (v);                       /* int v; と同じ */
```

C89 6.5.4 の宣言子は「( 宣言子 )」を含む。GCC の `hashtab.c` が
マクロとの衝突を避けるためこの形で書く。

**ポインタを含む形 (`int (*f)(int)`) は前から通っていた** —— `isfnp()`
が `(` の次の `*` を見て受けている。括弧の中が名前 1 つだけの場合を
`isparennm()` で見分け、括弧を外して読む。

### 5. block scope の `typedef`

C89 6.5.1 は `typedef` を記憶域クラス指定子として挙げており、置ける
場所を file scope に限っていない。

**`istype()` は `typedef` を見ない** —— 型指定子ではないからである。
複文と関数本体の宣言の並びで、`k_extern` とともに宣言の始まりとして
受けるようにした。

### 6. block scope の `extern`

実体は外にあるので、フレームは取らず大域として登録するだけにする。
**名前の解決は局所を先に見る**ので、局所を作らなければ大域へ届く。

大域の `dcont()` へ渡す方式は採れない —— 名前の次が `(` だと `funcdef()`
へ行き、`lcnt` / `lblk` を 0 に戻して**外側の関数の局所名を失う**。
`plocext()` として読み切る。

## 名前の見える範囲 —— 5 と 6 に共通する話

どちらも「複文を抜けると見えなくなる」名前である。局所名が `lblk` で
やっていることと同じ形にした。

| | 入口で控える | 出口で戻す |
|---|---|---|
| 局所名 | `lblk = lcnt` | `lcnt` |
| typedef 名 | `tdblk = tdcnt` | `tdcnt` |

`tdfind()` は `0..tdcnt-1` しか見ないので、`tdcnt` を戻せば内側の
`typedef` は引けなくなる。重複の検査も `tdfind() >= tdblk` にして、
**外側と同じ名前を内側で宣言してよい**ようにした (局所名の
`lfind() >= lblk` と同じ形である)。関数本体の分は `tdfn` で戻す。

## C89 より緩いところ —— **書き残す**

**block scope の `extern` で宣言した名前は、複文を抜けても見える。**
C89 6.1.2.1 では、その名前が見えるのはその複文の中だけである。

```c
int main(void) {
  { extern int shared; }
  return shared;        /* host: 'shared' undeclared。我々: 通る */
}
```

記号表が 1 つしかないので、大域へ登録した時点で外からも引ける。
**正しいソースを誤って拒むことはない**ので実害は無いが、**誤った
ソースを受けてしまう**方向の逸脱である。

この形は差分試験を書いている最中に出た —— プローブの側が先にホストで
落ちて判った。**外部の基準と比較しないと自分の緩さは見えない。**

## ビルドチェーンは変わらない

既存のソースはどの形も使っていない。`sh` / `ed` / `mk` を訳した `.o` は
`cc10l` のものと 1 バイトも変わらない (`tests/stage015/test.sh` が見る)。

## 測り方

`tests/stage015/probe/c89blk.c` を足した。**通ることだけでは足りない**
ので、5 つとも値を出してホストと突き合わせる。

- ビットフィールドは折り返しと隣の保存を、後置・前置の両方で見る
- 括弧で囲んだ名前は、関数と変数の両方で値を返させる
- block scope の `typedef` は、抜けた後に同じ名前を**変数として**使う
- block scope の `extern` は、別の複文から同じ実体が見えることを見る

`cc15ac` で同じプローブを走らせると「我々だけが拒む」で落ちる
(`STONE_DIFF_CC=tmp/build/cc15ac.bin`)。**直す前を再現できる。**
