# cc15ai --- C コンパイラ 第 15 世代 その 35

`cc15ah` との差は関数へのポインタを通した構造体の返却，括弧で囲んだメンバの宣言子，大域記号表の容量の 3 か所である (註を除く)。ソースは `stage015/cc15ai.sc`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.12。

## 直したもの: 構造体を返す関数を関数へのポインタで呼ぶ

```c
struct two { int lo; int hi; };
struct hooks { struct two (*pair)(int, int); };

t = hp->pair(6, 7);
```

構造体の返却はデータスタックで受け渡す (`cc15ai.sc` の `@section strret`)。
呼ばれた側は語 k-1 から語 0 までを積み，最後に 1 語の返却値を積んで戻る。
呼んだ側は呼出しの直後に語をフレームの一時領域へ引き取り，1 + k 語ぶん
データスタックを戻す。

名前つきの呼出し (`c_call`) は，引き取る語数 k を**呼出し先の記号の型**
(`gty`) から求めている。関数へのポインタを通した呼出し (`c_calli`) には
記号が無いので出力段で k を決められず，`cc15ah` までは `ecalli()` が
5 で拒んでいた。

**GCC の gcc/ はフックの表を関数へのポインタで呼び，構造体を値で返す。**
`targetm` や `lang_hooks` の項目，`double_int` (2 語の構造体) を返す
関数がその例である。

`cc15ai` は返却型の大きさを呼出し命令の側情報 `irsz` に持たせ，出力段は
`c_call` と同じ引取りを行う。呼ばれた側の返し方は変わらない。

| 書き方 | `cc15ah` | `cc15ai` |
|---|---|---|
| `t = f2(6, 7);` (f2 は構造体を返す関数へのポインタ) | **5 で拒む** | 通る |
| `hp->pair(8, 9).hi` | **5 で拒む** | 通る |
| `sum3(h.triple(10))` (返却値をそのまま値渡し) | **5 で拒む** | 通る |

## 直したもの 2: 括弧で囲んだメンバの宣言子

```c
struct target_reload {
  ...
  enum machine_mode (x_regno_save_mode
                     [FIRST_PSEUDO_REGISTER]
                     [MAX_MOVE_MAX / MIN_UNITS_PER_WORD + 1]);
  ...
};
```

GCC の `reload.h` の形である。C89 6.5.4 の宣言子は「( declarator )」を含み，
括弧は意味を変えない。`memb()` は名前の位置に `(` を見て構文エラー (1) に
なっていた。`reload.h` は gcc/ の多くの単位が読むので，31 単位がここで
止まっていた。

括弧の中で名前と配列の次元を読む。次元は括弧の中か外のどちらか一方だけを
受ける。両方に書く形 (`(a[2])[3]`) は内側と外側で次元の順が入れ替わるので
扱わず，1 で拒む。括弧の宣言子にビットフィールドの幅を付ける形も使う例が
無いので拒む。

関数へのポインタのメンバ (`int (*f)(int);`) は従来どおり `fnpdec()` が受ける。

## 直したもの 3: 大域記号表の容量

大域記号表は 8192 個だった。GCC の gcc/ の単位は extern の宣言と，VEC マクロが
展開する static 関数 (`VEC_tree_gc_safe_grow` など) でこれを使い切り，6 で
止まっていた (`gcc/cfg` / `gcc/alias` など。各 `exit(6)` の直前に箇所を出す
調査用の版で `gnew()` と特定した)。

| | `cc15ah` | `cc15ai` |
|---|---|---|
| 大域記号表 | 8192 個 | 32768 個 |
| 探索 (`gfind()`) | 線形 | ハッシュ表 (65536 個の鎖の頭) |
| `.strtab` の器 (`stt`) | 512 KiB (上限の検査なし) | 2 MiB (上限を越えれば 6) |

**線形探索のまま広げると遅くなる。** 識別子 1 個を引くたびに表全体を
なめるので，記号が 1 万個を超える単位では探索が翻訳の大半を占める。
ハッシュは `pp20` のマクロ表と同じ形 (`h = h * 31 + c` を 16 bit に畳む)
にした。同じ名前が複数あるときは最も小さい添字を返し，線形探索と同じ
結果にしている。

`.strtab` の器には上限の検査が無かった。大域記号が 8192 個に収まる
あいだは 512 KiB で足りていたが，32768 個では溢れうる。

## ビルドチェーンは変わらない

既存のソースは構造体を返す関数を関数へのポインタで呼ばない。`sh` / `ed` / `mk` を訳した `.o` は
`cc10l` のものと 1 バイトも変わらない。

## 測り方

`tests/stage015/probe/fpstru.c` を足した。**語数を取り違えればデータスタックが
ずれる。** 1 語・2 語・3 語の構造体を返させ，呼出しの後に積んだ引数と
局所変数が無事であることを値で見る。

| | `cc15ah` | `cc15ai` |
|---|---|---|
| `tools/diff17.sh fpstru` | **我々だけが拒む (rc=5)** | 値が一致 (`5 6 7 4 8 12 9 60 4 77`) |
| `tools/diff17.sh parenmemb` | **我々だけが拒む (rc=1)** | 値が一致 (`60 40 44 56 3 146`) |

`tests/stage015/probe/manyglob.c` は大域記号を 8300 個宣言する。**bare の
リンカ (stage008 の ld) は 1 オブジェクト 8192 記号までなので，リンクして
値を突き合わせることはできない。** `tools/diff17.sh` は理由を出して省略し，
`tests/stage015` が翻訳の通ることを見る (`cc15ah` は 6 で止まる)。

`tests/stage015/probe/parenmemb.c` は括弧の中の 2 次元配列と，括弧の外に
次元を書く形を並べ，前後のメンバの位置と構造体の大きさを値で見る。
**次元を読み違えれば配置が変わる。**
