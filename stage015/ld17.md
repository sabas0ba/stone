# ld17 説明文書

ld17 はリンカの Stage 17 世代である。[ld16.sc](ld16.sc) の複製に
**診断だけを足した**。通る道は 1 ビットも変えていない。

ソース [ld17.sc](ld17.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15p(ld17.sc) -> ld17.o -> ld(ld17.o) -> ld17.bin
```

SHA-256: db91c78e8fe1c4e2961bef904e0a0901edf7991cf04aabf92b4a3292a7c735d3

- 対象: RV32IM，リトルエンディアン
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 直したもの: 落ちた理由を言わせる

`ld16` は未定義シンボルを `exit(2)` で拒む。**どの名前が無いのかは
言わない。** 呼ぶ側 (`cc19`) に出るのは

```
cc: link failed
```

の 1 行だけである。実物 (zlib / bzip2) を我々の器で組む測定
([docs/stage017-gcc.md](../docs/stage017-gcc.md) 5.1) で，これが
そのまま行き止まりになった —— `bzip2` の結合が落ちたとき，判ったのは
「どれかが足りない」までで，原因に近づく手段が無かった。

足したのは 3 つ。

| 終了コード | ld16 | ld17 |
|---|---|---|
| 2 (未定義) | 黙る | `ld: undefined symbol: <名前>` を**全部**並べる |
| 3 (多重定義) | 黙る | `ld: duplicate symbol: <名前>` |
| 5 (main / ktrap が無い) | 黙る | `ld: undefined symbol: main` |

**最初の 1 つで止めない。** 足りないものが 10 個あるとき，1 回の走行で
1 個しか判らないと 10 回組み直すことになる。控えておいて，全部読んでから
並べて出す。同じ名前は 1 度だけ数える —— 1 つの未定義関数が 100 か所から
呼ばれていると，そのままでは同じ行が 100 本出る。

```
$ ld17 < undef.o          # nosuchfunc を 2 回，alsomissing を 1 回呼ぶ
ld: undefined symbol: nosuchfunc
ld: undefined symbol: alsomissing
（終了コード 2）
```

## 診断は標準出力へ出す

前置部が提供するのは `getc` / `putc` / `exit` だけで，`'F'` 形式には
`sys_write` が無い (`ld17.bin` はベアメタルの平たい像である)。だから
**書ける先は標準出力しかない**。

像を書き出すのは `relocate()` の後なので，診断を出す道では像は 1 バイトも
出ていない —— 混ざることはない。呼ぶ側が出力をファイルに向けていれば
(`cc19` はそうする)，**そのファイルの中身が診断そのもの**になる。

```
cc19 -o bzt bz/bzt.c bz/libbz2.a -I bz || cat bzt
```

## 通る道は変わらない

`ld16.o` / `pp16.o` / `cc15t.o` を `ld16` と `ld17` の両方に通し，
出た像が**バイト一致**することを確かめた (`tests/stage015`)。
足したのは落ちる道だけである。
