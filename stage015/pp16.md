# pp16 説明文書

pp16 は C プリプロセッサの Stage 15 第 6 部その 2 の世代である。
[pp15.sc](pp15.sc) (容量だけの世代) を出発点に，**再帰抑止が実引数の
事前展開で失われる不備**を直した。器は pp15 のままである。

ソース [pp16.sc](pp16.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15m(pp16.sc) -> pp16.o -> ld -> pp16.bin
```

SHA-256: 964c57fab24274293180367edb60a851c38c5fd0a2f5e328b6d465387614963d

## 直したもの (黙って誤る = bad)

tcc.h は自己参照マクロを多用する。

```c
#define eh_frame_section  s1->eh_frame_section
...
dwarf_data4(eh_frame_section, 0);
```

pp15 まではこれが `s1->s1->eh_frame_section` に展開されていた
(gcc は `s1->eh_frame_section`)。原因は，実引数の事前展開で
「展開中のマクロなので抑止して素通しした名前」が，置換結果を再走査する
ときにもう一度 domacro を通り，そのときは積みに印 (fmac) が無いので
展開されてしまうことである。

C99 6.10.3.4 は「抑止された名前は**以後どの走査でも**展開しない」と
定める。pp16 は抑止して素通しする識別子に**印 (バイト 1) を前置**して
事前展開の出力 (eb) へ書き，再走査で印つきの識別子に出会ったら展開せず
通す。最終出力へは印を出さないので，前処理結果の見た目は変わらない。

内側の展開へさらに入るときは印も持ち回る (`outer(sec)` のような
入れ子でも抑止が続く)。

## 検証

- 回帰: 既存のソース (libc15・sh) の前処理結果が pp15 と 1 バイトも
  変わらない
- [hyg16](../tests/stage015/probe/hyg16.c): 自己参照マクロを実引数に
  渡した展開が gcc と一致する
- tcc: 前処理結果が変わり，`s1->s1->...` が消える
