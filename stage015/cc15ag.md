# cc15ag --- C コンパイラ 第 15 世代 その 33

`cc15af` との差は `fnpdec1()`・`memb()`・大域宣言の 3 か所 (註を除く)。ソースは `stage015/cc15ag.sc`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.11。

## 直したもの: 関数へのポインタへのポインタ `(**)`

C89 6.5.4.1 の pointer は「`*` type-qualifier-list_opt pointer_opt」で，
括弧の中の `*` は 1 つとは限らない。

```c
void __gmp_get_memory_functions (void *(**) (size_t),
                                 void *(**) (void *, size_t, size_t),
                                 void (**) (void *, size_t));
```

`fnpdec1()` は `(` の直後の `*` を 1 つだけ読み，名前か `)` を期待して
いたので，2 つめの `*` で構文エラー (1) になった。

**GMP の `gmp.h` がこの形を持つ。** GCC の gcc/ の単位は `double-int.h`
から `gmp.h` を読むので，gcc/ を測った最初の回では**ほとんどの単位が
ここで止まっていた** (途中まで測った 242 単位のうち 190 単位が `gap 1`)。

| 書き方 | `cc15af` | `cc15ag` |
|---|---|---|
| `int (*f)(int);` | 通る | 通る |
| `int (**pf)(int);` | **1 で拒む** | 通る |
| `void g(int (**)(int));` (名前を省いた仮引数) | **1 で拒む** | 通る |

## 直したもの 2: ビットフィールドの幅は整数定数式

C89 6.5.2.1 の幅は「整数定数式」である。`memb()` は数のリテラル 1 個だけを
受けていたので，GCC の `real.h` の

```c
unsigned int uexp : EXP_BITS;          /* EXP_BITS は (32 - 6) */
```

で構文エラー (1) になった。`(**)` を通した次に `gcc/attribs` を止めていた。
配列の大きさと同じ `ccond()` で畳み込む。幅 0 (次の記憶単位へ送る) と
上限 (31) の検査は変えていない。

## 直したもの 3: 不完全型の extern 宣言

```c
extern struct alloc_zone rtl_zone;       /* GCC の ggc.h */
```

を，型の大きさが判らないとして 5 で拒んでいた。大きさが要るのは記憶域を
取る定義だけで，extern の宣言は不完全型のままでよい (C89 6.5.2.1 / 6.7.2)。
後で型を完全にして同じ名前を定義すれば，そのときの大きさで記憶域を取る。

**これで `gcc/attribs` が `.o` まで通った** (298,360 バイト)。gcc/ 本体で
最初に通った単位である。1 単位を通すのに 3 つの壁を順に越えた ——
`(**)` (1) → ビットフィールドの幅 (1) → 不完全型の extern (5)。

> **繋ぐ段の課題として残るもの。** 我々の cc は使わない extern も未定義の
> 記号として `.o` に出し，我々の ld はそれを解けずに落ちる。`rtl_zone` は
> どの単位でも定義されないので，cc1 を繋ぐ段で当たる。翻訳 (`.o` まで) の
> 話ではないので，この世代では扱わない。

## 直し方 (`(**)`)

`*` と型修飾子の並びを読み，2 つめ以降の `*` の数だけポインタの段を足す。
符号化は `pstars()` と同じ (1 段ごとに 65536)。

## どうやって見つけたか

`exit(1)` は `cc15af.sc` に 108 ある。`cc15af` と同じく各 `exit(1)` を別々の
値へ置き換えた調査用の版を組み (`tmp/` の中だけ)，`gcc/attribs` の `.i` を
通して `fnpdec1()` の「名前の後の `)`」と特定した。`.i` を宣言の境界で
切り詰める二分探索で `gmp.h` の範囲に絞り，`tools/gcc17.sh where` も同じ
範囲 (`.i` の 17186〜18671 行) を指した。

## ビルドチェーンは変わらない

既存のソースは `(**)` も式の幅も不完全型の extern も書いていない。`sh` / `ed` / `mk` を訳した `.o` は
`cc10l` のものと 1 バイトも変わらない。

## 測り方

`tests/stage015/probe/fnpp.c` を足した。**段を 1 つ数え違えれば，間接参照の
回数がずれて別の番地を呼ぶ。** 名前つき・名前なしの両方を使い，呼んだ結果の
値をホストと突き合わせる。

| | `cc15af` | `cc15ag` |
|---|---|---|
| `tools/diff17.sh fnpp` | **我々だけが拒む (rc=1)** | 値が一致 (`4 20 14 -4`) |
| `tools/diff17.sh bfexpr` | **我々だけが拒む (rc=1)** | 値が一致 (`15 9 67108863 1 0 1`) |

| `tools/diff17.sh extinc` | **我々だけが拒む (rc=5)** | 値が一致 (`6 99 12`) |

`bfexpr` は幅いっぱいの値を書いて読み戻し，さらに溢れさせて隣のフィールドが
無事であることを見る。**幅を読み違えれば詰め方が変わり，隣を壊す。**
