# cc15ak --- C コンパイラ 第 15 世代 その 37

`cc15aj` との差は 64 bit の値を受ける 4 か所 (添字・複合代入・`switch`・`?:`) である (註を除く)。ソースは `stage015/cc15ak.sc`。
経緯は [docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.13。

## 直したもの: 64 bit の値を 32 bit の文脈で使う

GCC の gcc/ は `HOST_WIDE_INT` (`long long`) を添字・複合代入の右辺・`switch` の
制御式・`?:` の片方に使う。`rv()` は「教えていない経路では黙って壊れるより
拒む」ために 64 bit の値を 5 で拒んでいた (docs/stage015-tcc.md 6.1)。
**経路ごとに意味を決めて通す。** 一律に下位語へ切り詰めると，上位語が
結果に効く所で値が変わる。

| 形 | GCC の例 | 扱い |
|---|---|---|
| 添字 | `have_swap[tree_low_cst (...)]` | 下位語だけを使う。32 bit の対象ではアドレスの計算が 2^32 で巡回するので，上位語は結果に効かない |
| 複合代入 `+ - * & \| ^ << >>` (左辺が 32 bit) | `hash += INTVAL (x);` | 右辺を下位語へ切り詰める。結果の下位 32 bit は右辺の下位語だけで決まる |
| 複合代入 `/ %` (左辺が 32 bit) | `xsize /= INTVAL (x1);` | 左辺を広げて 64 bit で割り，下位語を書き戻す。**上位語が商と剰余に効く** |
| `switch` の制御式 | `switch (TREE_INT_CST_LOW (label))` | case の値は 32 bit で読む。上位語が下位語の符号拡張でなければ，どの case にも当たらないので default (無ければ switch の外) へ送る |
| `?:` の then が 1 語・else が 2 語 | `x < 10000 ? x : expected` | then 側の値を else の型へ広げる。符号は then 側の型で決まる |

`?:` の逆向きは，then 側の命令を出し終えてから else の型が判る。then 側の
`jmp` の行き先を後から付け替え，else の後ろに置いた経路で then の値を読み
直して広げる。IR に命令を挿し込まずに済み，順向きの形の出力は変わらない。

**限界。** `switch` の case の値を 32 bit で読むので，`unsigned long long` の
制御式に 2^31 以上の case を書く形は扱えない (値の比較が符号拡張になる)。
then が `float` で else が 64 bit 整数の `?:` は 5 で拒む。64 bit の値を含む
定数式 (`(1LL << 2)` の初期化子。gcc/ の 2 単位) は定数の畳み込みを 64 bit に
する必要があり，この世代では扱わない。

## ビルドチェーンは変わらない

既存のソースはこの 4 つの形を使っていない (使えば 5 で止まっていた)。
`sh` / `ed` / `mk` を訳した `.o` は `cc10l` のものと 1 バイトも変わらない。

## 測り方

`tests/stage015/probe/wide64.c` を足した。**切り詰めてよい所と上位語が効く所の
境目の値を並べる。** `100 / (2^32 + 2)` は 0，`5 + (2^32 + 3)` は 8，
`switch (2^32)` は case 0 に当たらない，`c ? -5 : (long long) b` の上位語は -1。

| | `cc15aj` | `cc15ak` |
|---|---|---|
| `tools/diff17.sh wide64` | 5 で拒む | 値が一致 (`5 5 333 -1 0 8 17 144 10 20 30 40 40 1 3 -1 -5 3 0 30 25`) |

`cc15aj` の拒否は，diff17 では「C89 として誤り」と判定される。ホストを
`-std=c89 -pedantic-errors` で動かすと `long long` そのものを拒むためで，
我々の拒否が正しいことの裏付けにはならない。
