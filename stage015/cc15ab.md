# cc15ab --- C コンパイラ 第 15 世代 その 28

`cc15aa` との差は 5 か所で，**どれも差分試験がコンパイラ側で見つけた
穴**である。ソースは `stage015/cc15ab.sc`。経緯は
[docs/stage018-ext.md](../docs/stage018-ext.md) 12。

## 1. 何を直したか

| | 何が起きていたか | 種別 |
|---|---|---|
| 無名のビットフィールド (`unsigned : 5;` / `unsigned : 0;`) | 名前が無い時点で拒んでいた。C89 6.5.2.1 が定める詰め物の形である | gap |
| 関数ポインタの配列 (`int (*tab[3])(int, int)`) | 宣言子が名前の直後の `[n]` を読まなかった。typedef を挟めば通っていた | gap |
| 逆向きの添字 (`3[p]`) | 左がポインタであることを要求していた。`E1[E2]` は `*(E1 + E2)` で足し算に順序は無い (C89 6.3.2.1) | gap |
| **静的な初期化子のビットフィールド** | メンバごとに記憶単位を書いていたので，2 つめ以降が別の語へ書かれていた。`static struct a g = {1,0,5,200};` が `{1,0,0,0}` になる | **bad** |
| **関数ポインタ越しの 64 bit 返却** | 上位語を引き取らず，データスタックからも捨てていなかった。`d(2.5, 4.0) * 100` が 400 になる (直前の式の上位語が残って混ざる) うえ，スタックが 1 語ずれる | **bad** |

下 2 つは**通ったうえで値が違う**。上 3 つは拒むだけなので gap である。

## 2. 誰が見つけたか

[tests/stage015/probe](../tests/stage015/probe) に足した 4 本 ——
`bitfld` `funcptr` `intconv` `aggr` である。どれもホストの処理系と
同じソースを走らせて出力を突き合わせる形で，**我々が期待値を書いて
いない**。

とくに下 2 つは，我々のソースが使っていない形である ——
ビットフィールドを静的に初期化する場所も，double を返す関数ポインタを
呼ぶ場所も鎖の中に無い。**固定点もバイト一致も捕まえない**誤りで，
cc15u と同じ構図である ([roadmap.md](../docs/roadmap.md) の Stage 15)。

## 3. 受けない形を 1 つ残した

関数ポインタを**返す**関数を直に書く形 (`int (*pick(int))(int, int)`)
は受けない。宣言子の途中で「これは関数定義である」と判る形になり，
宣言の読み方そのものを組み直すことになる。typedef を挟めば書けるので，
実物が要求してから直す。

## 4. 鎖は変わらない

`sh` / `ed` / `mk` の `.o` は `cc10l` のものと一致し，`cc15ab0` と
`cc15ab` もバイト一致する (固定点)。
