# ld16 説明文書

ld16 はリンカの Stage 15 第 6 部の世代である。
[ld15.sc](ld15.sc) を出発点に，**`'K'` 前置部が U モードで浮動小数点を
使えるようにした**。変更は 3 語だけである。

ソース [ld16.sc](ld16.sc) が正本である。

## ビルド

```
sh tools/build.sh stage015
# cc15o(ld16.sc) -> ld16.o -> ld(ld16.o) -> ld16.bin
```

SHA-256: 31808584727c54b19b8b14f7ce019c235ddf48df6858cb43c5c35e92b5b92802

- 対象: RV32IM，リトルエンディアン
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 直したもの

RISC-V の浮動小数点命令は **`mstatus.FS` を立てるまで使えない**
(立てずに `fadd` などを実行すると不正命令になる)。ld15 までの
`'K'` 前置部は `mret` の直前に MPP (0x1800) を落とすだけで，
FS (0x6000) に触れていなかった。

```
  lui  t5, 0x2          ld15: t5 = 0x2000
  addi t5, t5, -2048          t5 = 0x1800
  csrc mstatus, t5            MPP だけ落とす -> FS は Off のまま
```
```
  lui  t5, 6            ld16: t5 = 0x6000
  csrw mstatus, t5            MPP = 0 (U) と FS = 3 (Dirty) を同時に
  nop                         (語数を ld15 と揃える)
```

他のビット (MIE / MPIE / MPRV) はもともと 0 なので，まるごと書いて
困るものは無い。このカーネルは割込みを使わない。

浮動小数点レジスタはトラップフレームに退避しない。カーネルは
ソフト浮動小数点で組んであり `f` レジスタに触れないので，syscall を
跨いでも利用者の値は残る (`spawn` の子は別で，親の `f` は壊れる)。

## なぜ要ったか

我々の cc が出すコードはソフト浮動小数点 (rtfp.o) なので，これまで
`f` レジスタを 1 度も使っていなかった。tcc の RV32 backend は
ハードウェアの浮動小数点を使うので，**tcc が作った実行形式を我々の
OS で走らせた瞬間に表に出た** (docs/stage015-tcc.md 12.24)。

第 5 部で裸で走らせたときは
[head.S](../tests/stage015/tccprobe/head.S) が自分で立てていた。
「OS がいれば OS が立てる」と書いてあったが，その OS 側が無かった。

## 検査

- `'K'` 以外の前置部 (`'F'` / `'E'`) は ld15 と同一である
- kernel16 を ld16 でリンクし，tcc が作った浮動小数点を使う実行形式が
  U モードで走ることを見る (tests/stage015)
