# cc15w --- C コンパイラ 第 15 世代 その 23

`cc15v` との差は 4 か所。**C89 の外側 (C99 と GNU の別綴り) を受ける
第 1 陣**である。ソースは `stage015/cc15w.sc`。設計は
[docs/stage018-ext.md](../docs/stage018-ext.md)。

## 1. 足したもの

| | 中身 | 出どころ |
|---|---|---|
| GNU の別綴り | `__extension__` を落とす。`__inline__` / `__inline` / `__const__` / `__const` / `__volatile__` / `__volatile` / `__signed__` / `__signed` / `__restrict__` / `__restrict` / `restrict` を素の綴りと同じに扱う | GNU C (`restrict` は C99) |
| 文の後ろの宣言 | 複文の中で宣言と文が混ざってよい | C99 6.8.2 |
| `for` の初期化での宣言 | `for (int i = 0; ...)`。名前は `for` を抜けると見えなくなる | C99 6.8.5.3 |

`__attribute__` は `cc15v` までで既に落としている。`inline` (素の綴り)
も既に読み捨てている。

## 2. どう直したか

**別綴りは字句の段で片付ける。** 綴りが違うだけで意味は同じなので，
`streq` の並びに足して同じトークンを返す。`__extension__` は
「この先で拡張を使う。診断を出すな」という印で中身を持たないから，
`__attribute__` と同じ場所で落とす。

`restrict` は C99 の予約語だが，我々は `const` / `volatile` と同じく
**読み飛ばす修飾子**として扱う。最適化の判断に使っていないので，
落としても意味は変わらない。

**宣言と文の環は 2 か所ある。** 複文 (`stmt` の `{`) と，関数本体の
最外である。関数本体は `stmt` を通らず自前で環を回しているので，
片方だけ直すと「関数の途中では書けるが，本体の直下では書けない」と
いう妙な処理系になる。両方を

```c
    while (tok != o_rc) {
      if (istype()) plocal();
      else stmt();
    }
```

にした。関数本体の側は，制御構造の状態 (`brkn` / `conn` / `swn` …) の
初期化を**環より前へ移した** —— 文がいつ来てもよい状態にしてから
入る必要がある。

`for` の初期化での宣言は，複文と同じに `lcnt` / `cloff` / `lblk` を
退避して戻す。`plocal` が末尾の `;` まで食べるので，宣言のときだけ
道を分ける。**戻す場所は 2 つある** (歩進の無い `for` と，ある `for`)。

## 3. 残る穴

**`typedef` 名と同じ名前の局所変数を作ると取り違える。** 宣言か文かの
見分けは `istype()` ただ 1 つで，これは名前が `typedef` 名かどうかしか
見ない。C の構文が元から持つ曖昧さで，我々はまだ解いていない。

先頭にまとめる書き方でも同じ曖昧さはあった (複文の先頭で
`foo = 1;` と書けば同じことが起きる) ので，**新しく生じた穴ではなく，
当たる場所が増えただけ**である。解くには宣言子の先読みが要る。

## 4. 鎖は変わらない

既存のソースはどの形も使っていない。`sh` / `ed` / `mk` を訳した `.o` は
`cc10l` のものと 1 バイトも変わらず (`tests/stage015` の regress)，
`cc15w0` と `cc15w` もバイト一致する。

## 5. 測り方

`tests/stage015/probe/c99decl.c` を `tools/diff17.sh` で測る。**この
プローブは `beyond_c89` に載せてある** —— C89 の外側なので，我々が
拒んだときに `gcc -std=c89 -pedantic-errors` へ訊く裏取りが素通しに
なるからである (同 4 章)。
