# cc15r --- C コンパイラ 第 15 世代 その 18

`cc15q` との差は **1 か所 4 行**。ソースは `stage015/cc15r.sc`。
経緯は [docs/stage017-cc.md](../docs/stage017-cc.md) 31 章。

## 直したもの: 文字列リテラルが配列であることを型として持っていなかった

`estr2()` は `ety = 65536` (`char *`) だけを置き，`earr` / `esz` /
`eaty` を立てていなかった。`sizeofn()` は `if (earr) n = esz;` で配列を
見分けるので，**文字列リテラルは常に「ポインタの大きさ」で数えられて
いた**。

```
sizeof "!<arch>\n"    cc15q 4 / C では 9
sizeof "abc"          cc15q 4 / C では 4   ← 偶然合っているだけ
```

直しは `estr2()` で退化前の配列型を立てるだけである。式の中での退化
(先頭要素へのポインタ) は `ety = 65536` のままなので変わらない。
配列型 `eaty` は単項 `&` が使う (`&"abc"` は `char(*)[4]`)。

```c
n = slen;                  /* next() が sbuf / slen を上書きする前に控える */
...
ety = 65536;               /* 式の中では char * のまま (変えない) */
elv = 0;
earr = 1;                  /* 退化前は配列である */
eaty = atype(0, n + 1);    /* char[n+1] */
esz = n + 1;
```

## これは `cc15q` で直したものと同じ根である

`cc15q` の 2 か所はどちらも「静的な初期化子の中の文字列リテラルが配列と
して扱われていない」だった。あのとき初期化子の側だけを直し，**式の側
(`sizeof` と単項 `&`) を見なかった**。

| | 直した場所 | 見なかった場所 |
|---|---|---|
| `cc15q` その 1 | 関数内 static のポインタ | 構造体の中の char 配列 |
| `cc15q` その 2 | 構造体の中の char 配列 | 多次元 (`char s[3][8]`。まだ `bad`) |
| **`cc15r`** | 初期化子ぜんぶ | **式の中の `sizeof` と `&`** |

`docs/stage017-cc.md` 27.4 に書いた「族を言語の規則ではなく振る舞いで
切った」を **3 度目に踏んだ**。今回は規則の側 ——「文字列リテラルの型は
`char[n+1]` である」(C89 6.1.4) —— から直している。

## 表に出た形

tcc が我々の OS の上で書庫 (`.a`) を読めなかった。`tccelf.c` は

```c
#define ARMAG "!<arch>\n"            /* tcc.h 1544 行 */
file_offset = sizeof ARMAG - 1;      /* tccelf.c 3681 行 */
```

で最初の見出しの位置を求める。8 のはずが 3 になり，見出しでない場所を
読んで `"invalid archive"` と言っていた。`tcc_object_type` の側は
`memcmp(h, ARMAG, 8)` と数を直に書いているので，**「書庫だ」という判定
だけは通る**。それが「書庫と判った上で読めない」という形になっていた。

## 鎖の成果物は変わらない

既存のソースは文字列リテラルの `sizeof` を使っていないので，出るコードは
変わらない。stage017 まで作り直しても `l19_*` / `l20_*` / `cc19` /
`kernel24` はすべて cached である。

**ただし tcc のバイト列は変わる。** `sizeof ARMAG` が 4 から 9 になるので
畳み込まれた定数が変わる (974,204 バイトで大きさは同じ，610,991 バイト目
から中身が違う)。21 章・29 章の突き合わせは「`Makefile` から出た tcc」と
「命令を直に並べた tcc」の間のものなので，両方を組み直せば成り立つ
(再測して確認済み)。参照実装との突き合わせ (roadmap 3 の
T2 == T3 == tccH) は Stage 15 の鎖 (`cc15p`) のもので，そちらは 1 バイトも
動いていない。
