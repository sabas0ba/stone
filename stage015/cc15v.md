# cc15v --- C コンパイラ 第 15 世代 その 22

`cc15u` との差は `ginit1()` の 1 か所 2 行 (註を除く)。ソースは
`stage015/cc15v.sc`。経緯は
[docs/stage017-gcc.md](../docs/stage017-gcc.md) 5.2。

## 直したもの: スカラの初期化子は 1 つだけである

C89 6.5.7 ——

> スカラの初期化子は，単一の式でなければならない。波括弧で囲んでも
> よい。

したがって

```c
static int a[2][2] = { 1, {2,3}, 4 };
```

の `{2,3}` は**制約違反**である。`1` を書いた時点で「いま埋めている
対象」は `a[0][1]` というスカラなので，その初期化子に式が 2 つある。

`cc15u` までは黙って通し，溢れた `3` を隣へ入れていた。

| | 出る値 | 診断 |
|---|---|---|
| 我々 (`cc15u`) | `1 2 3 4` | **無し** |
| ホストの gcc | `1 2 4 0` (3 を捨て，4 を次の行の先頭へ) | 2 件 |
| 我々 (`cc15v`) | —— | 拒む (6) |

**制約違反に対して黙って値を作っていたのは我々だけ**だった。
`staticstr3` (`{{1,2,3}}`) と同じ壊れ方 —— 溢れた側ではなく**別の場所が
埋まる** —— なので，同じに 6 で拒む。

```c
      base = outp;
      while (tok != o_rc) {
        ginit1(t);
        if (outp - base > w) exit(6);      /* 足した */
        ...
      }
```

この道は元々「多次元を平らにした列の一部を透過的に読む」ためのもの
だった。`cc15s` が `ginit` / `ginit1` の側で**要素ごとに対象を決める**
ようにしたので，ここへ来るのは**対象が本当にスカラのときだけ**に
なっている。透過的に読み続ける理由はもう無い。

## 見つかり方: 差分試験

**台帳の期待値は我々が書いている。** だから我々が「正しい」と思った値が
そのまま期待値になる。この形は `staticstr2` の 12 番として
**`ok` で載せてあった** ——
[stage015/cc15s.md](cc15s.md) の表にも「正」と書いてあった。

見つけたのは `tools/diff17.sh`。**同じソースを我々の鎖とホストの処理系の
両方に訳させ，走らせて値を突き合わせる**。

```
FAIL staticstr2     値が違う
       我々  [y]
       ホスト [16]
```

`16` は 12 番の検査の番号である。

これは `cc15u` (複合代入の符号) と同じ筋の収穫である —— **固定点も再現性も
バイト一致も，我々が書いた期待値の誤りは 1 つも捕まえない。**

## 鎖は変わらない

既存のソースにこの形は無い。`sh` / `ed` / `mk` を訳した `.o` は `cc10l`
のものと 1 バイトも変わらず，`cc15v0` と `cc15v` もバイト一致する。

## 測り方

- 台帳 `tests/stage015/ledger.txt` の `staticstr4` を **`gap 6`** で。
  `staticstr3` と同じく**ずっと `gap` のままでよい形**である
- `staticstr2` の 12 番は**正しい形へ差し替えた** ——
  `{ 1, 2, {3,4} }`。これは C89 として妥当で (gcc も
  `-std=c89 -pedantic-errors` で通す)，値は `1 2 3 4` になる
- `tools/diff17.sh` が「我々が拒む形」を見るときは，
  `gcc -std=c89 -pedantic-errors` が**エラーにするか**で判定する。
  警告の数では弱い —— gcc は正しいソースにも `-Wmissing-braces` の
  ような書き方の助言を出す
