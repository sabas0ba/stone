# cc15z --- C コンパイラ 第 15 世代 その 26

`cc15y` との差は 4 か所で，どれも `typeof` / `__typeof__` / `__typeof`
のためである。ソースは `stage015/cc15z.sc`。設計は
[docs/stage018-ext.md](../docs/stage018-ext.md) 9。

```c
#define MIN(a, b) ({ __typeof__(a) _a = (a); __typeof__(b) _b = (b); \
                     _a < _b ? _a : _b; })
```

## 1. なぜ要るか

カーネルのヘッダは `container_of` / `min` / `max` をこの形で書く。
**文式 (`cc15y`) と組で使う** —— 引数の型を持ち回るためである。
片方だけでは足りない。

## 2. どう直したか

型指定子として読む。`ptype()` に枝を足し，`istype()` が真を返すように
する (宣言の先頭に来るため)。中身は 2 通りで，型名ならそのまま読み，
式なら**型だけ**を求める。

### 2.1 コードを出さずに式を読む

**我々の器は読みながら出す。** 型だけが要る場所では出したものを捨てる。

```c
  si = icnt; sl = labcnt; ss = spcnt;
  assign();
  t = ety;
  if (earr) t = eaty;
  icnt = si; labcnt = sl; spcnt = ss;
```

IR (`icnt`)・ラベル (`labcnt`)・文字列 (`spcnt`) の位置を控えて戻す。
式そのものは普通に読むので，**型の決め方は式の道と 1 か所も違わない**
—— 型付けの規則を 2 つ持つと，必ず片方だけ直す誤りが出る。

### 2.2 配列は退化させない

`typeof(a)` の `a` が配列なら型も配列である (`sizeof(typeof(a))` が
配列全体の大きさになる)。式の側は配列を先頭要素へのポインタへ退化
させるので，退化前の型 (`eaty`) を使う。

## 3. 綴り

`typeof` / `__typeof__` / `__typeof` の 3 つを同じトークンにする。
`typeof` は C89 の予約語ではないので，これを識別子に使うソースは
翻訳できなくなる。**我々のソースは使っていない。**

## 4. 鎖は変わらない

`sh` / `ed` / `mk` の `.o` は `cc10l` のものと一致し，`cc15z0` と
`cc15z` もバイト一致する。
