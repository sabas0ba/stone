# mk 説明文書

mk はビルド記述を読んで実行するコマンドである。ホスト側の
[../tools/build.sh](../tools/build.sh) にあたる役目を，ゲスト内で果たす。
設計は [stage013-tools.md](../docs/stage013-tools.md) 9 章。

ソース [mk.c](mk.c) が正本である。

## ビルド

```
sh tools/build.sh stage013
# bundle(include/*.h mk.c) | pp | cc -> mk13.o
# ld13 'E' (mk13.o + string + stdlib + sys + morecore + stdio) -> mk13
```

SHA-256: 37835fcfd8a3fb81737f0a76ef4fb538bcf00a638bff9ea5b720e2a982b6f515

- 形式: ELF 実行形式 (RV32, ET_EXEC)，33880 バイト

## 使い方

```
mk [-f 記述] [目標]
```

記述を省略すると `mkfile`，目標を省略すると記述の最初の目標を作る。

### 記述の形

```
# 行頭の # は注釈
all: cc pp
	echo done

cc:
	eot < cc12.sc > cc12.in
	cc < cc12.in > cc12.o
```

- **目標行**は行頭が空白でなく `:` を含む行。`:` の後ろは依存の並び
- **命令行**は行頭が空白の行。make の「TAB でなければならない」規則は
  採らない (空白と TAB を区別する形式は誤りを生みやすいわりに得るものが
  ない)
- 命令行の解釈はシェルと同じ (空白で分割，`< 名前` `> 名前` で標準
  入出力を結ぶ)。組込みは `echo` だけ
- 実行する前にその行を出す (make の作法)
- 命令が 0 以外で終わったら，目標の名前と終了コードを出して止まる

## 時刻を見ない

**「目標が依存より古ければ作り直す」という判定はしない。** sfs が
ファイルの時刻を持たないからである
([stage012-os.md](../docs/stage012-os.md) 4.3)。mk がするのは順序づけ
だけである。

- 依存を先に済ませてから自分の命令を実行する
- 同じ目標は 1 度しか実行しない
- 循環は検出して止める

判定を足すなら sfs に時刻を持たせるところからで，**それが要るほど
再ビルドが重くなってから** 行う。現状はチェーンの再生成が十数秒である
([stage013-tools.md](../docs/stage013-tools.md) 9.2)。

## 上限

| 項目 | 上限 |
|---|---|
| 記述の大きさ | 32768 バイト |
| 目標 | 64 |
| 命令行 | 512 (全目標の合計) |
| 依存 | 256 (全目標の合計) |
| 1 命令の語 | 8 (kernel13 の argv の上限) |

9 語目以降は sh と同じく警告なしに捨てられる
([sh.md](sh.md) の「上限」)。

## 診断の粗さ

命令の実行が `spawn` の失敗 (-1) で返ったとき，mk は
`mk: bad command` とだけ出す。**ビルド記述の構文誤りと，コマンドが
sfs に無い・起動できない場合とが区別できない。** ゲスト内ビルドで
「mk: bad command」を見たら，まず目的のコマンドが sfs にあるかを
`sh` から直接起動して確かめるのが早い。errno を出し分けるには
`runcmd` が `spawn` の戻り値をそのまま持ち上げる必要があり，
新しい世代の課題である。
