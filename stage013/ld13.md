# ld13 説明文書

ld13 は実行像を作るリンカの Stage 13 世代である。stage012 の
[ld12.sc](../stage012/ld12.sc) を出発点に，'E' 前置部へ **汎用 syscall
スタブ sys_ecall** を足した。設計は
[stage013-tools.md](../docs/stage013-tools.md) 3.1。

ソース [ld13.sc](ld13.sc) が正本である。バイナリはビルドで再現される
生成物であり，git 管理しない。

## ビルド

```
sh tools/build.sh stage013
# cc(ld13.sc) -> ld13.o -> ld(stage008) -> ld13.bin
```

SHA-256: 39a49ebe330fda087d597579b86b1b86736993b4ccd2679a83376654de848c1f

- 対象: RV32IM，リトルエンディアン，34896 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## ld12 との差分

`'E'` 前置部の末尾 (ehsz + 448) にスタブを 1 本足しただけである。

```
int sys_ecall(int n, int a, int b, int c);   /* a7 = n, a0..a2 = a, b, c で ecall */
```

以降の syscall の増設は libc の環境部が sys_ecall を包むだけで済み，
前置部 (機械語) は変えなくてよい。既存の専用スタブ (sys_read /
sys_write / sys_openat / sys_close / sys_brk) と getc / putc / exit は
互換のためそのまま残る。エントリポイント (0x8600_0054) も変わらない。

`'F'` / `'K'` の前置部には触れていない。両形式の出力が ld12 と
バイト一致することを
[../tests/stage013/test.sh](../tests/stage013/test.sh) が確認する。
`'E'` の出力は前置部が 56 バイト延びるぶんだけ ld12 と異なる。

## 前置部が提供するシンボル

| 形式 | シンボル |
|---|---|
| `'F'` | getc, putc, exit |
| `'K'` | getc, putc, exit, urun |
| `'E'` | getc, putc, exit, sys_read, sys_write, sys_openat, sys_close, sys_brk, **sys_ecall** |
