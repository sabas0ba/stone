# libc22 --- ホストと突き合わせて出た穴を埋めた世代 (第 22 世代)

`libc21` の全文複製に，**差分試験の OS 側 (`tools/diff17.sh os`) が
見つけた C89 との食い違い**を直したものである。経緯は
[docs/stage017-gcc.md](../docs/stage017-gcc.md) 5.3。

## 1. 立場

**この世代から作られる記録対象の成果物はまだ無い。** 鎖の側
(`cc19` が tcc を組む道 / `tools/ext17.sh` が zlib・bzip2 を組む道) は
`libc21` のままである。そちらを動かすと 21 章・29 章・5.1 のバイト
突き合わせが動くので，触っていない。凍結した世代は凍結したまま再現
できることがこの鎖の前提である ([artifacts.md](../docs/artifacts.md))。

したがって本書に SHA-256 の表は無い。表が要るのは，この世代から
記録対象の成果物を作るようになったときである。

**訳す器を最前線へ揃えた。** `libc19` 〜 `libc21` は `cc15k` で訳して
いたが，この世代は `cc15v` で訳す。この世代を測るプローブも `cc15v` で
訳すので，器と libc の世代が食い違っていると，出た差がどちらのものか
言えなくなる。

## 2. `libc21` との差

| | 中身 | 誰が見つけたか |
|---|---|---|
| `posix/stdio.c` の `%o` | 8 進の変換が**無かった**。知らない変換指定は「普通の字」として書き出す作りなので，`%o` は `o` と書かれ，**可変部を 1 つも取り出さないまま次へ進んで**いた | `probe/printfmt.c` |
| 同 `%X` | 常に小文字で書いていた (`beef`)。C89 7.9.6.1 は `X` を大文字と定める | 同 |
| 同 整数の精度 | `%.3d` の精度を読み捨てていた。精度は最小の桁数であり，足りない分は 0 で埋める。`%.0d` の 0 は**何も書かない** | 同 |
| 同 旗 `+` / 空白 / `#` | 旗として認識せず，`%+d` が `+d` になっていた。ここでも可変部がずれる | 同 |
| 同 符号と詰め物の順 | **負の数を幅つきで書くと符号が先に出ていた** —— `%5d` の -42 が `-  42` になる。空白の詰め物は符号より前に来る (0 の詰め物だけが符号の後ろ) | 同 |
| 同 `%f` の丸め | 切り捨てていた。`%.0f` の 2.6 が 2 になる。C89 7.9.6.1 は「丸める」と定める | 同 |
| 同 `%c` の幅 | 幅を無視していた | **測っていない** (同じ直しの中で揃えたもの) |
| 同 `h` / `hh` | 長さ修飾として読み飛ばしていなかったので `%hd` が `hd` になっていた | **測っていない** (同上) |
| `src/stdlib.c` の `strtoul` / `strtoull` の空白 | 空白と水平タブしか読み飛ばさなかった。C89 の空白は 6 種類ある | `probe/strtolx.c` |
| 同 `endptr` | **変換できる桁が 1 つも無いときに `endptr` を進めていた。** `"  -"` で呼び手が 3 文字進んだことになる。C89 7.10.1.6 は「変換が行われなければ `nptr` を格納する」と定める | 同 |
| 同 `0x` の扱い | `"0x"` の後ろが 16 進数字でなくても `0x` を食べていた。主部は `"0"` であり，`endptr` は `x` を指す | 同 |
| `posix/stdio.c` の `fgets` | **「読めなかった」と「読む余地が無かった」を一括りにしていた。** `fgets(b, 1, f)` が NULL を返す —— 呼び手からは終端に見える。C89 7.9.7.2 が NULL を返せと言うのは終端か誤りに当たったときだけで，`n == 1` は 1 バイトも要求されていないだけである | `probe/filex.c` |

`printf` の整数変換は，第 21 世代の `pnum` (32 bit) と `pnum64`
(64 bit) を `pout` 1 つにまとめ直した。旗・精度・幅・符号・`0x` の
前置をすべてここで扱う。**32 bit と 64 bit で別々に旗を実装すると，
片方だけ直す誤りが必ず出る。**

## 3. なぜ自分では見つからなかったのか

**我々のソースはこれらの書き方を 1 つも使っていない。** `%o` も
`%+d` も `%#x` も `%.3d` も，鎖のどのプログラムにも出てこない。
`strtoul` に空白つきの文字列を渡す場所も無い。

したがって固定点も再現性もバイト一致も，この誤りを 1 つも捕まえない。
`cc15u` (複合代入の符号) と同じ構図である
([docs/stage017-gcc.md](../docs/stage017-gcc.md) 5.2)。

**台帳の期待値を我々が書いている限り，我々の思い込みがそのまま期待値に
なる。** 外の物差しと値を突き合わせる以外に道が無い。

## 4. まだ直していないもの

**無いものは無いと言う** (libc21.md 3 章と同じ方針)。

| | どうなっているか | なぜ |
|---|---|---|
| `%f` のちょうど半分 | 0 から遠い側へ倒す。ホスト (glibc) は偶数側 | C89 7.9.6.1 は丸めの向きを定めていない。どちらも規格に適合する。プローブはこの値を置かない |
| `%f` の桁の精度 | 10 の冪を割り算で作り，小数を掛け算で取り出すので，大きな値や長い精度では下位が狂う | 正しく書くには多倍長が要る。`%f` は統計表示にしか使っていない |
| `%e` / `%g` | `%f` の形で出す | 同上。指数形式を使う場所がまだ無い |
| `%p` | `0x` を付けずに 16 進で書く | C89 は表現を実装に委ねている。ホストと形が違うので，プローブでは測らない |
| `%n` / `%S` / `%ls` | 無い | 使う場所がまだ無い。知らない変換指定は今までどおり「普通の字」として書く |
| `strtol` の溢れ | `LONG_MAX` / `LONG_MIN` へ飽和する。`errno` は設定しない | 我々の `long` は 32 bit，ホストは 64 bit なので，飽和する値そのものが違う。プローブでは測らない |
| `sscanf` | `%d` と空白と字面の一致だけ。`%s` / `%c` / `%x` / `%*` / 幅は無い | `stdio.h` が最初から**非目標**と書いている。差分試験に置くと「違って当然」の行が並ぶだけになるので，**要るものが判ってから**実装する (5.4) |
| バッファリング | しない (`setvbuf` も無い) | 正しさを先に置く方針 (stage012 6.4)。`fflush` が何もしないのはその帰結で，**無バッファなら溜まっているものが無い**から正しい |
