# pp20 説明文書

pp20 は C プリプロセッサの第 20 世代である。[pp19.sc](pp19.sc) の
**全文複製**に，**マクロ表の容量と名前の引き方**だけを変えた。展開の規則も，
`-I` の探し方も，出力も変えていない (`libiberty/regex` の `.i` は `pp19` と
バイト単位で同じである)。

ソース [pp20.sc](pp20.sc) が原本である。

## ビルド

```
sh tools/build.sh stage017
# cc15p(pp20.sc) -> pp20.o -> ld16 'E' -> pp20
```

SHA-256: c5eadc105c075767a5b38d00484be51e7a3c6aa919593ef74a640865c1f44a25

## なぜ要ったか

GCC 4.7.4 の gcc/ 本体 (cc1 を作る 347 単位) を `pp19` に通すと，**全単位が
容量超過 (6) で止まった** ([docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.11)。
`pp19` と同じく各 `exit(6)` を別々の値にした調査用の版で場所を特定すると，
2 つの上限に順に当たっていた。

| 上限 | `pp19` | gcc/ の単位が要るもの |
|---|---|---|
| マクロの数 | 4096 | **7,000〜15,000** (対象の記述 `tm.h`・`insn-flags.h` などを読む) |
| マクロ本体 | 256 KiB | 0.5〜1.5 MB |
| 識別子の長さ | 63 バイト | **64 バイト** (`ggc_alloc_zone_cleared_vec_gimple_statement_with_memory_ops_base`) |

バンドル (入力) も 1 単位 2〜4 MB あり，`pp19` の入力の上限 4 MiB に近い。

## 変えたもの

| | `pp19` | `pp20` |
|---|---|---|
| マクロの数 | 4096 | 32768 |
| マクロ名のスロット | 64 バイト | 128 バイト |
| 識別子・マクロ名・仮引数名 | 63 バイト | 127 バイト |
| マクロ本体 | 256 KiB | 4 MiB |
| 仮引数名 | 128 KiB | 4 MiB |
| 入力 (`src`)・アリーナ 1 (`xb`) | 4 MiB | 8 MiB |
| **名前の引き方** | 全スロットを先頭から比べる | **ハッシュ表** (65536 項目の開番地法) |

**バンドルのメンバ名 (`#include` の綴り) は 63 バイトのまま**である。gcc/ で
使う綴りはすべて収まっている。

### 名前をハッシュ表で引く理由

`pp19` までは，識別子を 1 つ読むたびにマクロの全スロットを先頭から比べて
いた。4096 個までなら問題にならなかったが，15,000 個のマクロを持つ単位で
3 MB の入力を読むと，比較の回数が現実的な時間で終わる量を超える。容量だけを
広げても，gcc/ の単位は前処理が終わらない。

表は 65536 項目で，項目にはスロット番号 + 1 を置く (0 = 空)。スロットは
32768 までなので，詰まり具合は半分を超えない。スロットは `#undef` でも消さない
(`mcon` を 0 にするだけ) ので，表から項目を消す操作は要らない。

## C89 と識別子の長さ

C89 5.2.4.1 は内部識別子の先頭 31 文字を有意とすることを求めるが，**それより
長い識別子を拒んでよいとは言っていない**。`pp19` までの 63 バイトの上限は，
上限を超える名前を容量超過で拒んでいた。`pp20` でも 127 バイトを超える名前は
6 で拒む (黙って切らない)。

`tests/stage017/test.sh` 第 10 部。

  `pp19` は 6 で拒み，`pp20` は通して正しい置換結果を出す
