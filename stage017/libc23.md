# libc23 --- ホストと突き合わせて出た穴を埋めた世代 (第 23 世代)

`libc22` の全文複製に，**差分試験の OS 側 (`tools/diff17.sh os`) が
ホストと突き合わせて見つけた食い違い**を入れたものである。経緯は
[docs/stage017-gcc.md](../docs/stage017-gcc.md) 5.3 / 5.4 / 6.3。

触っているのは `posix/stdio.c` と `src/stdlib.c` の 2 本だけで，
`include/` は `libc22` と 1 バイトも変わらない。

> **2 つの枝の世代を 1 つに畳んである。** この直しは
> [PR #93](https://github.com/sabas0ba/stone/pull/93) の枝で
> `libc22` (printf の旗・精度・`%o` / `%X`，`strtoul` の空白と `endptr`，
> `fgets(b, 1, f)`) と `libc23` (浮動小数点変換) の 2 世代に分けて
> 刻まれていた。あちらの `libc22` はこちらの `libc22` (`putc` の
> マクロ) と名前が衝突するので，**両方の直しをこちらの `libc22` の上へ
> 合流させて 1 世代**にした。分けて刻み直しても測れるものは同じで，
> 世代を 2 つ増やすだけになる。

## 1. 立場

**この世代から作られる記録対象の成果物はまだ無い。** 鎖の側
(`cc19` が tcc を組む道 / `tools/ext17.sh` が zlib・bzip2 を組む道) は
`libc21` のままである。したがって本書に SHA-256 の表は無い。表が要る
のは，この世代から記録対象の成果物を作るようになったときである
([artifacts.md](../docs/artifacts.md))。

`configure` の道具 (`sed1`〜`sed3` / `sh3`〜`sh5` / `awk1` / `re1` /
`re2`) はすべてこの世代を繋ぐ。

**この世代から `cc15k` では組めない。** `l19`〜`l22` は `cc15k` で
組んでいたが，`libc23` の `posix/stdio.c` は `cc15k` が 5 で拒む。
最前線の `cc15ab` で組む —— libc を組む器が `cc15k` から動くのは
第 19 世代以来である。

## 2. `libc22` との差

### 2.1 `posix/stdio.c` —— 浮動小数点の変換

| | 中身 | 誰が見つけたか |
|---|---|---|
| `%g` / `%e` | **`%f` と同じ形で出していた。** `%.6g` が `3.141590` になり，`%e` が指数の形にならない。C89 7.9.6.1 は 3 つを別の形と定める | `probe/fltfmt.c` |
| `%f` の半端 | 0 から遠い側へ倒していた (`%.0f` の 2.5 が 3)。ホスト (glibc) は偶数側へ倒す。C89 は「どちらへ倒すか」を定めていないが，**物差しと突き合わせる以上は物差しに合わせる** | 同 |
| `%E` / `%G` / `%F` | 変換として認識していなかった (「普通の字」として書き出し，**可変部を取り出さないまま次へ進む**) | 同 |
| `#` 旗 | 浮動小数点に効いていなかった。精度が 0 でも小数点を残す | 同 |
| 幅と詰め物 | `%12.4e` の類が効いていなかった。符号と詰め物の順は整数の側と同じ規則である | 同 |

### 2.2 `posix/stdio.c` / `src/stdlib.c` —— 書式と変換の残り

`%g` / `%e` より先に出ていた食い違いである (5.3)。

| | 中身 | 誰が見つけたか |
|---|---|---|
| `printf` の旗と精度 | `-` / `0` / `+` / 空白 / `#` と精度の組合せが効かない場所があった | `probe/printfmt.c` |
| `%o` / `%X` | 変換として持っていなかった | 同 |
| `strtoul` | 先頭の空白を読み飛ばさず，`endptr` を進めていなかった | `probe/strtolx.c` |
| `fgets(b, 1, f)` | 読めた文字数が 0 なら `NULL` を返していた。`n == 1` は 1 バイトも要求していないので 0 になるのが正しく，**呼び手からは終端に見える** | `probe/filex.c` |

**どれも「動くが違う」である。** 拒まないので，我々が書いた期待値では
永久に出ない —— ホストという別の物差しに当てて初めて出た。

## 3. どう組んでいるか

十進へ寄せてから数える。

1. 10 の冪の表で値を `[1, 10)` へ寄せ，先頭桁の冪 `e` を得る
2. 求める有効桁数 `nsig` に対し `v * 10^(nsig-1-e)` を整数へ丸める
3. その整数の桁を並べ，`e` に従って小数点か指数を置く

**2 の掛け算は 1 回で済ませる。** `10^0` から `10^22` までは double で
正確に表せるので，1 回の掛け算なら誤差が入るのは丸めの 1 回だけである。
1 桁ずつ割ると割り算の回数だけ誤差が積む。

半端は偶数へ倒す。ただし**「半端かどうか」の判定に落とし穴がある** ——
`2.45` は 2 進では `2.45` より僅かに大きいので `%.1f` は `2.5` になる
べきだが，`2.45 * 10` を素直に計算すると丁度 `24.5` に丸まって半端に
見え，偶数丸めで `2.4` になる。積を Dekker の手 (`fprderr`) で正確に
求めて判定している。

## 4. 限界 (測っていない範囲)

**2 進の値を十進へ正確に展開してはいない。** 上の 2 で有効 18 桁まで
しか数えないので，

- 有効 17 桁を求める形 (`%.16e` の類) はホストと分かれる。有効 16 桁
  までは一致する
- `%f` で整数部と小数部を合わせて 18 桁を超える値 (`%f` の `6.02e23`
  など) は，18 桁から先を 0 で埋める。ホストは正確な十進展開を出す

正確な展開には多倍長の整数演算が要る。実際の呼び手が使うのは `%.6g` や
`%.2f` の類で，そこは一致するので，**必要になった世代で足す**。

`%#g` で丸めが桁上がりする値 (`%#.6g` の `999999.5`) はホストと分かれる。
glibc は `1.e+06` を返すが，C89 の `#` は「末尾の 0 を落とさない」で
あって「落とす」ではないので，我々の `1.00000e+06` が規格の側である
(glibc は `1000000.0` に対しては `1.00000e+06` を返しており，桁上がりの
ときだけ振舞いが変わる)。ここは物差しに合わせていない。
