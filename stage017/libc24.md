# libc24 --- `struct stat` の欄を足した世代 (第 24 世代)

`libc23` の全文複製に、**GCC 4.7.4 の 5 単位を止めていた 4 つの欄**を
入れたものである。経緯は
[docs/stage017-gcc.md](../docs/stage017-gcc.md) 8.5 / 8.7 の 7。

触っているのは `include/sys/stat.h` と `posix/sys.c` の 2 本だけで、
他は `libc23` と 1 バイトも変わらない。

## 1. 立場

**この世代から作られる記録対象の成果物はまだ無い。** ビルドチェーンの側
(`cc19` が tcc を組む経路 / `tools/ext17.sh` が zlib・bzip2 を組む経路) は
`libc21` のまま、`configure` の道具 (`sed1`〜`sed3` / `sh3`〜`sh5` /
`awk1` / `re1` / `re2`) は `libc23` のままである。したがって本書に
SHA-256 の表は無い。表が要るのは、この世代から記録対象の成果物を作る
ようになったときである ([artifacts.md](../docs/artifacts.md))。

**カーネルの第 26 世代が要る。** `stat` が `statat2` (502) を呼ぶので、
`kernel25` 以前では動かない。

## 2. 足した 4 つの欄

| 欄 | 値 | 止まっていた単位 |
|---|---|---|
| `st_dev` | **常に 1** | `libiberty/fdmatch` |
| `st_ino` | sfs の表の項目番号 + 1 | `libiberty/getpwd` |
| `st_mode` | **種別のビットだけ** | `libiberty/unlink-if-ordinary`, `libcpp/files` |
| `st_mtime` | epoch からの秒 | `libcpp/macro` |

**4 つとも本当の値である。** 埋め草を置いて名前だけ揃えたものは 1 つも
無い。`libc18` の `sys/stat.h` が書いた「あるのに嘘の値を返すより、
無いほうが呼び手にとって安全である」という判断は、ここでも変えていない。

### `st_dev` が 1 である理由

sfs の巻は 1 つしか無い。**見えているファイルは全部同じ装置の上にある**
ので、「同じ装置か」の答は常に「はい」である。これは埋め草ではなく事実で
あり、`(st_dev, st_ino)` の組で「同じファイルか」を見る呼び手
(`fdmatch` / `getpwd`) は正しく動く。

0 ではなく 1 にしたのは、0 を「判らない」の意で使う呼び手があるためで
ある。

**2 つめの巻を繋ぐ日には本物にすること。** そのときに初めてここが嘘に
なる。条件を書いておかないと、後から読んだ人は「1 で良い」とだけ読む。

### `st_ino` が項目番号 + 1 である理由

sfs の表の項目番号は 1 つの巻の中で一意で、名前を変えても追える ——
`st_ino` に求められる性質そのものである。

+1 するのは根の項目番号が 0 だからである。0 を「番号が無い」の意で使う
呼び手があるので、**どのファイルの番号も 0 にならない**ようにする。

配るのはカーネルである。`statat` (79) は u32 4 語を書くと約束していて、
その約束は変えていない —— 5 語を書く新しい約束は
`statat2` (502) という新しい番号で配る ([kernel26.c](kernel26.c) の註)。

### `st_mode` に許可ビットが無い理由

立つのは `S_IFDIR` か `S_IFREG` だけで、許可ビットは 0 である。これは
値としては嘘に近い —— 「誰にも読めない」と読めてしまう。

そこで**許可ビットを読む道具を置いていない**。`S_IRUSR` / `S_IWUSR` /
`S_IXUSR` などの macro を定義していないので、許可を見ようとするソースは
**翻訳の時点で止まる**。値で嘘をつく代わりに、名前を配らないことで
気づかせる。

`S_ISLNK` / `S_ISCHR` / `S_ISBLK` / `S_ISFIFO` / `S_ISSOCK` は常に偽で
ある。sfs にこれらの種別が無いので、「無い」が本当の答である。

### `st_mtime` が本当の暦の値である理由

カーネルの時計は goldfish RTC で、`kernel24` 以降は**本当の epoch から
のナノ秒**を表に書いている。`st_mtlo` / `st_mthi` の 64 bit を 10^9 で
割れば秒になる。

11.2 で「秒に直さない」と決めたのは、比べるだけなら 64 bit の除算が
要らないからである。`st_mtime` は POSIX が秒で配ると決めている欄なので、
ここでは直す。**除算はこの 1 か所だけ**で、`newer()` は今までどおり
2 語を上位から比べる。

> **`time()` と `localtime()` は別物である。** どちらもまだ紀元の固定値
> を返す ([include/time.h](libc24/include/time.h))。`st_mtime` が本物に
> なっても `__TIMESTAMP__` の類は直らない —— そちらは `asctime` も要る。
> `libcpp/macro` は `.o` までは出るが、まだ繋がらない。

## 3. 測り方

`tools/diff17.sh` の OS 側に `statx` を足した (`tests/stage017/probe`)。

**値そのものは突き合わせられない** —— 項目番号も装置番号も時刻も、
ホストと stone の OS で同じになる理由が無い。突き合わせるのは
**欄が満たすべき性質**である。

| 見るもの | 埋め草を置くとどうなるか |
|---|---|
| 同じファイルを 2 度見れば同じ番号 | 通る (埋め草でも通る) |
| 違うファイルなら違う番号 | **破れる** |
| 番号が 0 でない | **破れる** |
| 1 つの巻の上では装置番号が揃う | 通る |
| 種別のビットが `S_ISREG` / `S_ISDIR` と噛み合う | **破れる** |
| 時刻が 2001 年より後 | **破れる** (時計が無ければ 0) |

ホストでも我々でも同じ答になるはずのものだけを並べてある。違えば
**片方が嘘をついている**。

## 4. ビルド

```
sh tools/build.sh stage017
# cc15ac + pp で l24_*.o を組む
```

`libc23` は `cc15ab` で組んでいたが、この世代は最前線の `cc15ac` で
組む。`libc24` 自身は `cc15ab` でも組めるが、**最前線を 2 つに分けない**。
