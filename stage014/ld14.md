# ld14 説明文書

ld14 はリンカの Stage 14 第 8 部の世代である。
[../stage013/ld13.sc](../stage013/ld13.sc) を出発点に，**大域シンボル名の
上限を 15 バイトから 31 バイトへ広げた**。設計は
[stage014-external.md](../docs/stage014-external.md) 12 章。

ソース [ld14.sc](ld14.sc) が正本である。

## ビルド

```
sh tools/build.sh stage014
# cc.bin(ld14.sc) -> ld14.o, ld.bin -> ld14.bin   (ld13 と同じ道具立て)
```

SHA-256: fb5b56f1e55a484b8abf31e26907641868c42f92b1769f7186ea6e4c7aad3435

- 対象: RV32IM，リトルエンディアン，34896 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## なぜ要るか

ld13 までの大域シンボル表は 16 バイト固定 (15 文字 + 終端) で，登録時に
名前を黙って切り詰めていた。bzip2 の `BZ2_bzBuffToBuffCompress` (24 文字)
のような長い名前は，切り詰められた定義と切り詰められていない参照が
一致せず，**オブジェクトをまたぐ参照だけが未定義 (終了コード 2) になる**。

同一オブジェクト内の参照はシンボル名でなく節内オフセットで解決される
ため，この制限は「複数オブジェクトのリンク + 長い名前」の組合せで初めて
露呈する。ブートストラップ鎖自身のソースは短い名前しか使わないため，
外部ソースを当てるまで残っていた。

## ld13 との差分

- `gnm` (大域シンボル名の表): 16 バイト x 2048 -> 32 バイト x 2048
- `gfind` / `gadd` / `gfindlit` / `gaddlit` の走査幅を 32 へ
- それ以外 ('E'/'K'/'F' の前置部・再配置・出力形式) は ld13 と同一。
  短い名前しか含まない入力に対する出力はビット単位で変わらない

## 制限

- シンボル名は 31 バイトまで。それを超える名前は従来と同じ形で切り詰め
  られる (bzip2 1.0.8 の最長は 26 文字)
