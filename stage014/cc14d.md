## cc14c との差分

### タグの前方参照 (台帳: selfref)

`typedef struct node Node;` のように，本体が出る前のタグを使える。

- `ptype` がタグを引けなければ**不完全型** (大きさ 0) として登録し，
  本体は後の `struct node { ... }` (`strudef`) が同じ項目を埋める
- 大きさ 0 を「不完全」の印に使うので，メンバの無い定義も最小 4 にする
- **不完全のまま値で使うことは拒む** (終了コード 5)。メンバ・局所・
  大域のどこでも同じで，通せるのはポインタだけである (大きさが
  決まらないものに実体は置けない)

### K&R 形式の関数定義 (台帳: kr_func)

```
int add(a, b)
int a;
int b;
{ return a + b; }
```

- `(` の直後が「typedef 名でない識別子」なら K&R の並びとみなし，
  名前だけを int として登録する
- `)` と `{` の間の宣言 (`krdecl`) が型を与える。1 行に複数の宣言子を
  書け，配列は先頭要素へのポインタになる (仮引数の C の規則)
- 型宣言の無い名前は int のまま (C の既定)

## 制限

- K&R の並びとプロトタイプ (`int add(int, int);`) の整合は検査しない
  (個数は従来どおり検査される)
- 不完全型の配列 (`struct s arr[4];` を前方参照のまま) は個別には
  検査しない。実体を置く時点の大きさ 0 で捕まる
