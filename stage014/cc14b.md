# cc14b 説明文書

cc14b は C コンパイラの Stage 14 第 3 部の世代である。
[cc14.sc](cc14.sc) (第 2 部, cc14a) を出発点に，**入れ子の初期化子**を
足した。設計は [stage014-external.md](../docs/stage014-external.md) 6 章。

ソース [cc14b.sc](cc14b.sc) が正本である。

```
sh tools/build.sh stage014
# cc14a(cc14b.sc) -> cc14b0     (1 段目)

```

## cc14a との差分

台帳の 2 件を潰した。どちらも **原因は同じ**で，大域の初期化子を 1 個
読む `ginit1` が `{` を受けなかったことである。

| 台帳の項目 | 例 |
|---|---|
| nestinit | `struct p tab[2] = { { 1, 2 }, { 3, 4 } };` |
| fptab (**残る**) | 入れ子の初期化子は通るようになったが，`struct op { int (*fn)(void); };` の**構造体メンバの関数ポインタ**が別の未対応として残っている |

`ginit1` に次を足した。

- 要素が **構造体** なら，メンバを登録順に埋める。メンバ間の隙間と
  末尾の余りは 0 で埋める (`moff` と `tsize` を見る)
- それ以外なら，`{ ... }` を **透過的な括り** として読む。多次元配列は
  `ginit` が既に要素型を平らに畳んでいるので，内側の括りは「平らな列の
  一部」として読めばよい

あわせて `ginit` の配列ループが要素数を **出力バイト数から** 求めるように
した。入れ子の初期化子は 1 回の `ginit1` で複数の要素を出すので，
呼出し回数では数えられない。

## 制限

- **局所変数の初期化子 (`linit`) は入れ子を受けない。** 大域だけの対応で
  ある。現実の C で静的な表が大域に置かれることが多いのを優先した
- 構造体メンバが配列のとき，そのメンバへ文字列を直に書く形
  (`struct { char n[8]; } s = { "ab" };`) は扱わない。文字列は
  ポインタとして出る
