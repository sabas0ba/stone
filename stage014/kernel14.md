# kernel14 説明文書

kernel14 は簡易 OS のカーネルの Stage 14 世代である。stage013 の
[kernel.c](../stage013/kernel.c) を出発点に，**sfs の上書きが隣接ファイルを
壊す問題**と **ELF ローダの境界検査の欠落**を直した。機能は足していない。
設計は [stage014-external.md](../docs/stage014-external.md) 13 章。

ソース [kernel14.c](kernel14.c) が正本である。自作の C89 で書かれており，
特権命令は一切含まない (すべて ld14 の 'K' 前置部が持つ。'K' の前置部は
ld12 / ld13 と同一である)。

## ビルド

```
sh tools/build.sh stage014
# bundle(kernel14.c) | pp | cc14f -> kernel14.o -> ld14 'K' -> kernel14.bin
```

- 対象: RV32IM，リトルエンディアン，21888 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## kernel13 との差分

### sfs の上書き (追記割付けの不変条件を立てる)

kernel13 の `sfswrite` は表項目に割付け容量を持たず，`off + pos` へ
無条件に書いた。既存ファイルを元の割付けより長く書き直すと直後の
ファイルを壊し，末尾でない項目を伸ばすとカーソルが巻き戻った。

kernel14 は次の不変条件を立てる。

```
各項目は [off, off + rup4(len)) を占め，カーソルは常に使用済みの末尾を指す
  ⇒  off + rup4(len) == カーソル   ⇔   その項目が最後の割付け
```

`sfsgrow` がこれを見て分岐する。

| 状況 | 動作 |
|---|---|
| 今の割付けに収まる | そのまま書く |
| 最後の割付け | その場で伸ばし，カーソルを進める |
| 最後でない | 中身を末尾へ引っ越してから伸ばす |

カーソルは決して巻き戻らない。`O_TRUNC` は `len = 0` にするだけでよい
(次の書込みが `rup4(0) = 0` に収まらないので自動的に末尾へ移る)。

領域が尽きたら `sfswrite` は `-ENOSPC` を返し，`sys_write` は fd の
位置を進めずにそれをそのまま返す。

### ELF ローダの境界検査

`elfok` を分けた。載せる前に次を確かめ，1 つでも外れれば `ENOEXEC` で
拒む (kernel13 はマジック 2 バイトしか見ていなかった)。

- `\x7fELF` の 4 バイトと，ELF ヘッダぶんのファイル長
- プログラムヘッダと中身がファイルの中に収まること
- `p_filesz <= p_memsz`
- 載せ先が `[UBASE, UBRKMAX]` に収まること

引き算はすべて「引かれる側が大きいこと」を確かめてから行う。unsigned
なので `pva + msz > UBRKMAX` の形は桁あふれで通ってしまう。

### spawn の順序

退避領域の資源検査 (`ENOMEM`) と `elfok` を，つなぎ替えの解決 (出力
ファイルの切詰め) より**前**へ移した。kernel13 は起動に失敗しても
出力ファイルだけが切り詰められていた。

## 引き継ぐもの

kernel13 の機能はすべてそのまま持つ。

- `spawn` (500): プログラムからのプログラム起動。子の終わりを待つ逐次実行
- 標準入出力のつなぎ替え (`spawn` の引数で子の fd 0 / fd 1 を指定)
- fd 0 の read は最初の 1 バイトが届くまで待つ
- syscall 番号は RV32 Linux 互換 (read / write / openat / close / brk / exit)

## 制限

- 引っ越しは旧領域を捨てるので，同じファイルを何度も書き直すとイメージが
  やせる。詰め直しはホストで pack し直すのがいちばん安い
- ファイルの削除は無い (表項目の flags を落とす手段が無い)
- `fopen("a")` は追記にならない。libc 側の制限であり，カーネルは関与
  しない ([libc.md](libc.md) の「制限」)
