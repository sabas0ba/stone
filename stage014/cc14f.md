# cc14f 説明文書

cc14f は C コンパイラの Stage 14 第 8 部の世代である。
[cc14e.sc](cc14e.sc) (第 6 部) を出発点に，**外部ソース (bzip2 1.0.8) を
実際に当てて落ちた箇所**を潰した。設計は
[stage014-external.md](../docs/stage014-external.md) 12 章。

ソース [cc14f.sc](cc14f.sc) が正本である。

## ビルド

```
sh tools/build.sh stage014
# cc14e(cc14f.sc) -> cc14f0     (1 段目)
# cc14f0(cc14f.sc) -> cc14f     (正本。以降は固定点)
```

SHA-256: 9526b8391bb50f22c487087b3239577cf6989fe4cac4f1be66775a57ddd3421a

- 対象: RV32IM，リトルエンディアン，156436 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## cc14e との差分 (すべて bzip2 の実測で見つかったもの)

| 差分 | 台帳 | bzip2 での出所 |
|---|---|---|
| 16 進リテラルの大文字 (`0xFF`) | hexcase | bzlib_private.h のマクロ (`& 0xF`) |
| 単項 `~` (ビット反転) | bitnot | blocksort.c (`&= ~mask`) |
| 宣言子の定数式 (`[2 + 3]`) | dimexpr | `[BZ_MAX_SELECTORS]` = `[(2+(900000/50))]` |
| 2040 バイト超のフレーム | bigframe | fallbackSort のローカル配列 2052 バイト |
| IR 命令数 8191 -> 16383 | (台帳外) | sendMTFValues の手動アンロール展開 |

付随して，ラベル (1023 -> 2047) と前方参照の後埋め (2047 -> 4095) の
上限も倍にした (BZ2_decompress 級の巨大関数のため)。

### 実装の要点

- **`~` は `x ^ -1` へ落とす。** 命令種別 (c_*) を足さないので，
  IR の 4 箇所ルール ([dev-notes.md](../docs/dev-notes.md) 4 章) を
  踏まずに済む
- **宣言子の定数式は専用の畳込み評価器で読む** (`ccond` / `cbin` /
  `cuna`)。式の IR を作ってから畳むのではなく，トークンから直接値を
  作る。C89 の整数定数式のうち sizeof とキャストは保留 (会った例が
  無い)。列挙定数は使える
- **大きなフレームは x10/x11 を作業レジスタにした 3 語のアドレス生成**
  (`laddr`: liw + add) で扱う。2047 バイト以下の関数の生成コードは
  cc14e と 1 バイトも変わらない (回帰テストで確認)。フレームの新しい
  上限は 65528 バイト

## cc.bin は差し替えない

cc14a〜cc14e と同じ扱いである ([cc14.md](cc14.md) 参照)。

## 残っている未対応

台帳を参照。浮動小数点・空の引数リストへの実引数・long long が残る。
いずれも bzip2 のビルドには不要である (BZ_NO_STDIO 版は前処理後に
浮動小数点が消える)。
