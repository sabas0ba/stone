## cc14b との差分

### 関数内 `static` (台帳: staticloc)

実体をフレームではなく **`.bss`** に取り，呼出しをまたいで値が残る。

- 大域表へ「元の名前 + `.` + 通し番号」の別名で登録する。`.` は識別子に
  使えないので利用者の大域と衝突せず，一意性は通し番号だけで決まる
  (関数が違っても同じ名前の `static` を持てる)。ELF にはローカル
  シンボルとして出る
- 局所表には元の名前で載り，`lsg` が別名の大域記号を指す。参照
  (`eident`) は大域と同じ `c_gaddr` を出す
- **初期化子は未対応。** 通すと初期値が付かないまま静かに壊れるので
  拒む (終了コード 1)。`.bss` なので値は 0 で始まる (`static int n;`
  は C の意味どおり)

### 構造体メンバの関数ポインタ (台帳: fptab)

`struct op { int (*fn)(void); };` が通る。`strudef` がメンバの宣言子で
`isfnp()` を見て `fnpdec` へ回すだけで，呼出し (`ops[i].fn()`) は
既存の「関数へのポインタを通した呼出し」(`epost` の `o_lp`) がそのまま
効く。**コード生成には触れていない。**

## 制限

- 関数内 `static` の初期化子 (上記)
- `static` は宣言の先頭に書く (`int static n;` の順は受けない)
