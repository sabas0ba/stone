# pp 説明文書

pp は C プリプロセッサである。ソース群を束ねたものを受け取り，
`#include` の差込みとマクロ展開，条件コンパイル，コメントの除去を行って，
前処理済みのテキストを返す。設計は
[stage009-pp.md](../docs/stage009-pp.md) を参照。

名称が `cpp` でないのは，`.cpp` が C++ のソース拡張子として広く使われており，
将来 C++ を扱う場合にその名前が要るためである
([stage009-pp.md](../docs/stage009-pp.md) 1.2)。

ソース [pp.sc](pp.sc) が正本である。バイナリはビルドで再現される生成物であり，
git 管理しない。

## ビルド

```
sh tools/build.sh stage009
# ... -> cc, ld -> pp.o -> pp.bin
```

pp.sc 自身は指令を含まないため，前処理を通さずに cc + ld でビルドできる。

SHA-256: e54e418ba47b72253d804addaaa342be3dde4e44db492f611859391e9053afd3

- 対象: RV32IM，リトルエンディアン，53104 バイト
- ロードアドレス: 0x8000_0000 (QEMU virt, `-bios`)

## 使い方

実行環境は UART のみでファイルを開けないため，`#include` の探索対象は
**標準入力から与えた束ね** に限られる。束ねは `tools/bundle.sh` が作る。

```
sh tools/bundle.sh util.h main.c | sh tools/env.sh qemu tmp/build/pp.bin > main.i
cat main.i | sh tools/env.sh qemu tmp/build/cc.bin > main.o
{ cat main.o; printf '\0'; } | sh tools/env.sh qemu tmp/build/ld.bin > main.bin
```

最後に並べたファイルが前処理対象の翻訳単位で，それより前のものは
`#include` で参照できる。出力の末尾には EOT (0x04) が付くので，
そのまま cc へ繋げられる。

束ねのマジックで始まらない入力は，全体を 1 個のメンバとみなす。
指令の試験など，ヘッダを伴わない用途ではこちらが手軽である。

```
printf '#define A 1\nint main() { return A; }\n\004' | ... qemu pp.bin
```

## 対応する指令

| 指令 | 備考 |
|---|---|
| `#define` | オブジェクト形式・関数形式・可変長 (`...` と `__VA_ARGS__`) |
| `#undef` | |
| `#include "n"` / `<n>` | どちらも束ねのメンバを名前で探す |
| `#if` / `#ifdef` / `#ifndef` / `#elif` / `#else` / `#endif` | `defined` を含む定数式 |
| `#error` | 終了コード 5 |
| `#warning` / `#pragma` / `#line` | 読み飛ばす |

置換では `#` (文字列化) と `##` (連結) が働き，実引数は
`#` / `##` の作用対象でなければ事前に展開される。展開中のマクロは
再展開しない。定義済みマクロは `__STDC__` `__STONE__` `__FILE__` `__LINE__`。

コメント (`/* */` と `//`) は空白 1 個に置き換わる。**cc は `//` しか
解さないため，`/* */` が使えるようになるのは本 Stage の副次的な成果である。**

## プログラム構造

| 関数 | 内容 |
|---|---|
| `rdall` / `bundle` / `hasmagic` | 入力の読込みと束ねの分解 |
| `pushfile` / `pushx` / `popf` / `rawc` / `ungc` | 入力フレームの積み |
| `gc` / `gcnc` | 行連結の除去 / コメントの除去 |
| `scan1` | 走査の本体 (字句 1 個の処理)。展開結果の再走査も担う |
| `dodir` / `readline` / `d_define` / `d_undef` / `d_include` | 指令 |
| `cpush` / `cnext` | 条件コンパイルの段の操作 |
| `domacro` / `expobj` / `expfun` / `collect` / `subst` / `strize` | マクロ展開 |
| `expandto` | テキストを展開しきって eb へ積む (実引数の事前展開，`#if` の式) |
| `enext` / `e_cond` … `e_prim` | `#if` の定数式の評価 |
| `emitfile` / `emitline` | `__FILE__` / `__LINE__` |

中核は「フレームの積みから文字を 1 個引き出す」構造である。底が翻訳単位で，
`#include` はファイルのフレームを，マクロ展開は置換結果のフレームを積む。
再走査・入れ子の展開・include からの復帰がすべてこの 1 つの仕組みに乗るため，
`scan1` は「字句を 1 個処理する」だけの関数で済む。マクロの再帰抑止も
「積みの中に自分の印があるか」で判定する。

置換テキストの寿命は後入れ先出しなので，アリーナはスタック割付けで足りる。
2 本あるのは，実引数の事前展開の最中に「展開の出力先」と「展開のために
積むフレームのテキスト」が同時に伸びるためである。

## 制限

- `#include` の探索対象は束ねのメンバのみ (ディレクトリ探索は無い)
- `#if` の `||` `&&` `?:` は短絡しない。代わりに 0 除算の結果を 0 と定める
- GNU 拡張の `, ## __VA_ARGS__` (可変引数が空のときのカンマ削除) は無い
- 前処理後のソースが cc の字句制限 (識別子は英小文字 15 バイト以下) に
  収まるかどうかは利用者の責任である。pp 自身はより広い字句を受け付ける
